# กระบวนการรับเรื่องและข้อมูลสำคัญ (Intake Flow & Data Model)

> **วันที่จัดทำ:** 2026-07-28

---

## ภาพรวม Flow

```
[ใครก็ได้ส่งเรื่องมา]
        ↓
  สร้าง Intake (รับเรื่อง)
  - ผู้ส่งเรื่อง (Referral Source)
  - ลูกค้า + บุคคลติดต่อ
  - รายละเอียดเหตุการณ์เบื้องต้น
        ↓
  ประเมิน (Assessment)
  - ดูข้อเท็จจริง / เอกสาร
  - ความเห็นเบื้องต้น
        ↓
  ตัดสินใจ
  ┌───────────────┬─────────────────┬────────────────┐
  ↓               ↓                 ↓                ↓
ปฏิเสธ      ออก Notice        เจรจา         แปลงเป็น Case
(ไม่รับ)   (Demand Letter)   (Settlement)   (รับเป็นคดี)
```

---

## 1. Intake Record (การรับเรื่อง)

### 1.1 ผู้ส่งเรื่อง / Referral Source

ผู้ส่งเรื่องอาจเป็นใครก็ได้ ไม่ใช่แค่โรงพยาบาล:

| ฟิลด์ | ประเภทข้อมูล | หมายเหตุ |
|-------|-------------|---------|
| ประเภทผู้ส่งเรื่อง | Enum | บุคคลทั่วไป / ทนายความ / โรงพยาบาล / บริษัท / หน่วยงานรัฐ / อื่นๆ |
| ชื่อผู้ส่งเรื่อง | Text | ชื่อบุคคลหรือองค์กร |
| ช่องทางที่รับเรื่อง | Enum | Walk-in / โทรศัพท์ / อีเมล / Line / Referral / อื่นๆ |
| วันที่รับเรื่อง | Date | |
| ผู้รับเรื่องในสำนักงาน | FK → User | ทนาย/เจ้าหน้าที่ที่รับ |

### 1.2 ลูกค้า (Client)

ลูกค้าอาจเป็นคนละคนกับผู้เสียหาย (เช่น ทายาทมาแทนผู้เสียชีวิต):

| ฟิลด์ | ประเภทข้อมูล | หมายเหตุ |
|-------|-------------|---------|
| ชื่อ-นามสกุล | Text | |
| ชื่อเล่น | Text | |
| ประเภท | Enum | บุคคลธรรมดา / นิติบุคคล |
| เลขบัตรประชาชน / เลขนิติบุคคล | Text | |
| ที่อยู่ | Text | |
| **บุคคลติดต่อ** | ContactPerson[] | **1 ลูกค้า มีได้หลายคน — ดูส่วน 1.3** |

### 1.3 บุคคลติดต่อ (Contact Persons) — หลายคนต่อลูกค้า 1 ราย

> **กฎ:** ลูกค้า 1 ราย มีบุคคลติดต่อได้หลายคน  
> เช่น ลูกค้าเป็นบริษัท → มีทั้ง CEO, CFO, และ Legal Counsel เป็นคนติดต่อ  
> หรือครอบครัวผู้เสียหาย → มีทั้งลูก สามี และน้องสาว

| ฟิลด์ | ประเภทข้อมูล | หมายเหตุ |
|-------|-------------|---------|
| ชื่อเล่น | Text | **บังคับ** — ใช้เรียกในชีวิตประจำวัน |
| ชื่อ-นามสกุล | Text | **บังคับ** |
| เบอร์โทรศัพท์ | Text | **บังคับ** (อย่างน้อย 1 เบอร์) |
| อีเมล | Email | |
| ความสัมพันธ์กับลูกค้า | Text | เช่น สามี / ทายาท / ผู้จัดการ / ตัวแทน |
| เป็นผู้ติดต่อหลัก | Boolean | Primary contact สำหรับการแจ้งข่าว |
| วันที่รับเป็นบุคคลติดต่อ | Date | **บังคับ** |
| หมายเหตุ | Text | เช่น "ติดต่อได้เฉพาะวันทำการ" |

---

### 1.4 รายละเอียดเรื่องที่รับ (Matter Description)

| ฟิลด์ | ประเภทข้อมูล | หมายเหตุ |
|-------|-------------|---------|
| ประเภทเรื่อง | Enum | แพ่ง / อาญา / ปกครอง / ทางการแพทย์ / แรงงาน / อื่นๆ |
| คู่กรณี (ฝ่ายตรงข้าม) | Text | ชื่อบุคคล/องค์กรที่เกี่ยวข้อง |
| สรุปเหตุการณ์เบื้องต้น | Text (Long) | บันทึกจากปากลูกค้า — ไม่ต้องกรองก่อน |
| วันที่เกิดเหตุ (ถ้าทราบ) | Date | ใช้ประเมินอายุความเบื้องต้น |
| มูลค่าความเสียหายโดยประมาณ | Number | ลูกค้าแจ้งเอง — ยังไม่ verified |
| เอกสารที่ลูกค้านำมา | File[] | สแกนหรืออัปโหลด |

## 2. การประเมิน (Assessment)

| ฟิลด์ | ประเภทข้อมูล | หมายเหตุ |
|-------|-------------|---------|
| ผู้ประเมิน | FK → User | ทนายที่วิเคราะห์ |
| วันที่ประเมิน | Date | |
| ความเห็นเบื้องต้น | Text (Long) | |
| ความแข็งแกร่งของคดี | Enum | แข็งมาก / ปานกลาง / อ่อน / ไม่ชัดเจน |
| ความเสี่ยงที่จะแพ้ | Enum | ต่ำ / ปานกลาง / สูง |
| อายุความโดยประมาณ | Date | วันหมดอายุความ — คำนวณจากวันเกิดเหตุ |
| เอกสารที่ยังต้องการเพิ่ม | Text | รายการเอกสารที่ขาด |
| ต้องปรึกษาผู้เชี่ยวชาญภายนอก | Boolean | |

## 3. การตัดสินใจ (Decision)

| ฟิลด์ | ประเภทข้อมูล | หมายเหตุ |
|-------|-------------|---------|
| สถานะการตัดสินใจ | Enum | รอ / รับ / ปฏิเสธ / รอลูกค้าตัดสินใจ |
| คำแนะนำ | Enum | **ฟ้อง** / **ไม่ฟ้อง** / **เจรจาก่อน** / **ออก Notice ก่อน** / **ร้องเรียน** |
| เหตุผล | Text (Long) | อธิบายให้ลูกค้าเข้าใจ |
| วันที่แจ้งลูกค้า | Date | |
| ลูกค้าตัดสินใจ | Enum | เห็นด้วย / ไม่เห็นด้วย / ขอคิดก่อน |

## 4. การแปลงเป็นคดี (Convert to Case)

เมื่อตัดสินใจรับเป็นคดี ระบบจะ **สร้าง Case จาก Intake** โดยอัตโนมัติ:

| ข้อมูลที่ถ่ายโอนจาก Intake | หมายเหตุ |
|--------------------------|---------|
| ข้อมูลลูกค้า | ลิงก์ Client เดิม ไม่ duplicate |
| บุคคลติดต่อทั้งหมด | ถ่ายโอนมาพร้อมกัน |
| **ผู้ส่งเรื่อง (Referral Source)** | บันทึกใน Case ว่า "รับเรื่องมาจากใคร" |
| สรุปเหตุการณ์เบื้องต้น | กลายเป็น case description ใน Case |
| เอกสารที่ลูกค้านำมา | ถ่ายโอนมาใน case files |
| ผลการประเมิน | บันทึกเป็น intake notes ใน Case |
| Notice ที่ออกไป (ถ้ามี) | ลิงก์ไว้ใน timeline ของ Case |

### ข้อมูลที่ต้องกรอกเพิ่มเติมใน Case

| ฟิลด์ | หมายเหตุ |
|-------|---------|
| เลขคดีสำนักงาน | รหัสภายใน — Generate อัตโนมัติหรือกรอกเอง |
| ประเภทคดีอย่างเป็นทางการ | แพ่ง / อาญา / ปกครอง / แรงงาน / ฯลฯ |
| ทนายความหลัก + ทีม | Assign |
| ค่าบริการที่ตกลง | Fee agreement |
| เขตอำนาจศาล / ศาลที่จะยื่น | |
| อายุความที่คำนวณแล้วอย่างแม่นยำ | |

## สรุป Data Model (Entity Relationships)

```
Intake (การรับเรื่อง)
  ├── referralSource: { type, name, channel }
  ├── receivedBy: User
  ├── receivedDate: Date
  ├── client: Client ──────────────────────────────────┐
  │                                                     │
  ├── matters: MatterDescription[]                      │
  ├── assessment: Assessment                            ↓
  ├── decision: Decision                             Client
  ├── notices: Notice[]                                ├── name, nickname
  └── convertedToCase?: Case ←──────────┐             ├── idNumber
                                        │             ├── address
Case (คดี)                              │             └── contacts: ContactPerson[]
  ├── intakeRef?: Intake ───────────────┘                   ├── nickname  ← บังคับ
  ├── referralSource (copied from intake)                    ├── fullName  ← บังคับ
  ├── client: Client                                         ├── phone     ← บังคับ
  ├── contacts: ContactPerson[] (from client)                ├── email
  ├── caseNumber: String                                     ├── relation
  ├── caseType: Enum                                         ├── isPrimary: Boolean
  ├── assignedLawyers: User[]                                └── dateAdded: Date
  ├── feeAgreement: FeeAgreement
  ├── courtInfo: CourtInfo
  ├── limitationDeadline: Date
  ├── status: CaseStatus
  ├── documents: Document[]
  ├── hearings: Hearing[]
  └── timeline: Event[]
```

## หมายเหตุสำคัญ

- **Case ไม่จำเป็นต้องมี Intake** — รับเป็นคดีโดยตรงได้ (ไม่ผ่านขั้นตอนรับเรื่อง)
- **Intake ไม่จำเป็นต้องกลายเป็น Case** — ปิดเป็น "ไม่รับ" ก็ได้
- **Client ใช้ร่วมกันได้** — ลูกค้าคนเดิมอาจมีหลาย Intake และหลาย Case
- **ผู้ส่งเรื่อง (Referral Source)** ≠ **ลูกค้า** ≠ **บุคคลติดต่อ** — สามคนนี้อาจเป็นคนเดียวกันหรือคนละคน
