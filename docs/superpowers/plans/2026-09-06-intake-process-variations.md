# Intake Process Variations Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let staff (a) attach a new intake to a Case the client already has with this firm, (b) flag that a matter is already underway elsewhere before it ever reached this firm, and (c) close an intake as "consultation only" — without changing the intake pipeline for the ordinary case.

**Architecture:** Four new nullable fields on `Intake` (`relatedCaseId`, `isOngoingElsewhere`, `externalCaseNumber`, `currentStageNote`) plus one new value each on `IntakeDecision` (`CONSULTATION_ONLY`) and `IntakeStatus` (`CONSULTED`). `IntakeService.decide()` gets a new status-mapping branch; `IntakeService.convertToCase()` gets an early branch that attaches to an existing case instead of creating one when `relatedCaseId` is set. The client-portal status label map and the already-merged AI-analysis button gate both get the new `CONSULTED` status added to their existing conditionals. Two new form fields ship on `intake/new`, one new decision option and one status-gate tweak ship on `intake/[id]`.

**Tech Stack:** NestJS + Prisma (Postgres) backend (`apps/api`), Next.js/React frontend (`apps/web`), Jest for tests.

**Spec:** `docs/superpowers/specs/2026-09-06-intake-process-variations.md`

## Global Constraints

- Dashboard-only. Do not touch `client-portal-intake.controller.ts`, `client-portal-intake.service.ts`, `portal-intake.dto.ts`, or any `(client-portal)` page.
- `Case.intakeId` (unique, 1:1, "founding intake") stays exactly as-is. The new `Intake.relatedCaseId` is a separate, many-to-one field — never conflate the two.
- Do not touch `IntakeAttachment`, `IntakePrecedentAnalysis`, or the general document-repository work — that's a separate plan (`2026-09-06-intake-document-repository`). This plan only extends the AI-button's existing status-gate conditional with one more status.
