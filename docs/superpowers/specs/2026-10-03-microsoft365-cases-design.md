# เชื่อม Outlook + OneDrive เข้าคดี — ออกแบบ

สถานะ: ออกแบบไว้ ยังไม่ลงมือ (รอข้อมูลจากสำนักงาน — ดู "สิ่งที่ต้องได้ก่อนเริ่ม")

## เป้าหมาย

1. **ย้ายคดีเดิมเข้าระบบ** จากโครงสร้างที่สำนักงานใช้อยู่จริง: Outlook แยก folder ตามคดี + OneDrive แยก folder ตามคดี
2. **ใช้ต่อทุกวัน**: เปิดคดีในระบบแล้วเห็นอีเมลและไฟล์ของคดีนั้นทันที โดยทนายไม่ต้องเปลี่ยนวิธีเก็บงานใน Outlook/OneDrive

## หลักการ: ทุกคน login Microsoft ของตัวเอง

ใช่ — แต่ละคนกด "เชื่อม Microsoft 365" แล้ว login บัญชีของตัวเอง (OAuth แบบ delegated) ระบบจะเห็นเฉพาะสิ่งที่คนนั้นเห็นได้อยู่แล้วใน Outlook/OneDrive ไม่มากกว่านั้น

- ระบบเดิมมีส่วนนี้แล้ว (`apps/api/src/outlook-integration`): login รายคน, token เข้ารหัสในฐานข้อมูล, รับอีเมลใหม่แบบ real-time — แต่ตอนนี้ดึงแค่ **Inbox** และส่งเข้าคิว "เรื่องรับใหม่"
- ต่อยอดเพิ่ม: สิทธิ์อ่านไฟล์ (OneDrive), อ่านทุก folder ของอีเมล, ผูก folder เข้ากับคดี

**ทางเลือกที่ไม่แนะนำ**: ให้ admin ของ Microsoft 365 อนุญาตครั้งเดียวแล้วระบบอ่านอีเมล/ไฟล์ของ *ทุกคน* ในสำนักงานได้ (application permission) — ย้ายข้อมูลเร็วกว่า แต่เป็นสิทธิ์กว้างมาก เสี่ยง PDPA และถ้าระบบรั่ว ข้อมูลทั้งสำนักงานรั่ว ใช้เฉพาะถ้าต้องย้ายข้อมูลของคนที่ลาออกไปแล้ว

## ประสบการณ์ใช้งาน

### ขั้น 1 — เชื่อมบัญชี (แต่ละคน ครั้งเดียว)
ตั้งค่า → "เชื่อม Microsoft 365" → login → ยอมรับสิทธิ์: อ่านอีเมล, อ่านไฟล์, ทำงานต่อเนื่องเบื้องหลัง

### ขั้น 2 — จับคู่ folder กับคดี (ตัวช่วยย้ายข้อมูล)
ระบบสแกนรายชื่อ folder ใน Outlook และ OneDrive (ชื่ออย่างเดียว ยังไม่อ่านเนื้อหา) แล้วแสดงตาราง:

| Folder | พบใน | จับคู่กับคดี | ความมั่นใจ |
|---|---|---|---|
| `TSB2569-014 บจ.สยาม vs ...` | Outlook + OneDrive | TSBREF2569014 | ตรงเลขอ้างอิง |
| `คดีนาย ก.` | OneDrive | — (ไม่พบ) | [สร้างคดีใหม่] / [เลือกคดี] / [ข้าม] |

- จับคู่อัตโนมัติจาก: เลขอ้างอิง (Own Ref), เลขคดีดำ/แดง, ชื่อลูกความ ในชื่อ folder
- folder ที่ไม่มีคดีในระบบ → **สร้างคดีใหม่จาก folder** (ชื่อคดี/ลูกความจากชื่อ folder แก้ได้ก่อนยืนยัน) — นี่คือทางย้ายคดีเดิมเข้าระบบ
- ผู้ใช้ตรวจตารางแล้วกด "ยืนยัน" — ไม่มีอะไรถูกนำเข้าก่อนยืนยัน

### ขั้น 3 — นำเข้าเบื้องหลัง
- **อีเมล**: อีเมลใน folder ที่ผูกแล้ว → เข้าแท็บ "อีเมล" ของคดี (ไม่ใช่คิวเรื่องรับใหม่) เรียงเป็น thread พร้อมไฟล์แนบ
- **ไฟล์ OneDrive**: ไม่คัดลอกทั้งหมด — คดีแสดงรายการไฟล์ใน folder แบบ "สด" (ดึงจาก OneDrive ตอนเปิดดู) กดเปิดใน OneDrive หรือ "นำเข้าเอกสารคดี" ทีละไฟล์เมื่อต้องการใช้ AI วิเคราะห์ / เผยแพร่ให้ลูกความ
- แถบความคืบหน้า + หยุด/ทำต่อได้ (Microsoft จำกัดความเร็ว — mailbox ใหญ่ใช้เวลาหลายชั่วโมง)

### ขั้น 4 — ใช้ต่อทุกวัน
- อีเมลใหม่ที่ทนายลากเข้า folder คดีใน Outlook → เข้าคดีในระบบเองภายในไม่กี่นาที
- ไฟล์ใหม่ใน folder OneDrive ของคดี → เห็นในคดีทันที (เพราะดึงสด)
- folder ใหม่ที่ยังไม่ผูก → แจ้งเตือน "พบ folder ใหม่ ผูกกับคดีไหม"

## การเห็นข้อมูลของเพื่อนร่วมงาน (ประเด็นสำคัญ)

folder ใน OneDrive ของทนาย A — ทนาย B ที่อยู่ในทีมคดีเดียวกันจะเห็นไหม:

- **แบบแนะนำ**: ระบบใช้บัญชีของคนที่ผูก folder (A) ดึงรายการ/ไฟล์ให้ ส่วน "ใครเห็นได้" ตัดสินด้วยสิทธิ์คดีในระบบ (ทีมคดีเห็น คนนอกคดีไม่เห็น) + บันทึก audit ทุกครั้งที่เปิดไฟล์ — ทีมทำงานร่วมกันได้ทันทีโดยไม่ต้องไปตั้ง share ใน OneDrive
- ถ้า A ตัดการเชื่อมต่อหรือลาออก: อีเมลที่นำเข้าแล้วยังอยู่ในคดี; ไฟล์ที่ "ดึงสด" จะหายไปจากระบบ → มีปุ่ม "นำเข้าไฟล์ทั้ง folder" ก่อนตัดการเชื่อมต่อ และเตือน owner เมื่อมีคนกำลังจะตัด
- ระยะยาว (ถ้าสำนักงานพร้อม): ย้าย folder คดีไปไว้ SharePoint ของสำนักงาน แทน OneDrive ส่วนตัว — ไม่ผูกกับคนใดคนหนึ่ง

## ข้อมูล (ร่าง)

```prisma
model CaseExternalLink {            // folder ↔ คดี
  id           String   @id @default(uuid())
  firmId       String
  caseId       String
  connectionId String                // MailboxConnection ของคนที่ผูก
  kind         String                // OUTLOOK_FOLDER | ONEDRIVE_FOLDER
  externalId   String                // mailFolder id / driveItem id
  driveId      String?
  displayPath  String
  deltaLink    String?  @db.Text     // ซิงก์ต่อเนื่องราย folder
  linkedById   String
  createdAt    DateTime @default(now())
  @@unique([connectionId, kind, externalId])
  @@index([caseId])
}
// EmailThread: เพิ่ม caseId (อีเมลของคดี แยกจากคิวเรื่องรับใหม่)
// MailboxConnection: เพิ่ม scopes ที่ได้รับ (รู้ว่าเชื่อมแบบมีสิทธิ์ไฟล์แล้วหรือยัง)
// ImportJob: สถานะการนำเข้าแต่ละ folder (รอ / กำลังทำ / เสร็จ / ผิดพลาด, นับจำนวน)
```

สิทธิ์ Microsoft Graph (delegated): `User.Read`, `offline_access`, `Mail.Read` (มีแล้ว), `Files.Read.All` (อ่านไฟล์ของตัวเอง + ที่คนอื่นแชร์มา), `Sites.Read.All` (ถ้ามี SharePoint)

## ความปลอดภัย / PDPA

- token เข้ารหัส (มีแล้ว); อ่านอย่างเดียว — ระบบไม่ลบ/ย้าย/ส่งอีเมลใน Outlook
- ผูก folder ได้เฉพาะคดีที่ผู้ใช้มีสิทธิ์; การเปิดไฟล์ผ่านระบบตรวจสิทธิ์คดีทุกครั้ง + audit log
- ต้องมีหนังสือยินยอม/บันทึกของสำนักงานว่าอนุญาตให้นำอีเมลและไฟล์ลูกความเข้าระบบ (สำนักงานเป็นผู้ควบคุมข้อมูล)
- ข้อมูลที่ "ดึงสด" ไม่ถูกเก็บในระบบ → ลดภาระ PDPA; ที่นำเข้าแล้วเข้านโยบายระยะเก็บเดียวกับเอกสารคดี
- แก้ OAuth state ให้ผูกกับ browser (ข้อค้างจาก audit) ก่อนเปิดใช้

## งานที่ต้องทำ (ลำดับ)

1. ขยายสิทธิ์ + เชื่อมใหม่ (scopes, OAuth state nonce)
2. สแกน folder + หน้าจับคู่ (auto-match + สร้างคดีจาก folder)
3. นำเข้าอีเมลราย folder เข้าคดี (job เบื้องหลัง + ความคืบหน้า)
4. แท็บไฟล์ OneDrive ในคดี (ดึงสด + นำเข้าทีละไฟล์/ทั้ง folder)
5. ซิงก์ต่อเนื่อง (delta ราย folder + แจ้ง folder ใหม่)
6. Pilot กับทนาย 1–2 คนก่อนเปิดทั้งสำนักงาน

## สิ่งที่ต้องได้ก่อนเริ่ม (จากสำนักงาน)

1. **ใครเป็น admin ของ Microsoft 365** ของสำนักงาน — ต้องกดอนุมัติแอปครั้งเดียว (บาง tenant บังคับให้ admin อนุมัติก่อนพนักงานเชื่อมได้)
2. **ตัวอย่างชื่อ folder 5–10 ชื่อ** ทั้งใน Outlook และ OneDrive (ใช้เลขคดี? ชื่อลูกความ? ปี?) — ตัดสินว่าจับคู่อัตโนมัติได้แม่นแค่ไหน
3. **folder คดีอยู่ที่ไหน**: OneDrive ส่วนตัวของแต่ละคน / folder ที่แชร์กันในทีม / SharePoint
4. **ขนาดโดยประมาณ**: กี่คดี, อีเมลกี่ปีย้อนหลังที่ต้องการ (ทั้งหมด หรือ 2 ปีล่าสุด)
5. **หนังสืออนุญาตจาก owner** ให้นำข้อมูลอีเมล/ไฟล์ลูกความเข้าระบบ
6. **ทนาย pilot 1–2 คน** ที่ยอมให้เชื่อมก่อน
