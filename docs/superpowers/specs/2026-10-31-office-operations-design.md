## ไม่ทำ (non-goals)
- **e-Notice:** เจ้าของตัดสินใจตัดออกก่อน (API ไม่มีเอกสาร/เงื่อนไข, PDPA)
- **e-signature:** เจ้าของไม่เอา
- ระบบอนุมัติ write-off เป็นขั้น ๆ ตามวงเงิน (งานวิจัยหักล้างวงเงินตายตัว และยังไม่มีคนขอ)
- write-off หนี้ค้างของใบแจ้งหนี้ที่ออกไปแล้ว (bad debt) — ต้องเพิ่มสถานะใบแจ้งหนี้ใหม่ ไว้รอบหน้า
- ระยะเวลาเก็บรักษาเอกสาร (retention) ตอนปิดสำนวน — ยังไม่มีข้อมูลตามกฎหมายไทย ห้ามเดาค่าเริ่มต้น
- ชั่วโมงอบรม CLE, KPI ต่อทนาย, จองห้อง/รถ, จัดคิวแมสเซนเจอร์ (ยังไม่มีหลักฐาน)
- สแกน QR ในแอปมือถือ (ต้องเพิ่ม `expo-camera` และ build native ใหม่) — ใช้กล้องมือถือเปิดลิงก์แทน

## Anti-goals (ถ้าเกิดแบบนี้ถือว่าล้มเหลวแม้โค้ดจะทำงาน)
- เวลาที่ระบบร่างไว้ถูกนับเป็นเวลาจริงหรือเข้าใบแจ้งหนี้ก่อนทนายยืนยัน
- write-off แล้วชั่วโมงหายไปจาก utilization ของคนที่ทำงานจริง
- ปิดคดีแล้วระบบลบนัดหรือข้อมูลเองโดยผู้ใช้ไม่ได้เลือก
- ข้อมูลข้ามสำนักงาน (ทุก query ต้องกรอง `firmId` หรือ `case.firmId`, id จาก body ต้องผ่าน `assertFirmRefs`)

## F1. ร่างบันทึกเวลาอัตโนมัติ (กู้ของเดิม + Outlook)

**เจ้าของเลือก "เอาของเดิมกลับมา"** แล้วเพิ่มอีเมลจาก Outlook เป็นอีกแหล่ง

**ทำไมเคยลบ:** เจ้าของบอกว่าตอนนั้นสำนักงานไม่ได้คิดเงินรายชั่วโมง ตอนนี้อยากได้เพราะจะมี dashboard (F2) จึงกู้กลับมาตามเดิมได้ — แต่ต้องไม่บังคับให้ใครคิดเงินรายชั่วโมง: เวลาใช้วัดภาระงาน (utilization) ได้แม้สำนักงานเก็บเงินแบบเหมาจ่าย

**กู้จาก `0506bf10^` ทั้งชุด** (ดู `git show --stat 0506bf10`):
- API: `billing/time-suggestions.service.ts` (+ spec), การลงทะเบียนใน `billing.module.ts`, route `GET time-entries/suggestions`, `POST time-entries/confirm`, `GET time-entries` (firm timesheet), DTO `ConfirmTimeEntryDto`/`ConfirmTimeEntriesDto`, cron 18:00 LINE nudge
- Web: หน้า `/timesheet`, รายการใน `SamnuanSidebar`, i18n th/en, ฟังก์ชันใน `lib/api.ts`
- Mobile: `app/timesheet.tsx`, `Stack.Screen`, ลิงก์ในแท็บ More, hooks และ type
- **ต้องปรับให้เข้ากับโค้ดปัจจุบัน** — มี 27 commit แตะ billing/sidebar/more หลังจากลบ ให้ resolve ไม่ใช่ revert ทับ
- `TimeEntry.sourceKey` และ `@@unique([userId, sourceKey])` ยังอยู่ ไม่ต้องทำ migration

**แหล่งใหม่: อีเมลที่ทนายส่งออกจาก Outlook**
- นับ `EmailMessage` ที่ `direction = OUTBOUND`, `receivedAt` อยู่ในวันนั้น (เวลาไทย), อยู่ใน `EmailThread` ที่ `caseId` ไม่ว่าง และ**ผู้ส่งคือผู้ใช้**: เทียบ `fromAddress` (ไม่สนตัวพิมพ์) กับ `mailboxAddress` ของ `MailboxConnection` ที่ผู้ใช้เป็นเจ้าของ — ไม่ใช้เจ้าของ mailbox ของ thread เพราะ folder sync เพิ่มอีเมลของเราเข้า thread ที่เพื่อนร่วมงานเป็นคน file ไว้ได้ (`de8d2af8`)
- กรองด้วย `CaseAccessService` เหมือนแหล่งอื่น และต้องเคารพกฎ thread ส่วนตัวของเพื่อนร่วมงานที่มีอยู่ (ไม่เสนอจาก thread ที่ผู้ใช้ไม่มีสิทธิ์เห็น)
- รวมเป็น 1 รายการต่อคดีต่อวัน: `source: 'email'`, `sourceKey: email:<caseId>:<YYYY-MM-DD>`, คำอธิบาย `ส่งอีเมลคดี N ฉบับ`
- ชั่วโมงที่เสนอ (การตัดสินใจของผู้ออกแบบ): ฉบับละ 6 นาที ปัดขึ้นเป็นช่วง 0.25 ชม. (1-2 ฉบับ = 0.25, 3-5 = 0.5 …) ทนายแก้ได้ก่อนยืนยัน
- **นัดในปฏิทิน:** ปฏิทิน Outlook ของเราเป็นการ mirror ออกจาก `CalendarEvent` อยู่แล้ว ซึ่งของเดิมเสนอเวลาจากนัดศาลและนัดลูกความไว้แล้ว จึงไม่ต้องดึงนัดจาก Outlook เพิ่ม (ไม่มีการ import นัดที่สร้างใน Outlook โดยตรง)

**กติกาที่ต้องคงไว้:**
- ไม่มี AI — เป็นกฎล้วน (ไม่ขัดกฎ AI ต้องให้ผู้ใช้กด)
- ร่างไม่ถูกบันทึกเป็น `TimeEntry` จนกว่าทนายจะยืนยัน (ของเดิมสร้างร่างแบบ on-the-fly ไม่มีตาราง)
- ยืนยันซ้ำไม่ได้เพราะ unique `sourceKey`

**เพิ่มจากของเดิม (การตัดสินใจของผู้ออกแบบ — ไม่มีแล้ว dashboard ไม่มีความหมาย):**
- **บันทึกเวลาเอง:** ปุ่ม "เพิ่มเวลา" ในหน้า `/timesheet` และใน `CaseBillingPanel` (เลือกคดี, วันที่, ชั่วโมง, รายละเอียด, คิดเงิน/ไม่คิดเงิน) ใช้ `createTimeEntry` เดิม — งานค้นคว้า ร่างเอกสาร โทรศัพท์ ไม่มีแหล่งให้ร่าง
- **แก้/ลบเวลาของตัวเอง** ที่ยังไม่เข้าใบแจ้งหนี้และไม่ได้ write-off (`PATCH`/`DELETE time-entries/:id`); ผู้มี `manageInvoices` แก้/ลบของคนอื่นในคดีที่เข้าถึงได้
- **อัตราค่าเวลาเริ่มต้น:** `FirmMember.defaultHourlyRate Float?` ใช้เติม `rate` ตอนยืนยันร่างและตอนเพิ่มเวลาเอง (แก้ได้ทุกครั้ง) ว่าง = 0 เหมือนเดิม; ตั้งได้ในหน้า `/team` โดย role ที่มี `runOperations`

**เสร็จเมื่อ:** หน้า `/timesheet` และแอปแสดงร่างจากนัด/งาน/review/ข้อความ/อีเมล, ยืนยันแล้วเกิด TimeEntry, เพิ่ม/แก้/ลบเวลาเองได้, LINE 18:00 ทำงาน, spec เดิมผ่าน + spec แหล่งอีเมลและการแก้/ลบ

## F2. Firm Dashboard: utilization / realization / collection

**ที่:** ส่วนใหม่ในหน้า `/reports` ต่อจาก `OwnerKpiSection` (ไม่สร้างหน้าใหม่) สิทธิ์ `viewFirmReports`

**ข้อมูลใหม่:** `FirmMember.monthlyBillableTargetHours Float?` — เป้าชั่วโมงทำงานคดีต่อเดือนของแต่ละคน
- แก้ได้ในหน้า `/team` โดย role ที่มี `runOperations` (OWNER + OFFICE_MANAGER — `manageMembers` เป็นของ OWNER คนเดียว)
- ว่าง = ไม่แสดง utilization ของคนนั้น (แสดง "—" และชวนตั้งเป้า)

**สูตร (ตามนิยาม Clio, นับตาม `TimeEntry.date` ของงาน ไม่ใช่วันออกบิล):**
- ชั่วโมงคิดเงินที่ทำ = `TimeEntry.billable = true` ในช่วงเวลา (รวมที่ write-off แล้ว)
- **Utilization** = ชั่วโมงคิดเงินที่ทำ ÷ (เป้าต่อเดือน × จำนวนเดือนในช่วง แบบสัดส่วนวัน)
- **Realization** = ชั่วโมงที่เข้าใบแจ้งหนี้ ÷ ชั่วโมงคิดเงินที่ทำ — ชั่วโมงที่เข้าใบแจ้งหนี้ = มี `invoiceId` และใบแจ้งหนี้ไม่ใช่ DRAFT (entry ที่ write-off เข้าใบแจ้งหนี้ไม่ได้อยู่แล้ว จึงไม่ต้องลบซ้ำ — ตัวอย่าง ทำ 12 ชม. เรียกเก็บ 10 ตัดทิ้ง 2 = 83%)
- **Collection** = ชั่วโมงที่เก็บเงินได้ ÷ ชั่วโมงที่เข้าใบแจ้งหนี้ — ชั่วโมงที่เก็บเงินได้ = สัดส่วนที่จ่ายแล้วของ**กลุ่ม**ใบแจ้งหนี้ × ชั่วโมงของ entry
  - ใบแจ้งหนี้ที่แบ่งผู้จ่าย (`createInvoice` สร้างหลายใบ แต่ผูก entry ไว้ที่ใบหลักใบเดียว) ต้องคิดทั้งกลุ่ม: เพิ่ม `Invoice.splitGroupId String?` ให้ทุกใบที่เกิดจากการสร้างครั้งเดียวกัน สัดส่วน = ยอดรับชำระรวมของกลุ่ม ÷ `totalAmount` รวมของกลุ่ม; ใบที่ไม่ได้แบ่ง = กลุ่มของตัวเอง; ใบเก่าที่ไม่มี `splitGroupId` ถือเป็นกลุ่มเดี่ยว
- แสดงยอดบาทคู่กัน (ชั่วโมง × `rate`)
- **สำนักงานเหมาจ่าย:** ถ้าช่วงนั้นไม่มีเวลาเข้าใบแจ้งหนี้เลย ซ่อนคอลัมน์ realization/collection แบบชั่วโมง แล้วบอกว่า "สำนักงานไม่ได้วางบิลจากเวลา" — ยังแสดง utilization และยอดวางบิล/เก็บเงินต่อทนายผู้รับผิดชอบแบบบาทที่ `getOwnerKpis` คำนวณอยู่แล้ว
- **ร่างรอยืนยัน:** จำนวนรายการร่างจาก F1 ที่ยังไม่ยืนยันของแต่ละคนใน **7 วันล่าสุด** (นับรายการ ไม่ใช่ชั่วโมง เพราะร่างส่วนใหญ่ไม่มีชั่วโมง) แสดงแยก ไม่รวมในตัวชี้วัด และไม่ผูกกับตัวเลือกช่วงเวลา

**หน้าจอ:**
- ตัวเลือกช่วง: เดือนนี้ / เดือนที่แล้ว / ไตรมาส / ปีนี้ (เวลาไทย ใช้ helper ใน `owner-kpis.ts`)
- แถวรวมทั้งสำนักงาน + ตารางรายคน: ชั่วโมงทำ, เป้า, utilization, realization, collection, ยอดบาท, ชั่วโมงรอยืนยัน
- สูตรคำนวณเป็น pure function แยกไฟล์ (เช่น `operations/firm-metrics.ts`) พร้อม spec ครอบกรณี: ไม่มีเป้า, หาร 0, ใบแจ้งหนี้จ่ายบางส่วน, entry ที่ write-off

## F3. Write-off WIP และส่วนลดใบแจ้งหนี้

**สิทธิ์:** `manageInvoices` (OWNER, OFFICE_MANAGER)

**Write-off เวลาและค่าใช้จ่ายที่ยังไม่ได้เรียกเก็บ:**
- เพิ่มใน `TimeEntry` และ `Expense`: `writtenOffAt DateTime?`, `writtenOffById String?`, `writeOffReason String?`
- write-off ได้เฉพาะรายการที่ `invoiceId = null`; เหตุผลบังคับ (อย่างน้อย 5 ตัวอักษร)
- รายการที่ write-off: **ไม่เข้า** `getInvoiceDraft` / `createInvoice` / ยอด unbilled ทุกที่ (`getOwnerKpis`, `ownerWorklist`) แต่**ยังนับ**เป็นชั่วโมงทำของคนเดิมใน utilization
- ยกเลิก write-off ได้ตราบที่ยังไม่ได้เข้าใบแจ้งหนี้ (ล้างทั้ง 3 ฟิลด์)
- UI: ใน `CaseBillingPanel` แต่ละแถวเวลา/ค่าใช้จ่ายที่ยังไม่เรียกเก็บมีเมนู "ตัดทิ้ง (write-off)" + ช่องเหตุผล; แถวที่ตัดแล้วแสดงขีดฆ่า ชื่อผู้ตัด เหตุผล และปุ่มยกเลิก
- `createInvoice` ที่ claim entry ด้วย `updateMany` ต้องเพิ่มเงื่อนไข `writtenOffAt: null` เพื่อกัน race
- **ความต่างกับปุ่ม "สำนักงานออกเอง" ของค่าใช้จ่าย** (`PATCH expenses/:id/billable`): อันนั้นคือตกลงไว้ว่าไม่เรียกเก็บตั้งแต่ต้น ส่วน write-off คือควรเก็บได้แต่ตัดสินใจไม่เก็บ — คงทั้งสองอย่าง; ไม่เพิ่มปุ่มสลับ billable ให้เวลา (ใช้ write-off แทน เพื่อไม่ให้ชั่วโมงหายจาก utilization)

**ส่วนลดใบแจ้งหนี้:**
- เพิ่มใน `Invoice`: `discountAmount Float @default(0)`, `discountReason String?`
- ใส่ได้ตอนสร้าง และผ่าน `PATCH invoices/:id/discount` ขณะยังเป็น DRAFT (ยังไม่มี endpoint แก้ใบร่าง จึงทำเฉพาะส่วนลด); ส่วนลด > 0 ต้องมีเหตุผล; ส่วนลดต้องไม่เกินยอดก่อนหัก
- ใบที่แบ่งผู้จ่าย: ส่วนลดใส่รายใบ ไม่กระจายข้ามกลุ่ม
- `totalAmount` = ผลรวมรายการ − `discountAmount` (คำนวณที่ server เสมอ ไม่รับยอดจาก client)
- เอกสารใบแจ้งหนี้/PDF แสดงบรรทัดส่วนลด
- ส่วนลดนับเข้า realization แบบบาท (ยอดเรียกเก็บหลังหัก)

- แบบ 2 ปี ยื่นต่ออายุได้ภายใน 90 วันก่อนหมดอายุ
- หมดอายุแล้วต่อได้ภายใน 60 วัน เสียค่าธรรมเนียมเพิ่ม 20% ระหว่างนั้นว่าความไม่ได้

**ข้อมูล (บน `User` เพราะใบอนุญาตเป็นของคน ไม่ใช่ของสำนักงาน):**
- `lawyerLicenseNo String?`, `lawyerLicenseType LawyerLicenseType?` (`TWO_YEAR` | `LIFETIME`), `lawyerLicenseExpiresAt DateTime? @db.Date`
- แก้ได้โดยเจ้าตัว (settings → profile) และ role ที่มี `runOperations` (หน้า `/team`) — ต้องตรวจว่าเป้าหมายเป็นสมาชิกของ firm เดียวกัน
- `LIFETIME` ไม่มีวันหมดอายุ (ล้างค่าวันที่)

**แจ้งเตือน (cron ทุกวัน 08:00 เวลาไทย):**
| หมุด | วันเทียบวันหมดอายุ | ข้อความ |
|---|---|---|
| `OPEN_90` | −90 | เปิดให้ยื่นต่ออายุแล้ว |
| `DUE_30` | −30 | เหลือ 30 วัน |
| `DUE_7` | −7 | เหลือ 7 วัน |
| `EXPIRED` | 0 | หมดอายุวันนี้ — ว่าความไม่ได้จนกว่าจะต่อ |
| `LATE_45` | +45 | เหลือ 15 วันก่อนหมดสิทธิ์ต่อแบบเสียค่าปรับ |
- ส่งถึงเจ้าตัว + owner/office manager ของทุก firm ที่เขาเป็นสมาชิก
- กันส่งซ้ำด้วย `LawyerLicenseReminderLog` unique `[userId, expiresAt, milestone]`; ถ้าวันหมดอายุเปลี่ยน (ต่ออายุแล้ว) หมุดเริ่มใหม่ตามวันใหม่
- ถ้า cron พลาดวัน ให้ส่งหมุดล่าสุดที่ผ่านมาแล้วแต่ยังไม่เคยส่ง (ไม่ส่งย้อนทุกหมุด)
- หมวดแจ้งเตือน: เพิ่ม `NotificationCategory.LICENSE` (Prisma + shared + หน้าตั้งค่าแจ้งเตือนบนมือถือ)

**ที่แสดง:**
- หน้า `/team`: คอลัมน์ใบอนุญาต พร้อม badge "ใกล้หมด" (≤ 90 วัน) / "หมดอายุ" (สีแดง)
- เติม `{{lawyerLicenseNo}}` ใน template ซึ่งมี ponytail note รออยู่ที่ `templates/templates.service.ts:100`

## F5. ปิดสำนวน: เช็กลิสต์ที่ขาด

ของเดิม `outstanding` นับงานค้าง นัดในอนาคต และเอกสารค้าง แล้ว `close` ให้ยืนยันรับทราบ

**เพิ่มใน `outstanding`:**
- เวลาที่ยังไม่เรียกเก็บ (billable, `invoiceId = null`, ไม่ได้ write-off) — ชั่วโมงและยอดบาท
- ค่าใช้จ่ายที่ยังไม่เรียกเก็บ (billable, APPROVED/PAID, `invoiceId = null`, ไม่ได้ write-off)
- ใบแจ้งหนี้ที่ยังค้างชำระ (status SENT) — จำนวนและยอดค้าง
- ใบแจ้งหนี้ร่าง (DRAFT)
- ทั้งหมดอยู่ภายใต้ `acknowledgeOutstanding` เดิม (ระบบไม่ตัดสินใจแทน)

**นัดในอนาคตตอนปิด (ผู้ใช้เลือกเอง):**
- เพิ่ม `CloseCaseDto.removeFutureEvents?: boolean`
- ติ๊กแล้ว: ลบ `CalendarEvent` ของคดีที่ `startAt >= now` ผ่านเส้นทางลบปกติของปฏิทิน (เพื่อให้สำเนาใน Outlook ถูกลบตาม)
- ไม่ติ๊ก: นัดยังอยู่
- เปิดคดีใหม่ไม่กู้นัดที่ลบไปแล้ว — บอกไว้ใน UI ข้าง checkbox

**แก้บั๊ก:** `reminder.scheduler.ts` ยังส่งเตือนนัดของคดีที่ปิด/archive แล้ว → กรอง `case.status` ไม่เป็น CLOSED/ARCHIVED

**UI:** ฟอร์มปิดบนเว็บ (`cases/[id]/page.tsx` รายการ outstanding) และมือถือ (`app/case/[id]/close.tsx`) แสดงหัวข้อใหม่และ checkbox ลบนัด

## F6. เคลียร์เงินทดรองและใบเสร็จค่าธรรมเนียมศาล

**ปัญหา:** ตอนนี้จ่ายเงินทดรองแล้วหักได้ (`consume`) แต่ไม่มีการปิดยอด ไม่รู้ว่าเงินที่เหลือคืนแล้วหรือยัง และใบเสร็จศาลครบไหม

**ข้อมูล:**
- `CashAdvance`: `settledAt DateTime?`, `settledById String?`, `returnedAmount Float @default(0)`, `settlementNote String?`
- `Expense`: `officialReceiptNo String?` (เลขที่ใบเสร็จศาลหรือ e-Receipt)

**เคลียร์เงินทดรอง (สิทธิ์ `issueCashAdvance`):**
- บันทึกเงินคืน: กรอกยอดที่พนักงานคืน (≤ `remaining`) → `remaining` ลดลง, `returnedAmount` เพิ่ม
- ปิดยอด: ทำได้เมื่อ `remaining = 0` → ตั้ง `settledAt`; หลังปิดหักเพิ่มไม่ได้ (`consume` ต้องปฏิเสธ advance ที่ settled แล้ว)
- ทำใน transaction เดียวกับการปรับ `remaining` เพื่อกันชนกับ `consume`

**รายงานกระทบยอด (หน้า `admin/reimbursements` แท็บใหม่ "เงินทดรอง"):**
- ต่อ advance: ผู้รับ, วันจ่าย, ยอดจ่าย, ใช้ไป, คืนแล้ว, คงเหลือ, จำนวนค่าใช้จ่ายที่**ไม่มีไฟล์ใบเสร็จ**, จำนวนค่าธรรมเนียมศาลที่**ไม่มีเลขที่ใบเสร็จ**, สถานะ (ค้าง / ปิดแล้ว)
- กดเข้าไปเห็นรายการค่าใช้จ่ายที่หักจาก advance นั้น และแก้ `officialReceiptNo` ได้
- พนักงานเห็นเฉพาะของตัวเอง (ต่อยอด `listMineWithBalance`)

**ฟอร์มค่าใช้จ่าย (web + mobile + LINE expense flow):** เมื่อหมวดเป็น `ค่าธรรมเนียมศาล` แสดงช่อง "เลขที่ใบเสร็จศาล" (ไม่บังคับ)

## F7. ติดตามสำนวนกระดาษ (QR เบิก-คืน)

**หลักการ:** หนึ่งคดีมีสำนวนกระดาษหนึ่งชุด (การตัดสินใจของผู้ออกแบบ — หลายเล่มไว้รอบหน้า) ใช้ `Case.folderId` (`LF-<ปี>-<rand6>`) เป็นรหัสบนฉลาก

**ข้อมูล:**
- `Case`: `paperFileHolderId String?` (ผู้ถืออยู่), `paperFileLocation String?` (ที่เก็บ เช่น "ตู้ A ชั้น 2")
- `PaperFileMovement`: `id, firmId, caseId, action (CHECK_OUT | CHECK_IN | MOVE), holderUserId?, location?, note?, createdById, createdAt` — index `[firmId, caseId, createdAt]`

**การทำงาน:**
- **เบิก:** ผู้ใช้กด "เบิกสำนวน" → holder = ผู้ใช้ (หรือเลือกคนอื่นในสำนักงาน ผ่าน `assertFirmRefs`)
- **คืน:** "คืนสำนวน" + ที่เก็บ → holder ว่าง, location ใหม่
- **ย้ายที่เก็บ:** เปลี่ยน location โดยไม่มีคนถือ
- ทุกครั้งเขียน `PaperFileMovement` และ audit
- สิทธิ์: ใครก็ได้ที่เข้าถึงคดีได้ (`CaseAccessGuard`)

**QR:**
- ปุ่ม "พิมพ์ฉลาก" บนการ์ดสำนวนกระดาษ → หน้าพิมพ์ที่มี QR + เลขคดี + ชื่อคดีย่อ
- QR เข้ารหัส URL `https://<app>/f/<folderId>`; หน้า `/f/[folderId]` หาคดีจาก `folderId` ภายใน firm ของผู้ใช้แล้วแสดงปุ่มเบิก/คืนขนาดใหญ่ (ใช้บนมือถือได้ เปิดจากกล้องมือถือโดยตรง)
- ยังไม่ล็อกอิน → ไปหน้า login แล้วกลับมาที่ `/f/...`
- เพิ่ม dependency `qrcode` ใน `apps/web` (ไม่มี lib QR ในโปรเจกต์)

**ที่แสดง:**
- การ์ด "สำนวนกระดาษ" ในหน้าคดี: ผู้ถือ/ที่เก็บปัจจุบัน, ปุ่มเบิก/คืน/ย้าย, ประวัติ 10 รายการล่าสุด
- หน้ารายการ "สำนวนที่ถูกเบิกอยู่" (ใต้ `/operations`, สิทธิ์ `runOperations`): คดี, ผู้ถือ, เบิกมากี่วัน เรียงจากนานสุด, แบ่งหน้าที่ API
