# ออกแบบฟีเจอร์สำหรับลูกค้ากลุ่มใหม่ (2026-10-28)

ที่มา: [รายงานกลุ่มลูกค้า](../../research/2026-10-28-customer-segments-beyond-law-firms.md) อันดับ 1–3 ส่วนอัยการและตำรวจยังไม่ทำ

## หลักร่วมของทุกกลุ่ม
- **ระบบเดียว ไม่แยกแอป:**
  - เพิ่ม `Firm.workspaceType` (`LAW_FIRM` | `COLLECTIONS` | `IN_HOUSE` | `INSURER`) แค่เปลี่ยนคำเรียก เมนูที่แสดง และค่าเริ่มต้น
  - ข้อมูลยังเป็น `Case` / `Client` ชุดเดิม
- **Apple:** ทุกแพ็กเกจในเอกสารนี้ขายให้องค์กรผ่านเว็บเท่านั้น
  - แอปมือถือไม่มีราคา ไม่มีปุ่มซื้อ
  - ฟีเจอร์ใหม่ในแอปเป็นแค่การดู/อัปเดตงาน
- **รองรับข้อมูลหลักหมื่นคดีต่อสำนักงาน:**
  - ทุกหน้ารายการต้องแบ่งหน้าที่ฝั่ง API และมี index (บทเรียนจากเคสอีเมล 22,000 thread ที่ทำ server ล่ม)
  - งานชุดใหญ่ทำเป็น background job ไม่ทำใน request เดียว

## กลุ่ม 1: ทีมฟ้องคดีชุดของเจ้าหนี้ (ธนาคาร ลิสซิ่ง บัตรเครดิต AMC และสำนักงานที่รับงานจากเจ้าหนี้)

**ผู้ใช้:** หัวหน้าทีมคดีชุด, ทนายที่รับคดีวันละหลายสิบคดี, เจ้าหน้าที่ธุรการ, เจ้าหนี้ (ผู้ว่าจ้าง) ที่อยากเห็นผล

**สิ่งที่ต้องทำได้:**
- รับคดีครั้งละหลักพัน
- ไม่ให้คดีไหนหลุดอายุความ
- ทำเอกสารและนัดศาลเป็นชุด
- รายงานเจ้าหนี้ได้ทุกเดือนโดยไม่ต้องทำ Excel เอง

### F1. นำเข้าคดีชุดจาก Excel (ต่อยอด `DataImportBatch` ที่มีอยู่)
- **ใช้ของเดิม:** ขั้นตอน preview → commit → undo และ ledger ใน `practice-setup.service.ts`
- **เพิ่ม:**
  - รับไฟล์ได้ถึง 5,000 แถวต่อชุด
  - ประมวลผลเป็น job พร้อมแถบความคืบหน้า
  - ตรวจทีละแถว: แถวที่ผิดไม่ทำให้ทั้งชุดล้ม แสดงรายการแถวที่ผิดให้แก้แล้วอัปโหลดซ้ำ
- **คอลัมน์:** ชื่อลูกหนี้, เลขบัตร/เลขนิติบุคคล (เก็บแบบปิดบางส่วน), เลขสัญญา (ใช้ `Case.customerRef`), ประเภทหนี้, ยอดหนี้ (`claimedAmount`), วันผิดนัด, ศาลที่จะฟ้อง, ทนายผู้รับผิดชอบ (ว่างได้)
- **กันซ้ำ:** เลขสัญญาซ้ำกับคดีที่เปิดอยู่ของเจ้าหนี้รายเดียวกัน → แสดงเป็นแถวซ้ำ ไม่สร้างคดีใหม่
- **อายุความ:**
  - คำนวณ `limitationDeadline` จากวันผิดนัด + กฎตามประเภทหนี้ (`DeadlineRule` ใหม่ trigger = DEFAULT_DATE)
  - สำนักงานต้องตั้งและยืนยันกฎเอง ระบบไม่ใส่ระยะเวลาตามกฎหมายให้อัตโนมัติ
- **แจกงาน:** ทนายแบบวนรอบ หรือตามภาระงาน (ใช้ข้อมูลหน้าภาระงานทีมที่มีอยู่)
- **เพิ่มในฐานข้อมูล:** `Case.importBatchId` (ดูทุกคดีจากชุดเดียวกันได้)

### F2. มุมมองพอร์ตตามเจ้าหนี้
- **หน้าใหม่ "พอร์ต"** ต่อ `Client` (เจ้าหนี้):
  - จำนวนคดีตามขั้น (ยังไม่ฟ้อง / ฟ้องแล้ว / พิพากษา / บังคับคดี / ปิด)
  - ยอดฟ้อง vs ยอดพิพากษา vs ยอดได้คืน
  - คดีใกล้อายุความ 30/60/90 วัน
  - กรองตามชุดนำเข้า
- **เพิ่มฟิลด์:** `Case.judgmentAmount`, `Case.recoveredAmount` (ยอดรับชำระสะสม หรือตาราง `CasePayment` ถ้าต้องการรายการ)
- **รายการคดี:** ตารางแบ่งหน้า เลือกหลายคดีเพื่อสั่งงานชุดได้ (F3)

### F3. สั่งงานเป็นชุด
- **เลือกคดีหลายรายการ แล้วทำได้:**
  - เปลี่ยนขั้น
  - มอบหมายทนาย
  - สร้างงาน
  - ออกเอกสารจากแม่แบบ: หนังสือบอกกล่าว, คำฟ้องฉบับร่าง จาก `DocumentTemplate` เติมข้อมูลรายคดี ได้ zip หรือไฟล์ในแต่ละคดี
- **นัดชุด:** คดีหลายคดีที่ศาลเดียวกันวันเดียวกัน ลงนัดครั้งเดียว ทนายเห็นเป็นรายการเดียวในหน้า "วันนี้" ของแอปมือถือ
- **ประวัติ:** ทุกการสั่งงานชุดบันทึก audit log พร้อมจำนวนคดีที่โดน และย้อนกลับได้เท่าที่ทำได้ (ใช้แนวคิด ledger เดิม)

### F4. รายงานให้เจ้าหนี้ (ระยะ 2)
- **รายงานรายเดือนต่อเจ้าหนี้** (Excel + PDF): สถานะทุกคดี ยอดเงิน คดีที่เปลี่ยนสถานะในเดือน
- **ส่งอัตโนมัติ:** ทางอีเมลตามรอบที่ตั้ง ส่งด้วย Resend ที่มีอยู่
- **Portal เจ้าหนี้:** ใช้ client portal เดิม เพิ่มมุมมองพอร์ตแบบอ่านอย่างเดียว เจ้าหนี้ไม่ต้องโทรถาม

### F5. แพ็กเกจตามปริมาณคดี
- **แพ็กเกจกลุ่ม Collections:** คิดตามจำนวนคดีที่เปิดอยู่ (`maxActiveCases` ใน `PLAN_CONFIG` ที่เพิ่งทำใน PR #137)
  - ตัวอย่าง: 500 / 2,000 / 10,000 คดี + ผู้ใช้ 10 / 25 / ไม่จำกัด
  - ตัวเลขราคาต้องคุยกับลูกค้านำร่องก่อน
- **เกินเพดาน:** แจ้งเตือนที่ 90% และให้อัปเกรด (บนเว็บเท่านั้น)

### F6. ข้อควรระวังด้านกฎหมาย (ระยะ 2)
- **บันทึกการติดต่อลูกหนี้** (โทร / จดหมาย / LINE) ต่อคดี พร้อมเวลา เผื่อเจ้าหนี้ต้องตรวจสอบตาม พ.ร.บ.การทวงถามหนี้ พ.ศ. 2558
  - ขอบเขตว่ากฎหมายครอบคลุมงานฟ้องคดีของทนายแค่ไหน ยังต้องตรวจกับตัวบท
- **PDPA:** เลขบัตรประชาชนแสดงแบบปิดบางส่วน, ตั้งระยะเก็บข้อมูลหลังปิดคดี, export ทุกครั้งมี log

## กลุ่ม 2: ฝ่ายกฎหมายในบริษัท (in-house)

**ผู้ใช้:** หัวหน้าฝ่ายกฎหมาย, นิติกร, ผู้บริหารที่อยากเห็นความเสี่ยงคดีของบริษัท

### F7. งานที่ไม่ใช่คดีศาล
- **ประเภทงานใหม่:** "งานที่ปรึกษา / สัญญา" ใช้ `Case` เดิม ไม่ต้องมีศาลหรือเลขคดี
  - ขั้นงาน: รับเรื่อง → ตรวจ → อนุมัติ → เสร็จ
- **ผู้ขอ:** หน่วยงานภายใน (ฝ่ายขาย, HR) แทน "ลูกความ"
  - ใช้ `Client` แบบ type = INTERNAL_UNIT หรือฟิลด์ใหม่
  - ส่งเรื่องเข้ามาผ่านฟอร์มที่มีอยู่ (portal intake)

### F8. ติดตามสำนักงานกฎหมายภายนอก และงบประมาณ
- **ต่อคดี:** ระบุสำนักงานภายนอกที่จ้าง, ค่าจ้างที่ตกลง, ใบแจ้งหนี้ที่รับมา (ต่อยอด `Expense`)
- **รายงานค่าใช้จ่ายกฎหมาย:** ต่อเดือน / ต่อหน่วยงาน / ต่อสำนักงานภายนอก
- **ภาพรวมผู้บริหาร:** คดีที่บริษัทเป็นจำเลย ยอดเสี่ยงรวม (`claimedAmount`) และคดีที่ใกล้นัดสำคัญ

### F9. เข้าสู่ระบบด้วยบัญชีบริษัท (SSO)
- **Microsoft Entra ID:** มี Microsoft OAuth จาก Outlook integration อยู่แล้ว
- **เพิ่มผู้ใช้:** จากโดเมนบริษัทโดยไม่ต้องเชิญทีละคน

## กลุ่ม 3: บริษัทประกันภัย (เคลม ไล่เบี้ย สินค้าขนส่ง)

**มีอยู่แล้ว:**
- `InsuranceClaim` (ขั้นเคลม, หนังสือทวงถาม, ร้องเรียน คปภ.)
- `CargoClaim` (ข้อมูลขนส่ง, time bar, ผู้รับผิด)

### F10. งานไล่เบี้ย (subrogation)
- **ขั้นใหม่หลังจ่ายสินไหม:** ติดตามผู้ทำละเมิด / ผู้ขนส่ง → เจรจา → ฟ้อง → ได้คืน
- **ข้อมูลต่อคดี:** ยอดจ่ายสินไหม, ยอดเรียกคืน, ยอดได้คืน (ใช้ฟิลด์เดียวกับ F2)
- **นำเข้าเคลมเป็นชุด:** จากระบบเคลมของบริษัทผ่าน F1 ใช้คอลัมน์ชุดของประกัน
- **อายุความ:** เตือน time bar ด้วยกลไกเดียวกับ `CargoClaim.timeBarDeadline` และ `limitationDeadline`

### F11. รายงานอัตราได้คืน
- **อัตราได้คืน:** ต่อประเภทเคลม / ต่อผู้ขนส่ง / ต่อสำนักงานกฎหมายภายนอกที่จ้าง
- **ใช้ร่วมกัน:** มุมมองพอร์ตเดียวกับ F2 (ประกันคือ "เจ้าหนี้" ของงานไล่เบี้ย)

## กลุ่ม 4: อัยการ / ตำรวจฝ่ายสำนวน
ยังไม่ทำ ทบทวนใหม่เมื่อ:
1. Samnuan ยืนยันได้ว่าเก็บข้อมูลในประเทศได้ตามแนวทาง Cloud First
2. มีหน่วยงานแสดงความสนใจจริง

## ลำดับการทำ
| ระยะ | ฟีเจอร์ | ทำไม |
|---|---|---|
| 1 (ประมาณ 4–6 สัปดาห์) | F1 นำเข้าคดีชุด, F2 พอร์ต, F3 สั่งงานชุด, F5 แพ็กเกจตามปริมาณ, แบ่งหน้าทุกรายการ | ขายกลุ่ม 1 ได้ และ F1–F3 ใช้ต่อกับกลุ่ม 3 ได้ |

## สิ่งที่ต้องตัดสินใจก่อนเริ่มระยะ 1
1. มีลูกค้านำร่องในกลุ่ม 1 ไหม (ธนาคาร / AMC / สำนักงานที่รับงานจากเจ้าหนี้) ควรออกแบบคอลัมน์นำเข้าและรายงานตามไฟล์จริงของเขา
2. ราคาแพ็กเกจตามปริมาณคดี (ตัวอย่าง 500 / 2,000 / 10,000)
3. กฎอายุความตามประเภทหนี้: ใครเป็นคนยืนยันตัวเลข (ทนายของคุณ หรือลูกค้าตั้งเอง)
4. เครื่อง prod ตอนนี้ (EC2 t4g.small, RDS t4g.micro) ไม่พอสำหรับหลักหมื่นคดีต่อลูกค้า ต้องวางงบขยายเครื่องพร้อมระยะ 1
