# นำเข้าคดีเก่าจาก OneDrive (OneDrive → สร้างคดี)

วันที่: 2026-10-31 · สถานะ: ร่าง รออนุมัติ

## ทำไม

สำนักงานเพิ่งเชื่อม Microsoft 365 เข้าระบบ งานเก่าทั้งหมดอยู่ใน OneDrive แยกเป็นหนึ่งโฟลเดอร์ต่อหนึ่งคดี แต่ยังไม่มีคดีเหล่านี้ในระบบ
เป้าหมายคือ **ย้ายงานเดิมเข้าระบบในรอบเดียว** โดยเอาโฟลเดอร์เป็นต้นทาง สร้างคดีใหม่ แล้วผูกโฟลเดอร์ไว้กับคดีนั้น

ตอนนี้ระบบทำได้แค่ผูกโฟลเดอร์กับ**คดีที่มีอยู่แล้ว** (แท็บ `DriveFolderMatchingTab` ในหน้าตั้งค่า และ `CaseDriveService.linkFolder`) ยังสร้างคดีจากโฟลเดอร์ไม่ได้

## ข้อมูลจริงที่เห็น

โฟลเดอร์ต้นทางหลัก: `My files › backup flashdrive › 11111. บาร์ริสเตอร์` อยู่ใน OneDrive ส่วนตัวของ Suchanya Umoung

- **โฟลเดอร์คดี ~95 อัน** รูปแบบคร่าว ๆ คือ `เลขลำดับ. ประเภทงาน - เลขคดี - ศาล - คู่ความ (ชื่อเล่นคนทำ)`
  - `89. คำให้การ - พ264.69 - ศ.แพ่ง - แฟมมิลี่ & เมเจอร์ ซินีเพล็กซ์ (โบ, พี่ปิง)`
  - `86. คำฟ้อง - พE291.69 - ศจ.สมุทรปราการ - TMSTH & นายแสงเพชร (ยักยอก) (โบ)`
  - `36. จำเลย - ผบE6635-65 -ศาลจ.บุรีรัมย์ - น.ส.วาสนา - อลิอันซ์`
  - `14. เตรียมฟ้อง - TMSTH & บจ.วีฮิเคิล (รถยนต์ มาสด้า2)` (ไม่มีเลขคดี)
- **เลขคดีเขียนหลายแบบ** ได้แก่ `พE291.69`, `กค.187.65`, `กค186.64`, `ผบE6635-65`, `มE399.2566`, `พE.12862565`, `กค.152-25655` (พิมพ์ผิด) และ `กค.35,40-2564` (สองคดีในโฟลเดอร์เดียว)
- **ศาลเขียนย่อ** เช่น `ศ.แพ่งใต้`, `ศข.บางบอน`, `ศจ.สมุทรปราการ`, `ศ.แขวงเหนือ`
- **สถานะอยู่ในชื่อ** เช่น `close`, `Close -`, `พิพากษา close`, `ถอนฟ้อง`, `รอพิจารณา`
- **ชื่อในวงเล็บ** เช่น (โบ, พี่ปิง) คือคนในทีมที่ทำงานร่วมกัน **ไม่ได้บอกเสมอไป**ว่าใครเป็นทนายหลัก (ผู้ใช้ยืนยันแล้ว)
- **โฟลเดอร์รวม** เช่น `B. คดีทางการแพทย์` และ `A. ช่วยพี่ปิงเตรียมคดี` ข้างในมีคดีย่อยอีกหลายคดี เช่น `1. นพ.ชาญชัย ... - R023 0326 Viriyah` ซึ่งใช้เลขเคลมประกันแทนเลขคดี
- **โฟลเดอร์ที่ไม่ใช่คดี ~25 อัน** เช่น `แบบฟอร์มศาล`, `Notice ออกแล้ว`, `ภาษี`, `หนังสือมอบอำนาจ Dhip`, `audit` และมีไฟล์หลวมอยู่ที่ชั้นบนสุดด้วย
- ข้างในโฟลเดอร์คดีมีทั้งไฟล์และโฟลเดอร์ย่อย

## เป้าหมาย

1. คนนำเข้าเลือกโฟลเดอร์แม่ใน OneDrive แล้วเห็นโฟลเดอร์ย่อยทั้งหมดเป็นตาราง หนึ่งแถวต่อหนึ่งโฟลเดอร์
2. ระบบอ่านชื่อโฟลเดอร์แล้ว**เติมค่าเริ่มต้นให้** คนแก้ได้ทุกช่องก่อนสร้าง
3. กดครั้งเดียวสร้างหลายคดี แต่ละคดีผูกกับโฟลเดอร์ของตัวเอง
4. **ไฟล์อยู่ที่เดิมใน OneDrive** ไม่ก๊อปเข้าระบบ (ผู้ใช้ตัดสินแล้ว) หน้าคดีเปิดดูไฟล์ผ่านลิงก์โฟลเดอร์ที่มีอยู่แล้ว
5. กดนำเข้าซ้ำได้อย่างปลอดภัย โฟลเดอร์ที่ผูกกับคดีแล้วจะไม่ถูกสร้างคดีซ้ำ

## สิ่งที่ไม่ทำ

- ไม่ซิงก์ต่อเนื่อง และไม่สร้างคดีอัตโนมัติเมื่อมีโฟลเดอร์ใหม่ งานนี้เป็นการย้ายข้อมูลครั้งเดียว ใช้ซ้ำได้ด้วยมือ
- ไม่ใช้ AI อ่านชื่อหรืออ่านเนื้อไฟล์ ใช้กฎแยกข้อความแบบตายตัว ซึ่งตรงกับ `case-matching.ts` และนโยบาย "AI ต้องกดเอง"
- ไม่ก๊อปหรือนำเข้าไฟล์ ถ้าอยากเก็บไฟล์เข้าระบบ ใช้ปุ่ม "นำเข้า" ในหน้าคดีที่มีอยู่แล้ว
- ไม่สร้างลูกความ (Client) ใหม่จากชื่อโฟลเดอร์ ชื่อคู่ความในโฟลเดอร์ปนกันหลายฝ่าย เดาฝ่ายไม่ได้
- ไม่แก้ไข เปลี่ยนชื่อ หรือย้ายอะไรใน OneDrive ระบบอ่านอย่างเดียว

## สิ่งที่ถือว่าล้มเหลว แม้จะทำงานได้

- สร้างคดีไปแล้วโดยที่คนยังไม่ได้เห็นหรือยืนยัน
- สร้างคดีซ้ำจากโฟลเดอร์เดิม
- เลขคดีที่แปลงผิดถูกบันทึกเงียบ ๆ เช่น `กค.152-25655` กลายเป็นปีแปลก ๆ โดยไม่มีใครเห็น
- สร้างไปครึ่งเดียวแล้วพัง โดยไม่บอกว่าแถวไหนสร้างแล้ว แถวไหนยัง

## ขั้นตอนใช้งาน

อยู่ที่หน้า **ตั้งค่า → Microsoft 365 → แท็บจับคู่โฟลเดอร์ OneDrive** (`DriveFolderMatchingTab`) ต่อยอดจากแท็บนี้ ไม่ทำหน้าใหม่

1. เลือกโฟลเดอร์แม่ด้วย `DriveFolderPicker` ตัวเดิม
2. ตารางแสดงโฟลเดอร์ย่อย แต่ละแถวอยู่ในสถานะใดสถานะหนึ่ง:
   - **ผูกแล้ว**: แสดงคดีที่ผูกอยู่ ตามที่หน้านี้ทำอยู่แล้ว
   - **ตรงกับคดีที่มีอยู่**: แสดงคำแนะนำจาก matcher เดิม คนเลือกผูกได้ตามเดิม
   - **สร้างคดีใหม่**: แถวที่ยังไม่ผูก มีช่องให้กรอกตามหัวข้อถัดไป
   - **ข้าม**: คนติ๊กเอง
3. โฟลเดอร์รวม เช่น `B. คดีทางการแพทย์` คนกดเข้าไปดูชั้นถัดไปได้ด้วย picker เดิม แล้วนำเข้าชั้นนั้น ระบบไม่ไล่ลงหลายชั้นเอง
4. กด "สร้าง N คดี" ระบบจะ:
   - ตรวจทุกแถวก่อน
   - สร้างคดีและผูกโฟลเดอร์
   - แสดงผลรายแถวว่าสร้างแล้ว พร้อมลิงก์ไปคดี หรือผิดพลาดเพราะอะไร

## ช่องที่ระบบเติมให้ (แก้ได้ทุกช่อง)

| ช่องในคดี | ค่าเริ่มต้น |
|---|---|
| `title` | ชื่อโฟลเดอร์หลังตัด `เลขลำดับ.` ข้างหน้าออก ถ้าว่างใช้ชื่อเต็ม |
| `blackCaseNumber` | เลขคดีที่หาเจอในชื่อ แปลงให้อยู่ในรูป `prefix เลข/ปี4หลัก` ถ้าปี 2 หลักให้เติม `25` ข้างหน้า เช่น `พE291.69` → `พE291/2569`, `กค.187.65` → `กค187/2565` ถ้าแปลงไม่ได้ เจอหลายเลข หรือไม่ผ่าน `CASE_NUMBER_REGEX` ให้ปล่อยว่าง และโชว์ข้อความดิบที่เจอไว้ข้าง ๆ ให้คนดู |
| `courtName` | ข้อความศาลที่หาเจอ เช่น `ศ.แพ่งใต้` ใส่ตามที่เขียน ไม่แปลงเป็นชื่อเต็ม |
| `courtLevel` | ช่องนี้บังคับกรอก ค่าเริ่มต้นเป็นศาลชั้นต้น ถ้าชื่อมี `อุทธรณ์` หรือ `ฎีกา` ให้เปลี่ยนตาม |
| สถานะ | ถ้ามี `close` (ไม่สนตัวพิมพ์เล็กใหญ่) หรือ `ถอนฟ้อง` ให้แนะนำเป็น "ปิดแล้ว" ที่เหลือเป็น "เปิดอยู่" |
| ผลคดี (`outcome`) | ใช้เฉพาะแถวที่เป็น "ปิดแล้ว" และ**บังคับเลือกทีละแถว** (ผู้ใช้ตัดสินแล้ว) ได้แก่ WON / LOST / SETTLED / MEDIATED / WITHDRAWN ถ้าชื่อมี `ถอนฟ้อง` ให้เลือก WITHDRAWN ไว้ก่อน แถวอื่นเว้นว่าง ยังไม่เลือกจะกดสร้างไม่ได้ |
| สรุปตอนปิด (`closingSummary`) | ใช้เฉพาะแถวที่ปิดแล้ว ค่าเริ่มต้นคือ `นำเข้าจาก OneDrive: <ชื่อโฟลเดอร์>` ยาวเกิน 10 ตัวอักษรตามกฎของ `close()` อยู่แล้ว แก้ได้ |
| `leadLawyerId` | ช่องนี้บังคับกรอก และ**ระบบไม่เดา** คนเลือกจากรายชื่อผู้ใช้ในสำนักงาน เลือกหลายแถวแล้วตั้งค่าทีเดียวได้ |
| ทีม (`buddyIds`) | ว่างไว้ แสดงชื่อในวงเล็บข้างแถวเป็นคำใบ้ คนเลือกเพิ่มเอง |

ส่วนที่แยกชื่อโฟลเดอร์ต้องเป็นฟังก์ชันล้วน (pure function) แยกไฟล์ และมีเทสต์จากชื่อจริงข้างบน

## ข้อจำกัดและของที่มีอยู่แล้ว

- เลขคดีรับตัวอักษรภาษาอังกฤษในส่วนหน้าเลขแล้ว เช่น `พE291/2569` แก้ใน `packages/shared/src/validation.ts` ใน branch นี้
- ต้องสร้างคดีผ่านกติกาเดียวกับ `CasesService.create` ได้แก่ ตรวจว่าผู้ใช้อยู่สำนักงานเดียวกัน, `insertCase` สร้าง ownRef และ folderId, และบันทึก feed "เปิดคดี" **ห้ามเขียนข้ามไปที่ prisma ตรง ๆ**
- การผูกโฟลเดอร์ใช้กติกาเดียวกับ `CaseDriveService.linkFolder` ได้แก่ token ของผู้นำเข้าเอง, unique `connectionId_kind_externalId` และบันทึก audit `DRIVE_FOLDER_LINKED`
- ผูกด้วยการเชื่อม Microsoft ของ**คนที่กดนำเข้า** ใครก็ตามที่เข้าถึงคดีได้จะดูไฟล์ผ่าน token ของคนนั้น (ตาม `listCaseFolder`) ถ้าคนนั้นยกเลิกการเชื่อม คดีจะขึ้นสถานะ DISCONNECTED ตามที่ระบบทำอยู่แล้ว
- สิทธิ์: เฉพาะ `Role.ADMIN` และ `Role.LAWYER` เหมือน endpoint ผูกโฟลเดอร์
- ขนาด: ประมาณ 100 แถวต่อครั้ง ส่งเป็น request เดียวได้

## สิ่งที่ผู้ออกแบบตัดสินใจเอง (ผู้ใช้ยังไม่ได้ยืนยัน)

- **วันเปิดคดี (`openedAt`)** ใช้วันที่นำเข้าเหมือนคดีใหม่ทั่วไป เพราะวันที่ในโฟลเดอร์เชื่อไม่ได้ เกือบทุกโฟลเดอร์แก้ไขล่าสุด 22 ก.ค. 2025 ซึ่งเป็นวันที่ backup ลงไป ส่วนปีในเลขคดีก็มีไม่ครบทุกคดี ถ้าอยากได้วันย้อนหลัง ค่อยเพิ่มทีหลัง
- **ไม่ส่งแจ้งเตือนมอบหมายงานรายคดี** ตอนนำเข้า ถ้าตั้งทนายคนเดียวให้ 50 คดี จะกลายเป็น 50 push สร้างคดีผ่าน `CasesService` เหมือนเดิม แต่เพิ่มตัวเลือกปิดการแจ้งเตือนสำหรับการนำเข้า
- **กันสร้างซ้ำทั้งสำนักงาน** ใช้ `driveId` + `itemId` โดยไม่สนว่าใครเป็นคนเชื่อม Microsoft เพราะ unique key เดิมผูกกับ `connectionId` ถ้าคนที่สองนำเข้าโฟลเดอร์เดียวกัน จะสร้างคดีซ้ำได้
- **ไม่จำโฟลเดอร์ที่ติ๊กข้าม** เพราะเป็นการนำเข้าครั้งเดียว โฟลเดอร์ที่ไม่ใช่คดีราว 25 อันติ๊กใหม่ได้ ถ้าต้องนำเข้าบ่อยค่อยเพิ่ม
- **ตรวจโควตาคดีของแพ็กเกจก่อนสร้าง** ถ้าคดีที่เปิดอยู่จะเกิน `maxActiveCases` ให้บอกตั้งแต่ก่อนกด ไม่ใช่ให้พังทีละแถว
- **คนที่นำเข้าควรเป็นเจ้าของโฟลเดอร์ (Suchanya)** เพราะลิงก์ใช้การเชื่อม Microsoft ของคนนำเข้า เขียนบอกไว้ในหน้าจอ ไม่ได้บังคับในโค้ด

## ปล่อยให้ผู้สร้างตัดสินใจเอง

- รูปร่าง endpoint และ DTO ใช้ชื่อตามแบบที่มีอยู่ใน `outlook-integration/drive`
- จะสร้างคดีรายแถวหรือเป็นก้อนเดียว (transaction) แต่ต้องรายงานผลรายแถวและกดซ้ำได้ปลอดภัย **แต่ละแถวต้องจบในครั้งเดียว** ทั้งสร้างคดี ผูกโฟลเดอร์ และถ้าปิดแล้วก็ต้องมี `status=CLOSED`, `outcome`, `closingSummary`, `closedAt` และ stage ปิดเหมือนที่ `close()` ตั้ง ห้ามมีแถวที่สร้างแล้วแต่ยังไม่ผูกโฟลเดอร์ หรือปิดค้างไว้ครึ่งเดียว
- คดีที่นำเข้าแบบปิดแล้ว ไม่ต้องผ่านด่านของค้างของ `close()` เพราะคดีใหม่ยังไม่มีงานหรือนัดค้าง
- หน้าตาตาราง ให้ตามสไตล์ของแท็บเดิม
