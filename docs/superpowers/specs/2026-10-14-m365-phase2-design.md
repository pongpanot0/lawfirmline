| # | Feature | Short |

| F1 | Large files sent as a OneDrive link | A file too big to attach goes out as a "specific people" link automatically |

No new scope is needed: `Calendars.ReadWrite` covers getSchedule and delta, `Files.ReadWrite.All` covers createLink. No AI.

## F1 — Large files sent as a OneDrive link

**Rule:** for each attached case document in send/reply, if the file is ≤ 3 MB and the running inline total stays ≤ 15 MB → attach it as before. **Otherwise it is sent as a link** — no more error asking the user to do it themselves. Cap: 10 documents total (unchanged), each linked file ≤ 250 MB (larger → Thai BadRequest before any Graph call).

**Link = "specific people"** (confidential): upload a copy to the sender's own OneDrive `Samnuan/{ownRef}/ส่งออก` (`ensureFolderPath(token, ['Samnuan', ownRef, 'ส่งออก'])` + `upload`), then Graph `POST /me/drive/items/{id}/createLink` body `{ type: 'view', scope: 'users', recipients: [{ email }...to+cc] , retainInheritedPermissions: false }` → `link.webUrl`. Never `anonymous`. If the tenant refuses (Graph 400/403 on createLink) → Thai BadRequest `องค์กรของคุณไม่อนุญาตให้แชร์ไฟล์ OneDrive ให้ผู้รับนี้ — ลดขนาดไฟล์หรือส่งทางช่องทางอื่น` and **no draft is created**: all uploads + links are created BEFORE the draft. (Uploaded copies stay in the sender's OneDrive; acceptable, it is their own folder.)

**Body:** append to the HTML body (after the user text, before the quoted reply) a block `<p>ไฟล์แนบ (ลิงก์ OneDrive — เปิดได้เฉพาะผู้รับอีเมลนี้):</p><ul><li><a href="{webUrl}">{escaped filename}</a> ({size})</li></ul>`.

**API changes** (`outlook-send.service.ts`, `graph-drive.client.ts`):
- `GraphDriveClient.createSharingLink(token, driveId, itemId, recipients: string[]): Promise<{ webUrl: string }>` (validate ids like other methods).
- `loadAttachments` returns `{ inline: LoadedAttachment[], linked: { documentId, filename, mimeType, buffer }[] }` using the rule above.
- New step `shareLinkedFiles(token, ownRef, linked, recipients)` before `createDraft`.
- `SendCaseEmailResult` gains `linkedFiles: { documentId: string; filename: string }[]`. Audit metadata gains `linkedDocumentIds`.
- `composeOptions` gains `documentSizes: Record<documentId, number>`? **No** — no size column; skip. The web shows the rule as text.
- Tests: ≤3MB inline; 4MB → linked (upload + createLink with recipients to+cc, link in body); total >15MB overflow → linked; createLink 403 → BadRequest and `createDraftMessage` never called; >250MB → BadRequest before Graph; recipients de-duplicated.

**Web** (`CaseEmailComposer.tsx`): hint under attachments becomes `ไฟล์เกิน 3 MB ระบบจะส่งเป็นลิงก์ OneDrive ให้อัตโนมัติ (เปิดได้เฉพาะผู้รับ)`; confirm view keeps the attachment list with the same note; success toast appends `· ส่งเป็นลิงก์ {n} ไฟล์` when `linkedFiles.length`. Update `SendCaseEmailResult` type.

## F2 — Email templates

**Model:** firm-wide `EmailTemplate` (Task 1). Managed by `manageFirmContent`; used by everyone who can send.

**Built-ins** (code constants, read-only, `id: 'builtin:<key>'`, shown when choosing and in settings with a "คัดลอกไปแก้" button): 
1. `แจ้งนัดศาล` — subject `[{{ownRef}}] แจ้งนัดพิจารณาคดี วันที่ {{nextHearingDate}}`, body greeting `เรียน คุณ{{clientName}}`, hearing date/time/court, case numbers, closing `{{senderName}}`.
2. `ส่งเอกสาร` — subject `[{{ownRef}}] ส่งเอกสารคดี {{title}}`.
3. `ขอเอกสารเพิ่มเติม` — subject `[{{ownRef}}] ขอเอกสารเพิ่มเติม`.
(Write natural, polite Thai legal-office wording.)

**Variables:** reuse `TemplatesService` case variables — extract its var-building into a public `caseVariables(firmId, caseId): Promise<Record<string,string>>` (no behaviour change for document templates; keep their tests passing) and add `nextHearingDate` (th-TH long date, Asia/Bangkok), `nextHearingTime` (HH:mm), `nextHearingCourt` (next future `COURT_DATE` event of the case: courtName or case court), plus `senderName` (caller first+last name). Shared pure `fillPlaceholders(text, vars) → { text, missing: string[] }`: known+empty or unknown keys stay as `{{key}}` and are listed in `missing`.

**API** (new `apps/api/src/email-templates/` module or inside outlook-integration — pick the cleaner fit, likely its own small module importing TemplatesModule):
- `GET /email-templates` → built-ins + firm rows `{ id, name, subject, body, builtIn }` (any firm member).
- `POST /email-templates`, `PATCH /email-templates/:id`, `DELETE /email-templates/:id` — `@RequireCapability('manageFirmContent')`, firm-scoped, built-in ids refused. DTO: name ≤100, subject ≤255, body ≤20000, non-blank.
- `GET /cases/:caseId/email-templates/:id/render` (JwtAuthGuard + CaseAccessGuard) → `{ subject, body, missing: { key, label }[] }` with Thai labels for each key (e.g. `nextHearingDate` → `วันนัดถัดไป`).
- `GET /email-templates/variables` → `[{ key, label, example }]` for the editor chips.
- Audit `EMAIL_TEMPLATE_CREATED/UPDATED/DELETED`.
- Tests: CRUD scoping + capability; built-in refusal; render fills vars incl. next hearing; missing reported; `fillPlaceholders` unit tests.

**Web:**
- Composer: a `ใช้เทมเพลต` select at the top of the form (both new and reply). Choosing one calls render and fills subject (new mode only; reply keeps `Re:` subject) and **inserts the body above anything already typed** (confirm with an inline "แทนที่ข้อความเดิม?" only if body is non-empty → buttons แทนที่ / ต่อท้าย). If `missing` is non-empty show an amber note `ยังไม่มีข้อมูล: วันนัดถัดไป, ...` — the `{{…}}` stays in the text.
- `composeError` (web helper) blocks sending while the subject/body still contains `{{` → `ยังมีช่องข้อมูลที่ไม่ได้กรอก {{...}}`; API `send` mirrors it (BadRequest).
- Settings page `/settings/email-templates` (link in the settings `OFFICE_LINKS` card, gated `manageFirmContent`): list (built-ins first with badge "ตัวอย่าง"), create/edit in a `SideDrawer` with name, subject, body, **variable chips that insert `{{key}}` at the cursor**, and a live preview with example values. Delete with inline confirm. Members without the capability don't see the link; the composer still lists templates.

## F3 — Two-way calendar

**Read changes:** `GraphCalendarClient.calendarViewDelta(token, deltaOrStart: { deltaLink } | { start: Date; end: Date })` → `{ events: { id, start, end, isCancelled?, removed?: boolean }[], nextLink?, deltaLink? }` over `/me/calendarView/delta?startDateTime&endDateTime` (follow nextLink pages; `Prefer: odata.maxpagesize=100`; `@removed` → removed). Times: request `Prefer: outlook.timezone="UTC"`.

**Cron** `OutlookCalendarInboundService` every 5 minutes (guard `running`), per ACTIVE connection with userId and `syncCalendar`, that has ≥1 copy row:
- No `calendarDeltaLink` or `calendarDeltaStartedAt` older than 7 days → restart window `now-1d … now+400d`, store new deltaLink + startedAt, and **do not act on the first full page set** (baseline only) — except removed/moved detection is skipped too.
- Otherwise read delta; for each returned event id matching a copy row of this connection (`graphEventId`), compare Outlook start/end (minute precision) with the system event's `startAt` / effective end (`endAt ?? startAt + default` exactly as `buildOutlookEvent` computes). Equal → ignore (our own write echo).
- **Removed / cancelled** → set copy `removedInOutlookAt = now`; reconcile/sync must skip copies with `removedInOutlookAt` (never recreate). If the system event later changes, still skip. (A "ใส่กลับลง Outlook" action in the UI clears it — see web.)
- **Moved, event type `CLIENT_MEETING` or `OTHER`, and the copy owner is one of `eventPeopleIds(event)` or the Teams organizer** → apply: update `startAt`/`endAt` (keep duration from Outlook), which bumps `updatedAt` so the other copies + Teams meeting re-sync. Notify the other event people + lead lawyer (`notifyAssigned`, category CALENDAR, actor = copy owner) `🗓️ {ownerName} ย้ายนัดใน Outlook · {ownRef}\n{title}: {old} → {new}`. Audit `CALENDAR_EVENT_MOVED_FROM_OUTLOOK`.
- **Moved, type `COURT_DATE` or `DEADLINE`** (legal dates — never moved silently) → upsert an unresolved `CalendarEventOutlookChange` for (event, user) with the proposed times; notify the copy owner + lead lawyer `⚠️ นัดศาล/วันครบกำหนดถูกย้ายใน Outlook · {ownRef} — เปิดระบบเพื่อยืนยัน`. Nothing else changes.
- Moved by someone who is not a responsible person → treat like COURT (proposal), never apply.
- Per-connection try/catch; errors to `recordError` style log, never stop the loop; 410 Gone on delta → clear deltaLink (restart next run).

**Endpoints** (event access = same rule the calendar controller already uses for viewing/editing an event; reuse its guard/service check):
- `GET /calendar/events/:id/outlook-changes` → unresolved proposals with user name.
- `POST /calendar/events/:id/outlook-changes/:changeId/apply` → set event times to the proposal, resolve (APPLIED), resolve other open proposals for the event as KEPT, audit.
- `POST /calendar/events/:id/outlook-changes/:changeId/keep` → resolve KEPT and force re-sync of that user's copy (set its `syncedAt` older / call `syncEventSoon`) so Outlook goes back to the system time.
- `POST /calendar/events/:id/outlook-copies/restore` (caller's own copy) → clear `removedInOutlookAt` + `syncEventSoon`.
- Event detail payload (whatever the dialog loads) gains `outlookChanges` count/list and `myCopyRemovedInOutlook: boolean` — or the dialog calls the GET; pick the smaller change.

**Do not** add ImmutableId to calendar calls (stored copy ids are in the default format; delta returns the same format).

Tests: echo ignored; meeting moved → applied + notify; court moved → proposal only; non-responsible → proposal; removed → flagged and reconcile skips it; first window = baseline only; 410 resets; apply/keep/restore endpoints.

**Web** (`CalendarEventDialog.tsx` view mode, and a small badge in calendar lists if cheap):
- Amber banner when proposals exist: `{ชื่อ} ย้ายนัดนี้ใน Outlook เป็น {วันเวลาใหม่}` + buttons `ใช้เวลาใหม่` / `คงเวลาเดิม` (in-flight disabled, error inline).
- If my copy was removed in Outlook: muted note `คุณลบนัดนี้ออกจากปฏิทิน Outlook แล้ว` + `ใส่กลับลง Outlook`.
- Info line under the time field for meetings: `ย้ายเวลาใน Outlook ได้ ระบบจะอัปเดตตาม` and for court/deadline: `ถ้าย้ายใน Outlook ระบบจะถามยืนยันก่อน`.

## F4 — New-email alerts on a case

- `OutlookSyncService.upsertGraphMessage` result gains `created: boolean` and `caseId: string | null` (thread's case after the upsert). Only a successful message `create` is `created: true`.
- Callers collect INBOUND + created + caseId results per run: `CaseFolderSyncService.runLink` and the inbox/sent drains in `OutlookSyncService.syncConnection`.
- **Backfill suppression:** a link/folder with no cursor before the run (first sync) does not notify; the inbox drain's first sync (no deltaLink) does not notify. Additionally ignore messages whose `receivedDateTime` is older than 24 h.
- New `CaseEmailNotifier.notifyNewInbound(caseId, items: { fromName, fromAddress, subject }[], mailboxOwnerUserId)`: one notification per case per run via `AssignmentNotifierService.notifyAssigned` — recipients `LineLinkService.getCaseTeamUserIds(caseId)` minus the mailbox owner (they already got it in Outlook), `actorUserId: ''`, category `EMAIL`, `summaryText` `📧 อีเมลใหม่ {n} ฉบับ · {ownRef}\n{fromName||fromAddress}: {subject}` (first 3 lines, then `และอีก {k} ฉบับ`), `entityPath: /cases/{caseId}?tab=email` (verify the actual case-tab key for the email tab in `apps/web/src/lib/case-tabs.ts`). Never throws (notification failure must not fail sync).
- Make sure `EMAIL` works everywhere categories are listed (preferences API validation, web/mobile labels: label `อีเมลเข้าคดี`). grep `NotificationCategory` / category label maps in apps/web and apps/api.
- Tests: created flag (new vs existing vs P2002 race); first sync silent; >24h silent; grouping one call per case; owner excluded; notifier failure swallowed.

## F5 — See who is free

**API** `POST /calendar/availability` (JwtAuthGuard) body `{ userIds: string[] (1..20, uuid, same firm), date: 'YYYY-MM-DD' (Bangkok day), excludeEventId?: string }` → `{ date, people: [{ userId, name, source: 'OUTLOOK' | 'SYSTEM_ONLY', busy: [{ start: ISO, end: ISO, label?: string }], error?: string }] }`:
- System busy: that day's `CalendarEvent`s where the user is in event people (`eventForUserWhere`), excluding `excludeEventId`; label = event title only if the caller can access the case (otherwise `ไม่ว่าง`); end = effective end as in F3.
- Outlook busy: if the **caller** has an active connection, one Graph `POST /me/calendar/getSchedule` with `schedules` = mailbox addresses of those users' active connections (users without a connection → `SYSTEM_ONLY`), `startTime/endTime` = 07:00–21:00 Asia/Bangkok, `availabilityViewInterval: 30`; use `scheduleItems` with status `busy|oof|tentative|workingElsewhere` (not `free`), no subjects (privacy). Per-schedule `error` → person `error: 'ดูปฏิทิน Outlook ไม่ได้'`. Drop Outlook items that are copies of system events (same start/end as a system block for that user) to avoid duplicates.
- If the caller has no connection → everyone `SYSTEM_ONLY` + top-level `hint: 'เชื่อมต่อ Microsoft 365 เพื่อดูเวลาว่างจาก Outlook'`.
- Users must be active members of the caller's firm (else 400). Tests: merge + dedupe, privacy label, no-connection path, getSchedule error per person, firm check.
- `GraphCalendarClient.getSchedule(token, emails, startIso, endIso)`.

**Web** (`CalendarEventDialog.tsx`, edit mode, all types except DEADLINE):
- Add **duration** select next to the time for CLIENT_MEETING / OTHER / COURT_DATE: 30 นาที / 1 ชม. (default) / 1.5 ชม. / 2 ชม. / 3 ชม. / ครึ่งวัน (4 ชม.) → sends `endAt` (API DTO already has `endAt`; verify create+update persist it and existing events show their duration).
- Panel `เวลาว่างของทีม` (collapsed by default, auto-opens for CLIENT_MEETING) showing, for the selected date, one horizontal row per person (selected assignees, or lead lawyer when none, + me) over 08:00–19:00 with busy blocks (grey; amber for tentative), the chosen slot outlined in the primary color; red outline + text `ชนกับนัดของ {ชื่อ}` when it overlaps. Clicking an empty area sets the start time (snap 30 min). Button `หาเวลาที่ทุกคนว่าง` → earliest slot of the chosen duration ≥ now on that day, otherwise checks the next 5 working days (call the API per day, stop at first hit) and moves the date/time there; nothing found → `ไม่พบช่วงที่ทุกคนว่างใน 5 วันทำการ`.
- Pure helpers in `apps/web/src/lib/availability.ts` with `node --test`: overlap check, find-first-free-slot (busy merge, working hours 08:00–19:00 Bangkok, step 30 min), block → percentage position.
- Loading skeleton row, error + retry, `SYSTEM_ONLY` people tagged `(ไม่ได้เชื่อม Outlook — เห็นแค่นัดในระบบ)`.
- Mobile width: rows scroll horizontally inside the panel; no page overflow.
