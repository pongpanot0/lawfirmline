## ข้อมูลเช็กอินที่ต้องเตรียม

- กำหนดผู้ใช้ วันที่ตามเวลาเขตสำนักงาน สถานะ (`not_yet`, `checked_in`, `skipped`, `blocked`), เวลาส่ง/แก้ไข, รายการอ้างอิงงานเมื่อวานและวันนี้, ข้อความเพิ่มเติมแต่ละข้อ และข้อความสิ่งที่ติดหรือค่าไม่มีปัญหา `blocked` คือเช็กอินที่ระบุสิ่งติดขัด; ต้องกำหนดกติกาเปลี่ยนสถานะเมื่อแก้ไขและสิทธิ์การอ่านก่อนพัฒนา
- เติมชิปจากงานที่ผู้ใช้แก้ไขหรือทำเสร็จเมื่อวาน และงานที่ถึงกำหนดหรือวางแผนวันนี้จากข้อมูลจริง ไม่ใช้ AI; ผู้ใช้เอาชิปเมื่อวานออก เลือกชิปวันนี้ เพิ่มข้อความ และข้ามได้
- แจ้ง push และแสดงการ์ดเฉพาะผู้มีบทบาททนายในเช้าวันจันทร์–ศุกร์ ยกเว้นวันลาของคนนั้นและวันหยุดสำนักงาน; กำหนดเวลา เขตเวลา การแก้ไขย้อนหลัง และวิธีจัดการวันหยุดให้ชัดเจนก่อนพัฒนา
- ผู้จัดการเห็นสถานะใน radar และประวัติใน drawer; AI อ่านเช็กอินประกอบเมื่อผู้จัดการกดร่างเท่านั้น สิทธิ์เข้าถึงและขอบเขตข้อมูลต้องกำหนดก่อนพัฒนา
- การแนะนำผู้รับงาน: ไม่มีงานเกินกำหนด ไม่ลา และมีแต้มงานเปิดน้อยที่สุดในผู้เข้าเกณฑ์; กติกาเมื่อแต้มเท่ากันและเกณฑ์กรณีไม่มีผู้เข้าเกณฑ์ต้องยืนยันกับผลิตภัณฑ์

## ข้อมูลและสถานะสำหรับผู้พัฒนา
ข้อมูลด้านล่างเป็นข้อเสนอสำหรับพัฒนา ไม่ใช่สัญญา API ที่มีอยู่แล้ว

- `TeamRadarMember` ใน source ที่ตรวจยังไม่มี `standardPoints` หรือข้อมูล coaching; mockup สมมติให้มีเกณฑ์รายคน 5–30 แต้มและตัวบอกคำแนะนำใหม่/ล่าสุด ต้องกำหนดแหล่งข้อมูลและสิทธิ์ก่อนพัฒนา
- source ปัจจุบันเรียงตาม `openPoints` และ `workloadStatus` ใช้เกณฑ์สำนักงาน; แบบนี้แสดงลำดับที่ brief ระบุ: เกินเกณฑ์ → เลยกำหนด → ใกล้เกณฑ์ → ว่าง → ลา ต้องตกลงกฎเมื่อหลายสถานะซ้อนกันและวิธีใช้เกณฑ์รายคน
- ข้อมูลร่างต้องมาจากอัปเดตงานรายวัน ความคิดเห็น งานเลยกำหนด แต้มคิวเทียบเกณฑ์ และแต้มที่เสร็จรายสัปดาห์ย้อนหลัง 8 สัปดาห์; เริ่ม AI เฉพาะเมื่อกด ร่างยังไม่บันทึกก่อนยืนยันส่ง
- Coaching note ต้องมีผู้รับ ผู้ส่ง วันส่ง ข้อความที่แก้แล้ว งานอ้างอิง สถานะ/วันรับทราบ และข้อความตอบกลับหนึ่งบรรทัดแบบไม่บังคับ พร้อมการแจ้งเตือนผู้รับ; กำหนดสิทธิ์เข้าถึงและการนับใหม่/ล่าสุด
- สถานะที่ต้องออกแบบเพิ่มเมื่อพัฒนา: กำลังร่าง, ร่างไม่สำเร็จ/ลองใหม่, ส่งไม่สำเร็จ, ไม่มีประวัติ, กำลังโหลด, กรองไม่พบ, รับทราบแล้ว/ส่งคำตอบไม่สำเร็จ; การ์ดสรุปต้องกำหนดช่วงเวลาและขอบเขตทีมให้ตรงข้อมูลจริง
- HTML เป็นภาพจำลอง: ปุ่มส่ง/รับทราบและตัวกรองยังไม่เชื่อมระบบ ลิงก์งานเป็นตัวอย่าง และต้องใช้อินเทอร์เน็ตโหลด Tailwind, Lucide และฟอนต์
- PNG ที่มีอยู่เป็นภาพ v2 เดิม ยังไม่ได้ render v3 ตามคำขอ
