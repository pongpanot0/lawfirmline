## R — Unanswered client email reminder (API Task 2, web Task 3)
**Definition** — a case thread is *awaiting reply* when: `caseId` set; its latest message (by `receivedAt`) is `INBOUND`; the sender is **not internal** (sender address is not the email of any member of the firm and not any `MailboxConnection.mailboxAddress` of the firm, case-insensitive); and `replyDismissedAt` is null or earlier than that message's `receivedAt`. `awaitingSince` = that message's `receivedAt`. A reply sent from the system or from Outlook (Sent Items sync attaches OUTBOUND to the thread) ends it automatically.

**Threshold** — firm setting `slaConfig.emailReplyHours` (default 24, allowed 1–168), through the existing `getSlaConfig` / `updateSlaConfig` in `apps/api/src/operations/operations.service.ts` (add the default; keep other keys; check its controller guard and reuse it).

**Cron** `EmailReplyReminderService` `@Cron('0 9,14 * * 1-5', { timeZone: 'Asia/Bangkok' })` (skip if today is a `PublicHoliday`), `running` guard: per firm, threads with `caseId != null` and `lastMessageAt` within the last 14 days; compute awaiting; if `now - awaitingSince ≥ threshold` and `replyReminderMessageId !== latestInbound.id` → group per case, one `notifyAssigned` per case: recipients `LineLinkService.getCaseTeamUserIds(caseId)`, `actorUserId: ''`, category `EMAIL`, `summaryText` `⏰ อีเมลลูกความรอตอบ · {ownRef}\n{fromName||fromAddress}: {subject} (รอ {n} ชม.)` (max 3 lines + `และอีก {k} ฉบับ`), `entityPath: /cases/{caseId}?tab=email`, `appPath: /case/{caseId}?section=email`; then set `replyReminderMessageId` for those threads (after a successful call; notifier never throws). Bounded queries (no N+1 per message: load the latest message per thread with one query, e.g. `distinct`/ordered findMany on threadId).

Also add `appPath: /case/{caseId}?section=email` to the existing new-email alert (`case-email-notifier.service.ts`).

**API changes**
- `listCaseThreads` items gain `awaitingReplySince: string | null` (same definition; compute in the same query set, bounded).
- `POST /cases/:caseId/email/threads/:threadId/reply-dismiss` → sets `replyDismissedAt = now`; `DELETE` same path → clears it. Thread must belong to the case and pass the existing visibility filter. Audit `EMAIL_REPLY_DISMISSED` / `EMAIL_REPLY_UNDISMISSED`.
- Tests: internal sender ignored; outbound after inbound = answered; dismissed then new inbound = awaiting again; threshold respected; one reminder per inbound message; holiday/weekend skip; grouping per case; list field.

## S — Personal email signature (Task 4, API + web)
- API: extend `UpdatePreferencesDto` / `GET+PATCH users/me/preferences` with `emailSignature?: string` (≤ 2000 chars; empty string → null).

In `outlook-send.service.ts` send: if true and the user has a signature → append `<br><div style="color:#444">-- <br>{escaped, newlines→<br>}</div>` after `linksHtml(...)` (so in replies it stays above the quoted original). `composeOptions` gains `signature: string | null` for preview.

- Tests: signature appended + escaped; not appended when false/none; reply keeps it above quote; preferences round-trip.

## M — Email on mobile (Task 6)
App: `apps/mobile` (Expo SDK 56, expo-router, React Query, `api<T>()` client, `FormPage/FormField`, `ui.tsx` components, `Dropdown`, RN `Modal` sheets, theme tokens, `AppText`). Follow the existing screens' look; Thai text; large touch targets (court-phone-first).
- Case detail `app/case/[id].tsx`: add tab `อีเมล` (lazy query `enabled: tab === 'อีเมล'`), deep link `section=email` selects it. List rows: subject, from, relative time, `📎n`, amber `รอตอบ` tag when `awaitingReplySince`; pull-to-refresh; empty state `ยังไม่มีอีเมลในคดีนี้ — ผูก folder Outlook ได้ที่เว็บ`; a primary button `เขียนอีเมล`.
- Thread screen `app/case/[id]/email/[threadId].tsx`: messages oldest→newest as cards (from, to/cc collapsed, date, **bodyText** — no HTML/WebView), attachments listed (download/open via the email attachment endpoint `GET /email-intake/attachments/:attachmentId/download` reusing the mobile file-open helper pattern in `src/api/files`), per-message `ตอบกลับ` / `ตอบทั้งหมด`, and when awaiting: `ไม่ต้องตอบ` (calls reply-dismiss).
- Compose screen `app/case/[id]/email/compose.tsx` (params: `replyTo?`, `replyAll?`): loads compose-options; if `mailboxAddress` null → explain `เชื่อมต่อ Microsoft 365 ที่หน้าเว็บ (ตั้งค่า) ก่อน` and stop. Fields: ถึง / สำเนา as chip inputs (type + add, tap a case contact suggestion to add, validate email), หัวเรื่อง (`[ownRef] ` for new; `Re: …` for reply), template picker (Dropdown of `GET /email-templates`, render → fill, replace/append choice if body non-empty, missing-fields note), ข้อความ (multiline), แนบเอกสารคดี (sheet with checkboxes of case documents; note that files > 3 MB go as OneDrive links), `แนบลายเซ็น` switch with preview, then `ตรวจทานก่อนส่ง` → confirm view (from, to, cc, subject, attachments count, signature yes/no) → `ส่งอีเมล` (in-flight disabled). Same validation rules as web (reuse logic by copying the pure helpers from `apps/web/src/lib/case-email-compose.ts` into `apps/mobile/src/lib/` — no cross-app import). `clientRequestId`: one RFC4122 v4 per compose (small Math.random-based generator is fine). Success: toast/Alert `ส่งอีเมลแล้ว` (+ linked-files / REPLY_AS_NEW notes), go back and invalidate the thread list/detail queries. Errors: Thai inline with the API message.
- Drafts: keep text if the user leaves accidentally? Skip (YAGNI) — but confirm before discarding a non-empty draft on back (`ทิ้งข้อความที่เขียน?`).
- Verify: mobile `tsc --noEmit` once; if there is a node check-script pattern that fits a pure helper, add one small script for the copied helpers (e.g. `apps/mobile/scripts/check-email-compose.cjs`) or skip if it would need a TS loader.
