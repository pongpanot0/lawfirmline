# นำเข้าคดีจาก Excel (template ของระบบ)

วันที่: 2026-10-31 · สถานะ: ร่าง รออนุมัติ · ต่อยอดจาก `2026-10-31-onedrive-case-import-design.md`

## ทำไม

คดีเก่าไม่ได้อยู่ใน OneDrive เสมอไป ผู้ใช้อยากกรอกรายการคดีลง Excel แล้วนำเข้าระบบทีเดียว สำนักงานยังไม่มีไฟล์ Excel คดีเดิม ระบบจึงต้อง**ให้ template ที่ครอบคลุม**ช่องของคดี (ผู้ใช้ยืนยันแล้ว)

## เป้าหมาย

1. ดาวน์โหลด template `.xlsx` จากระบบได้ มี dropdown ในช่องที่เป็นตัวเลือก และมีแผ่นอธิบายวิธีกรอก
2. อัปโหลดไฟล์ที่กรอกแล้ว ระบบอ่านแล้วแสดงตารางตรวจทีละแถว พร้อมเหตุผลเป็นภาษาไทยในแถวที่ผิด แก้ในตารางได้
3. กดสร้าง ระบบสร้างหนึ่งคดีต่อหนึ่งแถว แต่ละแถวจบในครั้งเดียว และรายงานผลรายแถว
4. **ไม่มีอะไรถูกสร้างก่อนกดสร้าง**

## สิ่งที่ไม่ทำ

- ไม่สร้างลูกความใหม่จากชื่อในไฟล์ **(ผู้ออกแบบเลือกเอง)** ถ้าชื่อตรงกับลูกความที่มีอยู่แบบตรงตัวหลังตัดช่องว่าง ให้ผูก `clientId` ถ้าไม่ตรง ให้จดเป็น `clientName` ในคดี
- ไม่ผูกโฟลเดอร์ OneDrive จาก Excel ใช้ปุ่ม "สร้าง folder ใหม่" หรือ "ผูก folder" ในหน้าคดีทีหลัง
- ไม่รับไฟล์ในรูปแบบอื่นนอกจาก template ระบบอ่านจากชื่อหัวคอลัมน์ ไม่เดาคอลัมน์ ไม่รับ CSV
- ไม่ใช้ AI

## Template (แผ่น "คดี" หนึ่งแถวต่อหนึ่งคดี, * = ต้องกรอก)

| หัวคอลัมน์ | ลงช่องไหนในคดี | กฎ |
|---|---|---|
| ชื่อคดี * | `title` | 1–300 ตัวอักษร |
| ทนายหลัก (อีเมล) * | `leadLawyerId` | ต้องเป็นอีเมลทนาย/แอดมินในสำนักงาน (ไม่รวม EXTERNAL) |
| ชั้นศาล * | `courtLevel` | dropdown: ศาลชั้นต้น / ศาลอุทธรณ์ / ศาลฎีกา |
| ทีม (อีเมล คั่นด้วย ;) | `buddyIds` | ทุกอีเมลต้องเป็นสมาชิกสำนักงาน |
| เลขอ้างอิงภายใน | `ownRef` | เว้นว่างได้ ระบบออกเลขให้ ถ้ากรอกแล้วซ้ำ → แถวนั้นผิด |

| ฐานะลูกความ | `partyRole` | dropdown: โจทก์ / จำเลย / ผู้ร้อง / ผู้คัดค้าน |

| ประเภทคดี | `caseTypeId` | dropdown จากประเภทคดีที่เปิดใช้ของสำนักงาน ณ ตอนดาวน์โหลด |
| ศาล | `courtName` | |
| เลขคดีดำ | `blackCaseNumber` | `CASE_NUMBER_REGEX` |

| สรุปตอนปิด | `closingSummary` | ≥ 10 ตัวอักษรถ้าปิดแล้ว ค่าว่างใช้ `นำเข้าจาก Excel: <ชื่อคดี>` |
| รายละเอียด | `description` | |

- **แผ่น "วิธีกรอก"** อธิบายทุกคอลัมน์ มีตัวอย่าง 2 แถว (คดีเปิด 1 แถว, คดีปิด 1 แถว) พร้อมรายชื่ออีเมลทนายของสำนักงาน
- **แผ่นซ่อน "lists"** เก็บค่าของ dropdown
- **แถวว่างทั้งแถวให้ข้าม** ไฟล์หนึ่งรับได้สูงสุด 300 แถว ขนาดไม่เกิน 2 MB

## ขั้นตอน

อยู่ที่หน้ารายการคดี หรือหน้าตั้งค่า (ผู้สร้างเลือกได้) เป็นปุ่ม **"นำเข้าคดีจาก Excel"**

1. **"ดาวน์โหลด template"**: `GET` ไฟล์ `.xlsx` ที่สร้างตามสำนักงาน (ประเภทคดี และรายชื่อทนาย)
2. **อัปโหลดไฟล์**: ระบบอ่านแล้วตรวจทุกแถว ยังไม่สร้างอะไร ส่งกลับเป็นร่างรายแถว ประกอบด้วยค่าที่อ่านได้ ค่าที่แปลงแล้ว (อีเมล → user id, ชื่อลูกความ → clientId หรือชื่อ) และรายการปัญหาภาษาไทย
3. **ตารางตรวจ**: แสดงทุกแถว ติ๊กเลือกได้ แถวที่มีปัญหาติ๊กไม่ได้จนกว่าจะแก้ ช่องหลักแก้ในตารางได้ ได้แก่ ชื่อคดี, ทนายหลัก, ชั้นศาล, เลขคดีดำ/แดง, สถานะ/ผลคดี/สรุป ช่องอื่นให้แก้ในไฟล์แล้วอัปโหลดใหม่
4. **"สร้าง N คดี"**: แต่ละแถวเป็น transaction เดียว ทำผ่าน `CasesService.createForImport` ที่ขยายช่องเพิ่ม เมื่อเสร็จรายงาน สร้างแล้ว (ลิงก์ไปคดี) หรือไม่สำเร็จ (เหตุผล) ทีละแถว

## กติกาที่ต้องเหมือนการนำเข้าจาก OneDrive

- ไม่ส่งแจ้งเตือนมอบหมายงาน ไม่ผ่านด่าน conflict check (เป็นงานเก่า)
- ตรวจโควตาแพ็กเกจก่อนสร้าง โดยนับเฉพาะแถวที่เปิดอยู่ คดีที่ปิดแล้วไม่นับ
- ตรวจสมาชิกทีมทั้งคำขอก่อนเขียนอะไร
- คดีที่ปิดแล้ว ลงด้วยฟิลด์เดียวกับ `close()` ได้แก่ `status`, `outcome`, `closingSummary`, `closedAt` และ stage `CLOSING`
- ทุก query ผูกกับ `firmId` ของผู้ใช้ ไม่มีข้อมูลข้ามสำนักงาน ผู้ใช้ย้ำแล้วว่า "ห้ามเห็นของกันและกัน"
- สิทธิ์ใช้งาน: `Role.ADMIN` และ `Role.LAWYER`

## กันนำเข้าซ้ำ (ผู้ออกแบบเลือกเอง)

Excel ไม่มีรหัสคงที่แบบโฟลเดอร์ OneDrive การกันซ้ำจึงทำตอนตรวจ แถวจะเป็นปัญหา `มีคดีนี้ในระบบแล้ว (<ownRef>)` และติ๊กไม่ได้ เมื่อเข้าเงื่อนไขข้อใดข้อหนึ่ง:
- **เลขอ้างอิงภายใน**ตรงกับคดีที่มีอยู่ในสำนักงาน
- **เลขคดีดำ + ศาล** ตรงกับคดีที่มีอยู่ในสำนักงาน (เทียบทั้งของคดีและของทุก `CaseProceeding`) เลขดำเดียวกันแต่คนละศาลเป็นคนละคดีได้ เลขดำที่ไม่มีศาลให้เทียบเฉพาะเลข
- **สองแถวในไฟล์เดียวกัน**ซ้ำกันด้วยกติกาเดียวกัน

แถวที่ไม่มีทั้งเลขอ้างอิงและเลขคดีดำ จะกันซ้ำไม่ได้ ให้แสดงคำเตือนไว้เหนือตาราง

## สิ่งที่ผู้ออกแบบตัดสินใจเอง (เพิ่มหลัง builder check)

- **ลูกความต้องค้นเจอใน conflict check ได้:** ทุกแถวที่มีชื่อลูกความ ให้สร้าง `CaseParticipant` ฝั่ง OURS ด้วย ถ้าผูก `clientId` ได้ ใช้ `ensureOurClientParticipant` ตามปกติ ถ้าไม่ผูก ให้สร้างแถวชื่ออย่างเดียว ฝ่ายตรงข้ามใช้ `addOpponents` ตามเดิม การนำเข้าข้ามด่าน conflict แต่คู่ความต้องค้นเจอในการตรวจครั้งต่อไป
- **เตือนวันครบอายุความยังทำงาน:** คดีเปิดที่อายุความใกล้ครบ จะได้การเตือนที่เลยกำหนดแล้วหลายอันพร้อมกันในรอบถัดไป ยอมรับได้ เพราะเป็นกำหนดตามกฎหมายที่ห้ามพลาด คดีที่ปิดแล้วหรือมีเลขคดีดำแล้ว `syncLimitationReminder` ไม่ตั้งเตือนอยู่แล้ว
- **ใครเป็นทนายหลักได้:** ใช้รายชื่อเดียวกับ `GET /users/lawyers` คือ role ADMIN/LAWYER และไม่ใช่ EXTERNAL ทั้งในแผ่นอธิบายและตอนตรวจแถว ทีมใช้กติกาเดียวกับ `create()` คือสมาชิกที่ไม่ใช่ EXTERNAL

## สิ่งที่ผู้สร้างตัดสินใจเองได้

- ไลบรารีอ่าน/เขียน `.xlsx` ผู้ออกแบบแนะนำ `exceljs` ฝั่ง API เพราะเขียน dropdown (data validation) ได้ ส่วน SheetJS รุ่นฟรีทำไม่ได้ ถือเป็น dependency ใหม่ 1 ตัว
- รูปร่าง endpoint และ DTO
- หน้าตาตาราง ให้ใช้รูปแบบเดียวกับ `DriveCaseImportTable`
