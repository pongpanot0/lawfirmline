## หลักฐานทดสอบ

### Browser กับ API จริง

- ใช้บัญชี Owner บน tenant `thesiambarristers.localhost:3005` ไม่ใช้ผลจากหน้า apex แทน tenant
- พิมพ์เรื่องอุบัติเหตุสมมติ → ค้นจริงจากผู้ให้บริการ → ได้ฎีกา 3 รายการ, ข้อเท็จจริง 3 รายการ และข้อสังเกตข้อมูลขาด 3 รายการ
- แก้จำนวนเงินใน Fact ให้เป็นถ้อยคำที่ผู้ใช้ระบุ → บันทึก → ตรวจเทียบ → reload → กรองตรวจแล้ว พบข้อความที่แก้ พร้อมประวัติ 2 ครั้ง ยังคงอยู่
- สร้าง intake ชื่อ `ทดสอบ UX — รับงานประกัน (ข้อมูลสมมติ)` ด้วยชื่อและข้อความ โดยไม่กรอกลูกความ/ทีม/เคลมครบก่อน
- อัปโหลด `insurance-ux-synthetic.txt` จากพื้นที่ทำงาน → เอกสารขึ้นในเรื่อง 1 ไฟล์ → จัด Facts จริง → ได้ข้อเท็จจริงพร้อมข้อความอ้างอิงและชื่อไฟล์ 4 ข้อ พร้อมปุ่มต้นฉบับรุ่น 1 และข้อสังเกตข้อมูลขาด 1 ข้อ
- หน้า `/work` แสดงงานคดี 4 งาน และเปิด `Gather evidence documents` ในแผงรายละเอียดงานที่ถูกต้อง
- เปิดแท็บ Facts/ฎีกาในคดีจริงได้ โดยไม่ได้ส่งเอกสารคดีจริงหรือข้อมูลผู้ป่วยไปวิเคราะห์ใหม่
- ตรวจบอร์ดจริง: คดีใหม่ 1 / ยื่นฟ้อง 2 / รอคำพิพากษา 1 / ปิด 1 และค่าที่เลือกตรงกับคอลัมน์
- เปิดหน้ารับเรื่องใหม่ สร้างคดี ใบแจ้งหนี้ และพื้นที่คดีหลังแก้ ไม่พบข้อผิดพลาดที่ยังค้างในการแสดงผล
- ตรวจหน้าจอที่ 320, 768, 1024 และ 1440px ในหน้าหลักที่เปลี่ยน โดยวัดความกว้าง main กับเนื้อหาและดูภาพจริง ไม่พบเนื้อหาล้นแนวนอนในตัวอย่างที่ตรวจ
- ทดสอบ API ด้วย Owner, Senior และ Lawyer จริง: อีกสองบัญชีไม่เห็นประวัติค้นส่วนตัวของ Owner และ PATCH ผลนั้นถูกปฏิเสธด้วย 404; งานรวมได้ตามขอบเขตบัญชี 4/1/0 รายการ

ข้อมูลสมมติถูกเก็บไว้ให้เปิดตรวจผลต่อได้: intake `c095be97-8bba-4337-8dde-f8fdeef70c60` และประวัติ research ของ Owner วันที่ 20 กันยายน 2569 เวลา 12:28 ไม่มีการสร้างบิล ชำระเงิน ส่งอีเมล หรือเปลี่ยนข้อเท็จจริงของคดีจริงในการทดสอบนี้

### การตรวจอัตโนมัติ

- API: ผ่าน 248 กรณี ใน 26 suites ครอบคลุมชุดรับเรื่อง, intelligence, dashboard, cases controller, calendar และ billing
- เพิ่ม regression tests สำหรับข้อความล้วน, facts-only ไม่เรียกผู้ให้บริการฎีกา, input ว่าง, ผู้ให้บริการล้มเหลว, สิทธิ์คดี/ไฟล์, ประวัติส่วนตัว, การแก้พร้อมกัน, ข้อสังเกตไร้หลักฐาน, คำตอบไม่มีเอกสาร, เลขหน้าที่แต่งขึ้น และการล้าง description เพื่อใช้เฉพาะไฟล์
- Web unit tests ผ่าน 53 กรณี
- TypeScript ฝั่ง web/API ผ่าน
- Production build ของ web ผ่าน รวมการสร้าง static pages 58/58 ใช้ output `.next-verify` แยกจาก dev server
- พบ React ซ้ำใน local node_modules ทำให้ build หน้าข้อผิดพลาดล้มเหลว แก้ local runtime ให้ web/root/Next ใช้ React สำเนาเดียวกัน แล้ว build ผ่าน ไม่เปลี่ยนรุ่นใน manifest หรือ lockfile

## ฐานข้อมูลและขอบเขตที่ต้องรู้

- Migration ใหม่ `20260920130000_research_workspace`: อนุญาตผลค้นที่ไม่มี intake, เก็บ firmId และเพิ่ม index; ไม่มีการลบตารางหรือ reset ข้อมูล
- ฐานข้อมูล local เดิมไม่มี migration history ที่ตรงกับ schema (81 migrations ยังไม่ถูกลงประวัติ) จึง execute เฉพาะ migration ใหม่นี้บน local สำเร็จ ไม่ deploy migrations เก่าทั้งหมดทับฐานข้อมูล ก่อนใช้งานกับฐานอื่นต้องใช้กระบวนการ migration/baseline ของสภาพแวดล้อมนั้น
- Generated Prisma client ถูกอัปเดต และตั้ง watchAssets เพื่อให้ dev server รับ client ใหม่หลัง generate
- ทดสอบ browser ครั้งนี้เป็น E2E ของ flow ที่เปลี่ยนและ smoke ของหน้าที่เกี่ยวข้อง ไม่ใช่ทุกธุรกรรมของ 50 route ใน audit เดิม และไม่ใช่การตรวจหลายบทบาทใน browser ครบทุกหน้าหรือทดสอบ portal ทุกขั้นตอน
- AI ใน workspace รอบนี้รองรับ PDF/TXT; การอ่านรูปภาพเดี่ยวและ DOCX ยังไม่ได้เพิ่ม ส่วน PDF สแกนมีขีดจำกัดตาม OCR_MAX_PAGES (ค่าเริ่มต้น 30)
- PDF/OCR error paths มีการป้องกันในโค้ด; browser upload ที่รันจริงใช้ TXT สมมติ ไม่ได้ยืนยัน OCR ของชุดเอกสารจริงทุกประเภท
- หน้าใบแจ้งหนี้ใช้ 20 รายการล่าสุดตาม API เดิม ไม่ใช่รายงานย้อนหลังทุกเดือน และยังไม่ได้เพิ่ม rate card/วางบิลรวมรายบริษัทหรือรายงานประกันรูปแบบใหม่
- เลือก Facts ค้นต่อเป็นข้อความที่ผู้ใช้คัดเลือกพร้อมระบุต้นทาง ไม่ได้ยกระดับเป็นข้อยุติทางกฎหมาย การแปลง intake เป็น case ใช้กลไกพาประวัติและไฟล์ไปต่อที่มีอยู่เดิมและมี regression tests; ไม่ได้แปลงเรื่องสมมติเป็นคดีผ่าน browser ในรอบนี้

## Dashboard รอบปรับใหม่ตาม feedback

- เปลี่ยนหน้า `/dashboard` เป็นภาพรวมงาน: สรุปตัวเลขแบบแถบเดียว รายการงานที่ทำต่อได้ และนัด/กำหนดถัดไป ไม่มีการ์ดวันนี้/พรุ่งนี้ว่างขนาดใหญ่
- แท็บงานและเรื่องรับเข้าล่าสุด; งานกรองทั้งหมด/มอบหมายให้ฉัน/เกินกำหนด พร้อมผู้รับผิดชอบและสถานะจริง; ตัวเลขเกินกำหนดเปิดตัวกรองในหน้าเดียว
- เรื่องรับเข้าแสดงบริษัทประกัน/ลูกความ และเลขเคลมเมื่อมีข้อมูล; ปุ่มหลักรับงานใหม่และทางเข้าข้อเท็จจริง/ฎีกาแบบข้อความ
- ย้ายรายงานและค่าใช้จ่ายเป็นลิงก์สำหรับ Owner; ตัดผู้ช่วย AI ลอยซ้ำบน dashboard เท่านั้น; มือถือเรียงงาน → นัดและทางค้น → คดีล่าสุด
- แยก failure state ตามแหล่งข้อมูลและมี retry; แท็บรองรับลูกศร/Home/End; วันและเวลาใช้ Asia/Bangkok; ไทย/อังกฤษตาม locale
- ตรวจ browser จริงบน tenant เดิม: ตัวกรองเกินกำหนดแสดง 1 จาก 4 งาน, เปิด Review employment contract เข้ารายละเอียดงาน, เปิดเรื่องรับเข้าสมมติถูกเรื่อง, keyboard สลับแท็บสำเร็จ
- ตรวจภาพ 823/1440px และมือถือ 390/320px; DOM ยืนยันไม่มี horizontal overflow ที่ 390/320px; ตรวจอังกฤษและคืนภาษาไทย
- Web tests 53 ผ่าน, typecheck ผ่าน, production build แยก `.next-verify` ผ่าน 58/58 หน้า; หลังปรับลำดับ grid มือถือ ตรวจ typecheck และภาพ desktop ซ้ำสำเร็จ
- รอบนี้เป็นการยืนยัน Dashboard และทางเปิดงานที่เปลี่ยน ไม่ใช่ E2E ใหม่ครบทุกหน้าหรือทุกบทบาท

## รวมจัดทำใบเบิกและ export

- หน้า expenses เหลือปุ่มจัดทำใบเบิกจุดเดียวที่หัวหน้า เลือกร่างหรือประวัติที่ส่งแล้วเพื่อจัดเอกสารได้; กรองข้อมูลแล้วตัด selection ที่ไม่อยู่ในรายการใหม่
- หน้าตรวจใบเบิกดาวน์โหลด ZIP เดียว มีใบเบิก.html สำหรับพิมพ์/Save as PDF, CSV และไฟล์แนบต้นฉบับในโฟลเดอร์ใบเสร็จ; ไม่รวมไฟล์แนบทั้งหมดเป็น PDF เดียว
- ใช้รายชื่อผู้เบิกจริง ไม่ใช้ชื่อ Owner ที่เป็นผู้กด export; แสดงสถานะในเอกสาร และซ่อนส่งอนุมัติเมื่อมีรายการที่ไม่ใช่ DRAFT
- ดึงไฟล์แนบผ่าน endpoint ตรวจสิทธิ์เดิม หากไฟล์ใดล้มเหลวไม่ส่งออกชุดขาด; ชื่อไฟล์ใช้ ID เต็มเป็น prefix ป้องกันชนกัน และ escape HTML/CSV formula
- Browser ยืนยันเลือกประวัติ 3 รายการ → ใบเบิกยอด 2,650 บาท ไม่มีปุ่มส่งอนุมัติซ้ำ; กด download ไม่พบ error ในหน้า/console แต่ in-app browser ไม่รายงาน download event จึงไม่ได้ยืนยันไฟล์ที่บันทึกผ่าน browser
- ทดสอบเนื้อหา ZIP ด้วยไฟล์สมมติ: มี HTML/CSV/attachment และ bytes ของไฟล์แนบตรงต้นฉบับ; missing-file block/HTML escaping ผ่าน; web tests 58 ผ่าน, typecheck ผ่าน
