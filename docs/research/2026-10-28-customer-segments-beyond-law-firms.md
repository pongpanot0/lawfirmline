# Samnuan: กลุ่มลูกค้านอกเหนือจากสำนักงานกฎหมาย — การวิจัยแนวทางปฏิบัติที่ดี
วันที่ 28 ต.ค. 2569 · คำถามเจ้าของ: ถ้าไม่ขายเฉพาะทนาย/สำนักงานกฎหมาย จะขายให้ใครได้บ้าง

## สรุปสำหรับตัดสินใจ (TL;DR)
- **ควรไล่ตามก่อน: หน่วยทวงหนี้/ฟ้องคดีของธนาคาร ลิสซิ่ง บัตรเครดิต บริษัท AMC และบริษัทติดตามหนี้** เพราะปริมาณคดีเป็นชุด (batch) และมีแรงกดดันเชิงนโยบายจาก ธปท. ตัวเลขยังเป็นการประมาณ ต้องยืนยันเพิ่ม
- **อันดับ 2: ฝ่ายกฎหมายภายในบริษัท (in-house / นิติกร)** เหมาะกับแพ็กเกจ Team/Firm เดิม ใช้ฟีเจอร์คดี นัดศาล งาน เอกสาร และค่าใช้จ่ายได้เกือบทั้งหมด
- **อันดับ 3: บริษัทประกันภัย (งานเรียกร้อง/ไล่เบี้ย/สินค้าขนส่ง)** มีโมเดล `CargoClaim` อยู่แล้ว (`apps/api/prisma/schema.prisma:1576`) จึงเป็นทางต่อยอดที่ถูกที่สุด
- **อัยการและตำรวจสอบสวนเป็นกลุ่มที่ไม่เหมาะในระยะนี้**: ระบบงานสำนวนเป็นของรัฐ จัดซื้อผ่าน e-GP ใช้เวลานาน และร่างแนวทาง Cloud First กำหนดให้ข้อมูลรัฐอยู่ในประเทศไทย ตอนนี้ยังไม่มีข้อมูลยืนยันว่า Samnuan ตอบข้อกำหนดนี้ได้
- **กฎ Apple 3.1.3(c)** อนุญาตให้ขายนอก IAP ได้เฉพาะเมื่อผู้ซื้อเป็นองค์กรหรือกลุ่ม ทุกกลุ่มในรายงานนี้ผ่านเงื่อนไขนี้ได้ถ้าซื้อในนามองค์กร แต่ผู้ใช้รายบุคคลที่ซื้อเองต้องผ่าน IAP (รายละเอียดในหัวข้อสุดท้าย)

## ส่วนที่ 1: แนวทางปฏิบัติที่ดีของอุตสาหกรรม (ภาพรวม)

### UX / flow
- ระบบจัดการคดีของ in-house และของ AMC มักเน้น **มุมมองพอร์ต** (ดูทุกคดีตามเจ้าหนี้ สถานะ วันที่ครบกำหนด) มากกว่ามุมมองรายคดีแบบทนาย ดูตัวอย่างการจัดการ NPL ของ BAM ได้ที่ [BAM business performance](https://investor.bam.co.th/en/financial-info/business-performance) (ข้อมูลเชิงธุรกิจ ไม่ใช่ UX โดยตรง)
- การนำเข้าข้อมูลเป็นชุด (import ไฟล์ Excel หรือ feed) เป็นความต้องการหลักของกลุ่มเจ้าหนี้ เพราะต้องรับคดีหลักพันต่อเดือน

### Technical / architecture
- การนำเข้าข้อมูลจำนวนมากควรมีการตรวจสอบรายแถว แสดงข้อผิดพลาด และทำซ้ำได้ (idempotent) ตามแนวทางทั่วไปของ import pipeline (ยังไม่ได้ตรวจแหล่งอ้างอิงเฉพาะ ระบุเป็น *unverified*)
- การเชื่อมระบบเจ้าหนี้ผ่าน API หรือ SFTP ต้องมี audit log และการแยกข้อมูลระหว่างเจ้าหนี้ (multi-tenant ในระดับลูกค้าของลูกค้า) — *unverified*

### API design
- ถ้าจะให้ธนาคารหรือ AMC ส่งคดีเข้ามา ควรออกแบบ endpoint แบบ batch พร้อมผลลัพธ์รายรายการ (ไม่ใช่ fail ทั้งชุด) ซึ่งเป็นรูปแบบที่ระบบ API ทางการเงินทั่วไปใช้ — *unverified* ยังไม่ได้เทียบกับ Stripe หรือ Shopify โดยตรงในรอบนี้

### Business rules / compliance
- **พ.ร.บ.การทวงถามหนี้ พ.ศ. 2558**: บังคับใช้กับการทวงหนี้จากลูกหนี้ที่เป็นบุคคลธรรมดา ไม่ครอบคลุมลูกหนี้ที่เป็นนิติบุคคล ผู้ทวงหนี้ต้องจดทะเบียน และห้ามทำให้ลูกหนี้เข้าใจผิดว่าเป็นการกระทำของศาลหรือทนาย ดู [Tilleke & Gibbins](https://www.tilleke.com/insights/thailands-new-debt-collection-law-provides-measure-protection) และ [Bangkok Post](https://www.bangkokpost.com/business/general/454143/debt-collection-law-to-take-effect-soon)
- **หน่วยงานกำกับยังไม่ชัด**: แหล่งข้อมูลขัดกันว่ากระทรวงการคลัง มหาดไทย หรือสภาทนายความ ต้องตรวจราชกิจจานุเบกษาก่อนตัดสินใจ — [Luther practice note](https://www.luther-lawfirm.com/fileadmin/user_upload/Practice_Note_Debt_Collection_in_Thailand.pdf)
- **PDPA**: ผู้ควบคุมข้อมูลต้องแจ้งเหตุละเมิดต่อ PDPC ภายใน 72 ชั่วโมง ต้องมีสัญญากับผู้ประมวลผล และต้องบันทึกกิจกรรมการประมวลผล ดู [OneTrust](https://www.onetrust.com/blog/the-ultimate-guide-to-thai-pdpa-compliance) ส่วนข้อกำหนด DPO สำหรับหน่วยงานรัฐ ยังไม่ได้ตรวจกับตัวบทจริง (*unverified*)
- **การจัดการงานของรัฐ**: ร่างแนวทาง Cloud First กำหนดให้ข้อมูลภาครัฐเก็บในประเทศไทย และให้ผู้ให้บริการที่ไม่แสดงความสอดคล้องถูกตัดออกจากการจัดซื้อ ดู [Tilleke & Gibbins (draft)](https://www.tilleke.com/insights/thailand-releases-draft-guidelines-on-government-cloud-adoption-and-data-classification/) ยังไม่พบยืนยันว่าเป็นฉบับสุดท้าย
- **e-GP**: รายงานข่าวระบุว่าการยื่นข้อเสนอและอุทธรณ์ต้องผ่าน e-GP เท่านั้นตั้งแต่ 1 ต.ค. 2569 — [ฐานเศรษฐกิจ](https://www.thansettakij.com/economy/669263) (ยังไม่ได้เปิดหน้าต้นทางตรวจซ้ำ)

## ส่วนที่ 2: การประเมินแต่ละกลุ่ม

> ตัวเลขทั้งหมดในส่วนนี้ที่ไม่มีแหล่งที่เป็นทางการ ถือเป็น **ประมาณการ (estimate)** หรือ **unverified**

### 2.1 อัยการ (สำนักงานอัยการสูงสุด)
- **ขนาด**: ไม่พบจำนวนอัยการทั้งประเทศจากแหล่งทางการในการค้นรอบนี้ (*unverified*) ต้องดึงจากรายงานประจำปีของ สนง.อัยการสูงสุด
- **ความเจ็บปวด**: ปริมาณสำนวนสูง งานเอกสารและการติดตามสำนวนหลายขั้น
- **ความเหมาะสมกับ Samnuan**: ต่ำ โครงสร้างงานเป็นฝั่งรัฐ ไม่ใช่ฝั่งที่ยื่นคดีเอง ฟีเจอร์คดีแบบทนาย (`partyRole`, `Client`, ค่าธรรมเนียม) ไม่ตรงกับบทบาท อัยการเป็นโจทก์ในนามรัฐ
- **ช่องว่าง**: โมเดลสำนวนตามกระบวนการสอบสวนและสั่งคดี, การเชื่อมระบบเดิม, การจัดชั้นความลับของข้อมูล
- **ระบบเดิม**: พบเพียงงานวิจัยที่อ้างถึง "สารบบคดีอิเล็กทรอนิกส์" ของ สนง.อัยการ ไม่พบเอกสารทางการเกี่ยวกับชื่อหรือสถานะระบบ (*unverified*) ดู [ศึกษา ม.ราม (ตัวอย่างจังหวัดปราจีนบุรี)](https://islocal.ru.ac.th/images/is_pdf/is_61/6114880017.pdf)
- **การจัดซื้อ**: ระเบียบจัดซื้อภาครัฐ, e-GP, งบประมาณรายปี, และข้อกำหนดด้านความปลอดภัยข้อมูล
- **ความเต็มใจจ่าย/ความสามารถ**: งบจัดซื้อมีแต่ใช้เวลานาน ราคาต่อหน่วยอาจสูงแต่ยอดยืนยันยาก
- **ความเสี่ยง**: จัดซื้อยาว, ต้องผ่านเกณฑ์ความปลอดภัย, ข้อมูลคดีอาญาอาจจัดชั้นสูง
- **คำแนะนำ**: **ไม่ควรไล่ตามในปี 2570**

### 2.2 พนักงานสอบสวน (ตำรวจฝ่ายสำนวน)
- **ขนาด**: Wikipedia ระบุประมาณ 8,000 นายพนักงานสอบสวน และกำลังพลรวมราว 230,000 นาย แต่ไม่มีปีที่ชัดเจน (*unverified*) [Wikipedia: Royal Thai Police](https://en.wikipedia.org/wiki/Royal_Thai_Police) ต้องยืนยันกับ สตช. โดยตรง
- **ความเจ็บปวด**: ปริมาณสำนวนมาก (สตช. รายงานการจับกุม/คลี่คลายคดีราว 500,000 คดีในปี 2567) [Khaosod English](https://www.khaosodenglish.com/news/2024/12/31/thai-police-solve-93-of-more-than-500000-cases-in-2024/)
- **ความเหมาะสม**: ต่ำมาก ตำรวจมีระบบงานสำนวนของตัวเองและต้องใช้กับข้อมูลคดีอาญา ไม่ใช่งานของทนาย ไม่พบชื่อระบบ CRIMES ของไทยในการค้นรอบนี้ (ผลค้นเจอแต่ CRIMES ของสหรัฐฯ จึงไม่นำมาใช้)
- **ช่องว่าง**: การรับสำนวนจากตำรวจ, ความลับระดับสูง, ระบบจัดเก็บในประเทศ
- **การจัดซื้อ/ความเต็มใจจ่าย**: เหมือนอัยการ
- **คำแนะนำ**: **ไม่ควรไล่ตามในระยะนี้** ถ้าสนใจควรเริ่มจากการมองว่าพนักงานสอบสวนเป็น "ผู้ใช้" ไม่ใช่ "ผู้ซื้อ" ที่ต้องผ่านเจ้าหน้าที่จัดซื้อ

### 2.3 หน่วยทวงหนี้/ฟ้องคดีของธนาคาร ลิสซิ่ง บัตรเครดิต และ AMC (แนะนำอันดับ 1)
- **ขนาด**: NPL ในระบบประมาณ 1 ล้านล้านบาท (ตัวเลขจากบล็อกผู้ให้บริการซึ่งอ้างอิง SET ประมาณการ) ผู้ประกอบการ AMC ประมาณ 86-90 ราย แต่ราว 50% ทำงานอยู่ (ตัวเลขขัดกันระหว่างแหล่ง) [TBN](https://tbn.co.th/amc-capacity-crisis-thailand-npl/) [Bloomberg](https://www.bloomberg.com/news/articles/2025-10-28/thai-central-bank-chief-wants-bad-debt-purchases-doubled) ค.ศ. 2025: ธปท. ต้องการให้ AMC ซื้อหนี้เสียเพิ่มเป็นสองเท่า
- **นโยบายขับเคลื่อน**: ครม. อนุมัติโครงการเคลียร์หนี้เสียกว่า 2.3 ล้านบัญชี ผ่าน AMC ตั้งแต่ ธ.ค. 2568 [Nation Thailand](https://www.nationthailand.com/news/policy/40059578) ซึ่งทำให้ปริมาณคดีเพิ่มขึ้นในระยะสั้นถึงกลาง (*ประมาณการ*)
- **ความเจ็บปวด**: คดีเป็นชุดจำนวนมาก, กำหนดเวลาฟ้องและอายุความ, ติดตามผลและค่าธรรมเนียมศาลรายคดี, ต้องรายงานต่อเจ้าหนี้และ ธปท.
- **ความเหมาะสมกับ Samnuan**: **สูง** ใช้ได้กับ `Case`, `DeadlineRule`, `EmailThread`, `DataImportBatch`, `Client` (เจ้าหนี้) และมุมมองรายงานที่มีอยู่
- **ช่องว่าง**: นำเข้าคดีเป็นชุดขนาดใหญ่ (หลักพันถึงหลักหมื่น), มุมมองพอร์ตตามเจ้าหนี้, รายงานให้เจ้าหนี้, เชื่อมระบบธนาคารด้วย API/SFTP, แยกข้อมูลระหว่างเจ้าหนี้, ข้อจำกัด `PLAN_LIMIT_CASES` และแพ็กเกจราคาต่อคดี (Free 15 คดี; แพ็กเกจที่ขายได้ Team 499/3 ผู้ใช้, Firm 1,290/10, Professional 2,990/20 ที่ `packages/shared/src/index.ts:199`)
- **การจัดซื้อ**: เอกชนตัดสินใจเอง รอบ 1–3 เดือน ต้องผ่านฝ่ายกำกับ/ความปลอดภัยข้อมูล
- **ความเต็มใจจ่าย**: สูงถ้าเทียบกับต้นทุนค่าทนายจ้างนอก ควรตั้งราคาตามจำนวนคดีที่ active หรือตามปริมาณ (*ประมาณการ*)
- **ช่องทางขาย**: ขายตรงระดับฝ่ายกฎหมาย/ฝ่ายคดีของ AMC และ leasing; ผ่านผู้ให้บริการด้านการทวงหนี้
- **ความเสี่ยง**: ชื่อเสียงด้านการทวงหนี้ที่ไม่เป็นธรรม, ความเข้าใจผิดว่า Samnuan เป็นผู้ทวงหนี้เอง (ต้องวางตำแหน่งเป็นซอฟต์แวร์ไม่ใช่บริการทวงหนี้), ข้อมูลทางการเงิน PDPA
- **คำแนะนำ**: **ไล่ตามอันดับ 1** แต่เริ่มจากฝ่ายคดีของ AMC/ลิสซิ่งขนาดกลาง

### 2.4 ฝ่ายกฎหมายภายในบริษัท (in-house / นิติกร เอกชน) (แนะนำอันดับ 2)
- **ขนาด**: ไม่พบจำนวนนิติกรเอกชนทั้งประเทศในการค้นรอบนี้ (*unverified*)
- **ความเจ็บปวด**: คดีทั้งในศาลและนอกศาล (ทวงหนี้ สัญญา แรงงาน), ต้องแจ้งผู้บริหาร, ต้องเช็คค่าใช้จ่ายและงบกฎหมาย
- **ความเหมาะสม**: สูง ฟีเจอร์ที่มีอยู่เกือบทั้งหมดใช้ได้: คดี, นัดศาล, งาน, เอกสาร, ค่าใช้จ่าย (`ExpenseClaim`), ใบแจ้งหนี้, ตรวจสอบความขัดแย้ง (`ConflictCheck`)
- **ช่องว่าง**: มุมมองระดับบริษัท (หลายแผนก), งบประมาณกฎหมายรายปี, การจัดการสัญญา (ไม่มีในปัจจุบัน — *ต้องตรวจเพิ่ม*)
- **การจัดซื้อ**: บริษัทเอกชนตัดสินใจเอง รอบ 2–6 สัปดาห์ (*ประมาณการ*)
- **ความเต็มใจจ่าย**: ปานกลาง มักเทียบกับค่า SaaS ทั่วไป ราคาแพ็กเกจ Team/Firm น่าจะเหมาะ
- **ช่องทางขาย**: ตรงจากผู้ใช้ผ่าน trial แล้วขยายไปยังผู้ซื้อ, ผ่านสมาคมนิติกร
- **ความเสี่ยง**: ทีมภายในมักใช้ระบบของบริษัทแม่อยู่แล้ว ต้องดูเรื่อง SSO และการเชื่อมกับระบบ ERP
- **คำแนะนำ**: **ขยายจากแพ็กเกจเดิม** โดยเพิ่มมุมมองระดับบริษัท

### 2.5 บริษัทประกันภัย (งานเรียกร้อง / ไล่เบี้ย / สินค้าขนส่ง) (แนะนำอันดับ 3)
- **ขนาด**: ไม่พบจำนวนบริษัทหรือตัวเลขงานไล่เบี้ยในรอบนี้ (*unverified*)
- **ความเจ็บปวด**: งานไล่เบี้ย (subrogation) เป็นชุดตามอุบัติเหตุหรือความเสียหายสินค้า ต้องติดตามอายุความและค่าเสียหาย
- **ความเหมาะสม**: สูงในระดับ "งานสินค้าขนส่ง" เพราะ `CargoClaim` มีฟิลด์ผู้ขนส่ง ผู้รับ ค่าเสียหาย สกุลเงิน และกฎหมายที่ใช้ (`apps/api/prisma/schema.prisma:1576`) ส่วนงานไล่เบี้ยทั่วไปต้องเพิ่มโมเดล
- **ช่องว่าง**: การส่งงานเข้าจากระบบของบริษัทประกัน, รายงานอายุความ, มุมมองตามบริษัทรับประกัน
- **การจัดซื้อ**: ตัดสินใจโดยฝ่ายกฎหมายหรือฝ่ายเคลม รอบ 1–3 เดือน
- **ความเต็มใจจ่าย**: ปานกลางถึงสูง ถ้าชนะคดีแล้วได้ค่าเสียหายคืนมาก
- **ความเสี่ยง**: กฎ คปภ. และข้อมูลสุขภาพ/ประกันชีวิต (PDPA) ต้องตรวจก่อน

### 2.6 บริษัทติดตามหนี้ (debt collection agencies)
- **ขนาด**: ไม่พบตัวเลขที่ยืนยันได้ (*unverified*)
- **ความเหมาะสม**: ปานกลาง ความต้องการคล้ายกับ AMC แต่ปริมาณเล็กกว่าและมีจำนวนผู้เล่นมาก
- **ความเสี่ยง**: อยู่ในขอบเขตของ พ.ร.บ.ทวงหนี้ตรง ๆ และมักถูกตรวจสอบ การขายให้กลุ่มนี้อาจทำให้ Samnuan ถูกมองว่าเกี่ยวข้องกับการทวงหนี้ที่ไม่เป็นธรรม
- **คำแนะนำ**: เก็บไว้เป็นลำดับรอง ใช้เป็นแหล่งรายได้ผ่านการขายต่อ AMC

### 2.7 นิติบุคคลอาคารชุด / บริษัทผู้จัดการนิติบุคคล (คดีค่าส่วนกลางเป็นชุด)
- **ขนาด**: ไม่พบจำนวนนิติบุคคลอาคารชุดทั้งประเทศ ตัวเลขที่พบเป็นของจำนวนห้องที่นิติบุคคลถือครอง 244,115 ห้อง (ข่าว Bangkok Biznews ก.ย. 2569 ไม่ชัดว่าเป็นตัวเลขทั้งประเทศหรือไม่) [Bangkok Biznews](https://www.bangkokbiznews.com/economics/1250794) ต้องยืนยันก่อนใช้
- **ความเจ็บปวด**: คดีค่าส่วนกลางค้างชำระเป็นชุด, ต้องมีมติที่ประชุมใหญ่ก่อนฟ้อง
- **ความเหมาะสม**: ปานกลาง ความต้องการใกล้กับคดีทวงหนี้เป็นชุด แต่ขนาดแต่ละลูกค้าเล็ก
- **ช่องว่าง**: ราคาต่ำ/ลูกค้าเยอะ จำเป็นต้องมีแพ็กเกจต่ำ และขั้นตอนการตั้งค่าที่ง่ายกว่าเดิม
- **การจัดซื้อ**: ผู้จัดการนิติบุคคลตัดสินใจ รอบสั้น แต่ผู้มีอำนาจอนุมัติคือคณะกรรมการ
- **ความเต็มใจจ่าย**: ต่ำถึงปานกลาง
- **คำแนะนำ**: เป็นช่องทางขายผ่านบริษัทผู้จัดการ (channel) มากกว่าเป็นกลุ่มหลัก

### 2.8 หน่วยงานรัฐ (นิติกรกระทรวง/องค์กรปกครองส่วนท้องถิ่น) และหน่วยบังคับคดี
- **ขนาด**: ไม่พบตัวเลขนิติกรรัฐทั้งประเทศ (*unverified*) กรมบังคับคดีมีชุดสถิติคดีเข้ากระบวนการบังคับคดีบนศูนย์ข้อมูลเปิด แต่ไม่พบจำนวนเจ้าพนักงานบังคับคดี (*unverified*)
- **ความเหมาะสม**: ต่ำ หน่วยงานรัฐมักมีระบบของตัวเองตามกฎ จัดซื้อผ่าน e-GP ใช้เวลานาน และติดกับ Cloud First
- **คำแนะนำ**: ไม่ควรไล่ตามในระยะนี้ ยกเว้นต่อมาเป็นโครงการที่มีงบชัดเจน

### 2.9 ผู้ประกอบการบังคับคดีภาคเอกชน
- **ความเหมาะสม**: ส่วนใหญ่เป็นสำนักงานทนายความ จึงตรงกับกลุ่มเดิมของ Samnuan อยู่แล้ว (ไม่ใช่กลุ่มใหม่)
- **คำแนะนำ**: ไม่แยกเป็นกลุ่มใหม่

### 2.10 องค์กรช่วยเหลือทางกฎหมาย (สภาทนายความ, NGO) และคลินิกกฎหมายของมหาวิทยาลัย
- **ขนาด**: ไม่พบตัวเลขในรอบนี้ (*unverified*)
- **ความเหมาะสม**: สูงทางสังคม ต่ำทางรายได้ งบมักมาจากทุนหรือโครงการ
- **ความเจ็บปวด**: งานมาก คนน้อย, อาสาสมัครเปลี่ยนบ่อย
- **Apple**: องค์กรไม่แสวงหากำไรซื้อได้ในลักษณะองค์กร แต่ราคาต้องตรงกับงบจริง
- **คำแนะนำ**: ใช้เป็นช่องทางสร้างชื่อ/ทดลองระบบ (pro bono หรือ NGO plan) ไม่ควรเป็นแหล่งรายได้หลัก
- **คลินิกมหาวิทยาลัย**: เป็นกลุ่มเล็ก เหมาะกับการใช้ในการเรียนการสอน ไม่ใช่รายได้

## ส่วนที่ 4: ลำดับแนะนำ

1. **หน่วยทวงหนี้/ฟ้องคดีของ AMC และลิสซิ่ง**: ขนาดคดีสูง, นโยบาย 2.3 ล้านบัญชีผลักดัน; **ต้องทำ**: นำเข้าเป็นชุด, มุมมองพอร์ตตามเจ้าหนี้, รายงาน, แพ็กเกจราคาตามคดีที่ active; **ระวัง**: ภาพลักษณ์การทวงหนี้และ PDPA
2. **ฝ่ายกฎหมายภายในบริษัท**: ใช้ฟีเจอร์เดิมได้มาก; **ต้องทำ**: มุมมองระดับบริษัท หลายแผนก, งบกฎหมาย, SSO
3. **ประกัน (งานสินค้าขนส่ง/ไล่เบี้ย)**: มี `CargoClaim` อยู่แล้ว; **ต้องทำ**: โมเดลไล่เบี้ย, อายุความ, การรับงานจากระบบประกัน

ไม่แนะนำในระยะนี้: อัยการ, ตำรวจ, หน่วยงานรัฐ (เพราะ e-GP, Cloud First และระบบเดิม) ตัดนิติบุคคลอาคารชุดออกจากกลุ่มหลัก ให้เป็นช่องทางขายผ่านบริษัทผู้จัดการ

## ส่วนที่ 5: หมายเหตุ Apple 3.1.3(c) รายกลุ่ม

กฎ 3.1.3(c) ระบุว่า "ถ้าแอปขายโดยคุณเองให้กับองค์กรหรือกลุ่มสำหรับพนักงานหรือนักเรียนเท่านั้น" การขายนอก IAP ทำได้ และ "การขายให้ผู้บริโภค ผู้ใช้รายเดียว หรือครอบครัว ต้องใช้ IAP" ([Apple App Review Guidelines](https://developer.apple.com/app-store/review/guidelines/))

| กลุ่ม | ผู้ซื้อคือ | สถานะ |
|---|---|---|
| อัยการ/ตำรวจ/หน่วยงานรัฐ | หน่วยงาน (องค์กร) | ผ่านเกณฑ์ตามตัวบท แต่ไม่มีกรณีตัวอย่างยืนยันจากหน่วยงานรัฐ |
| ทวงหนี้/AMC/ลิสซิ่ง | บริษัท | ผ่านเกณฑ์ |
| in-house | บริษัท | ผ่านเกณฑ์ ถ้านิติกรไม่ซื้อเองเป็นรายบุคคล |
| ประกัน | บริษัท | ผ่านเกณฑ์ |
| นิติบุคคลอาคารชุด | นิติบุคคล (องค์กร) | ผ่านเกณฑ์ ถ้าเป็นการซื้อในนามนิติบุคคล |
| องค์กรช่วยเหลือกฎหมาย/NGO | องค์กร | ผ่านเกณฑ์ |
| ทนายคนเดียว/ผู้ซื้อรายบุคคล | บุคคล | **ต้องผ่าน IAP** |

ข้อควรระวัง:
- ตัวบท 3.1.3(c) ไม่ได้พูดถึงแอปที่ขายทั้งแบบองค์กรนอก IAP และรายบุคคลผ่าน IAP พร้อมกัน ฟอรัมนักพัฒนามีคำถามเรื่องนี้แต่ยังไม่มีคำตอบทางการ (ดู [Apple Developer Forums 773357](https://developer.apple.com/forums/thread/773357)) ควรถาม App Review ก่อน
- ฟอรัมยังรายงานว่ามีแอปถูกปฏิเสธภายใต้ 3.1.1 และ 3.1.3(c) ทั้งที่ไม่มี IAP ในแอป ดังนั้นต้องเตรียมเอกสารแสดงว่าการซื้อเป็นการซื้อขององค์กร
- 3.1.3(d) ไม่เกี่ยวกับกลุ่มเหล่านี้ เพราะไม่ใช่บริการระหว่างบุคคลแบบเรียลไทม์
