# Samnuan: ลำดับพัฒนาผลิตภัณฑ์จากงานจริง

วันที่: 12 กันยายน 2026
สถานะ: ข้อเสนอผลิตภัณฑ์ ยังไม่ใช่รายการที่พัฒนาเสร็จหรือกำหนดส่งมอบ

## จุดยืน

Samnuan ควรเป็นระบบที่ทำให้สำนักงานรู้ว่าแต่ละคดีอยู่ตรงไหน ใครต้องทำอะไรต่อ และมีอะไรเสี่ยงหลุด โดยเฉพาะการทำงานวันไปศาล ทนายเป็นผู้ตัดสินใจ ระบบช่วยเตรียมและติดตาม ลูกความเห็นเฉพาะสิ่งที่สำนักงานเลือกเผยแพร่

ข้อเสนอนี้ใช้ผล E2E รอบก่อนร่วมกับการอ่าน source เฉพาะส่วน ไม่ใช่ audit ทุกโมดูล การไม่พบ implementation ในการค้นหาไม่ได้ยืนยันว่าไม่มีทั้งระบบ

## ฐานที่ตรวจพบใน source ปัจจุบัน

- My Day มีหน้าและ MyDayPanel; ควรต่อยอดหน้าเดิม
- RecordHearingOutcomeDialog รวมผลนัด นัดถัดไป งาน และร่างค่าใช้จ่าย พร้อมแสดงผลบันทึกแยกรายการอยู่แล้ว
- DeadlineRulesService มีกฎและข้อเสนอกำหนดเวลาให้ผู้ใช้ยืนยัน ไม่ควรสร้างเครื่องคำนวณซ้ำ หรือถือค่าเริ่มต้นเป็นข้อยืนยันทางกฎหมาย
- ClientPortalService จำกัดเอกสารตาม publication และมี PublishDocumentDialog เลือกผู้รับ
- ClosingEmailService มีการสร้าง แก้ไข และอนุมัติร่าง
- OperationsService มีข้อมูลภาระงานและกำหนดใกล้ถึง
- การค้นหา source รอบนี้ยังไม่พบกลไก offline ของแฟ้มศาลที่ยืนยันการดาวน์โหลดและซิงก์ครบวงจร

## ลำดับที่แนะนำ

| ลำดับ | สิ่งที่เพิ่มหรือต่อยอด | ผู้ใช้ได้รับอะไร | หลักฐานก่อนถือว่าเสร็จ |
| --- | --- | --- | --- |
| 1 | ศูนย์งานที่ต้องลงมือทำใน My Day | เห็นงานเสี่ยง งานรอรับผิดชอบ รอเอกสาร รออนุมัติ และงานหลังศาลค้าง พร้อมปุ่มจัดการ | ข้อมูลเดียวไม่สร้าง task ซ้ำ; ทุกแถวบอกเหตุผล ผู้รับผิดชอบ กำหนดและทางแก้; ทดสอบเลื่อนนัด/เปลี่ยนผู้รับผิดชอบ/ปิดคดี |
| 2 | แฟ้มไปศาลบนมือถือ | ก่อนศาลมี checklist และเอกสารฉบับที่เตรียมไว้; ที่ศาลเปิด brief/ไฟล์/จดบันทึก; หลังศาลต่อ dialog เดิม | เปิดเอกสารได้เมื่อปิดเครือข่าย; draft ไม่หายหลังปิดแอป; retry ไม่สร้างนัด/ค่าใช้จ่ายซ้ำ; แสดง sync failed/conflict จริง |
| 3 | การติดตามกำหนดจนมีคนรับผิดชอบ | ต่อจากกฎเดิมเป็นขั้นตอน ยืนยันวัน → รับงาน → เตือน → ส่งต่อผู้ดูแลเมื่อไม่มีการตอบรับ | แสดงวันตั้งต้นและที่มาของกฎ; เปลี่ยนวันแล้วแสดงผลกระทบให้ทนายยืนยัน; บันทึกผู้แก้และเหตุผล; แยกส่งแจ้งเตือนออกจากรับทราบ |
| 4 | ห้องงานลูกความใน Portal | ขอ/ส่งเอกสาร ตอบคำถาม เห็นสิ่งที่สำนักงานกำลังรอ และติดตามการส่งงานได้ | ส่งงานไม่เท่ากับสำนักงานรับว่าจ้าง; แยกวันที่ลูกค้าขอกับวันตกลง; contact ใหม่เห็นประวัติตามสิทธิ์; draft ภายในไม่รั่ว |
| 5 | ชุดขั้นตอนมาตรฐานตามประเภทงาน | เลือกงานแล้วได้ checklist เอกสาร ผู้รับผิดชอบ จุดอนุมัติ และแม่แบบที่เกี่ยวข้อง | เริ่มจากประเภทงานจริงหนึ่งประเภท; มี version; แก้ template ไม่เปลี่ยนคดีเก่าเงียบ ๆ; รันซ้ำไม่สร้างงานซ้ำ; medical/transport แยก flow |
| 6 | AI ที่อ้างกลับถึงหลักฐานได้ | สรุปคดี ลำดับเหตุการณ์ และร่างอัปเดตลูกความจากเอกสารที่มี | ทุกข้อเท็จจริงเปิดกลับถึงเอกสาร/หน้า/เวอร์ชันได้; แสดงข้อมูลขัดกันหรือขาด; ทนายแก้และอนุมัติก่อนส่ง; ประเมินชุดภาษาไทยและสิทธิ์ข้ามสำนักงาน |
| 7 | เริ่มใช้งานและย้ายข้อมูลอย่างมั่นใจ | สำนักงานใหม่เชิญทีม ตั้งสิทธิ์ นำเข้าลูกค้า/คดี และมีงานแรกที่ใช้ได้ | preview ก่อน import; แสดงแถวผิด/ข้อมูลซ้ำ; ย้อนกลับเฉพาะชุดนำเข้าได้; เห็นผลสำเร็จจริง ไม่ใช่ checklist ที่ติ๊กเอง |

## ชุดแรกที่ควรลงมือ

ทำเส้นทางเดียวให้ครบ: **นัดศาลพรุ่งนี้ → ตรวจความพร้อม → เปิดแฟ้ม → บันทึกผล → ยืนยันงานต่อ → เตรียมร่างแจ้งลูกความ**

เริ่มจากออนไลน์ ใช้ My Day และ dialog ผลนัดเดิม เชื่อม checklist เอกสารที่ต้องใช้และร่างติดตามให้ครบ ก่อนเพิ่ม offline ที่ต้องทดสอบข้อมูลสูญหายและ conflict อย่างจริงจัง ไม่ติดป้ายพร้อม offline จนเปิดไฟล์โดยไม่มีเครือข่ายผ่านแล้ว

เกณฑ์รับงานของช่วงแรก:

1. เปิดจาก My Day แล้วทราบคดี ศาล เวลา ผู้รับผิดชอบ เอกสารขาด และงานเตรียมที่ยังไม่เสร็จ
2. งานที่มีอยู่เชื่อมเข้ากับนัดได้โดยไม่ต้องคัดลอก
3. หลังศาลบันทึกผลและเลือกรายการต่อเนื่องได้ใน flow เดิม; ส่วนที่สำเร็จ/ล้มเหลวแสดงแยกและกู้คืนได้
4. ร่างอัปเดตลูกความมีข้อมูลตั้งต้นชัดเจนและต้องผ่านผู้ตรวจ; การบันทึกผลนัดไม่ส่งข้อความออกเอง
5. ตรวจมือถือ 375px, keyboard, ข้อความยาว, โหลดช้า, หลุดเครือข่าย, double submit และสิทธิ์ต่างบทบาท

## มาตรฐานการออกแบบและการวัด

คงสี ฟอนต์ และความเรียบของ Samnuan ใช้หน้าเดิมก่อนเพิ่มเมนู แสดงรายการที่ต้องตัดสินใจก่อนตัวเลขรวม ให้แต่ละรายการมี action หลักเดียวพร้อมเหตุผล ปุ่มมือถือกดได้จริง สถานะ loading/empty/error/saved ต้องชัดเจนและไม่ทำข้อมูลที่กรอกหาย

เก็บ baseline ก่อนกำหนดเป้าหมายเชิงตัวเลข: เวลาตั้งสำนักงานจนสร้างคดีแรก, สัดส่วนนัดที่เตรียมเอกสารครบ, งานหลังศาลที่ตกค้าง, เวลาตั้งแต่ลูกค้าส่งเอกสารจนเจ้าหน้าที่รับเรื่อง, ความสำเร็จของ sync และจำนวนข้อมูลซ้ำ ไม่ใช้จำนวนฟีเจอร์หรือจำนวนเทสต์เป็นตัวแทนคุณภาพงานของผู้ใช้

พื้นฐานที่ต้องพัฒนาควบคู่: ทดสอบการกู้คืน backup, MFA/การยกเลิก session, ขอบเขตสิทธิ์ไฟล์และการส่งออก, audit trail ที่ตรวจตามเหตุการณ์ได้, monitoring ข้อผิดพลาดจริง รายการนี้เป็นเกณฑ์ที่ต้องตรวจเพิ่ม ไม่ใช่ข้อสรุปว่าระบบยังไม่มีทั้งหมด

## สิ่งที่ยังไม่ควรให้มาก่อน

แชต AI อเนกประสงค์เพิ่มอีกตัว, dashboard กราฟเพิ่มโดยไม่มี action, native app ก่อนพิสูจน์ mobile web, และ workflow builder ที่ตั้งค่าได้ทุกอย่าง ล้วนเพิ่มภาระก่อนพิสูจน์เส้นทางหลัก ขยายจากงานที่ใช้ซ้ำจริงภายหลัง
