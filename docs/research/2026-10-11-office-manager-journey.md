# ผู้จัดการสำนักงาน (Office Manager): role, หน้าจอ และ journey ตั้งแต่วันแรกจนพ้นสภาพ (2026-10-11)

> โจทย์: บริษัทจะรับคนมาดูแลสำนักงาน ไม่ได้ว่าความเอง ควรได้ role อะไร หน้าจอทำงานควรเป็นอย่างไร และเริ่มงานอย่างไร
> ที่มา: ลองใช้ Casefox และ Clio จริง + ไล่โค้ด LexFlow (อ้าง path จาก root ของ worktree)

## 1. คำตอบสั้น

**ตอนนี้ยังไม่มี role ที่เหมาะ** ต้องเพิ่ม role ใหม่ชื่อ `OFFICE_MANAGER`

| ถ้าให้ role ที่มีอยู่ตอนนี้ | ผลที่เกิดขึ้น |
|---|---|
| ASSISTANT (ค่าเริ่มต้นตอนเชิญ) | ทำงานกฎหมายได้เกือบเท่าทนาย: เปิด/ปิดคดี, ส่งอีเมลปิดคดี, ใช้ AI วิจัยกฎหมาย แต่ **งานสำนักงานทำไม่ได้เลย** ทั้งอนุมัติเบิก, จ่ายเงิน, ดูใบแจ้งหนี้, ตามหนี้, อนุมัติลา, เชิญคน, ดูปฏิทินทั้งสำนักงาน |
| OWNER | ทำงานสำนักงานได้ครบ แต่ **เห็นทุกคดี ลบคดีได้ เปลี่ยน role คนอื่นได้ และจัดการค่าสมาชิก SaaS ได้** ซึ่งมากเกินไป |

สองระบบที่ไปดูมาก็แยกเรื่องนี้ไว้:
- **Casefox** แยก "ระดับสิทธิ์" (Administrator / Normal Staff / Contract Staff / **Office Secretary**) ออกจาก "ตำแหน่งงาน" (Partner, Associate, Paralegal, Legal Assistant, Law Clerk และอื่น ๆ รวม 26 แบบ) และกำหนดอัตราค่าบริการรายชั่วโมงแยกรายคน
- **Clio** แยกคนเป็น Attorney กับ Non-Attorney แล้วค่อยให้ Roles (Administrator / General Access รวมถึงสิทธิ์ด้าน Billing / Accounts / Reports) ใส่เข้า Groups และบล็อกคนรายคดีได้

**ข้อเสนอ**
1. เพิ่ม `FirmRole.OFFICE_MANAGER` ได้สิทธิ์งานสำนักงานแบบเดียวกับ OWNER แต่ไม่ได้สิทธิ์งานกฎหมาย และไม่ได้สิทธิ์ระดับเจ้าของ
2. เพิ่มฟิลด์ `FirmMember.jobTitle` เป็นข้อความอิสระ แยกจากสิทธิ์แบบ Casefox เช่น "ผู้จัดการสำนักงาน" หรือ "เลขานุการ"

**วิธีทำในโค้ดแบบน้อยที่สุด**
1. เพิ่ม enum `OFFICE_MANAGER` และ helper `isOfficeAdmin(member)` (OWNER หรือ OFFICE_MANAGER) ไว้ใน `packages/shared`
2. ไล่เปลี่ยนจุดที่เช็ก `firmRole === OWNER` ประมาณ 40 จุด ให้แยกเป็น 2 กลุ่ม:
   - **งานสำนักงาน** → ใช้ `isOfficeAdmin`
   - **งานระดับเจ้าของ** (role, ลบคดี, subscription, ลบสมาชิก) → คงเป็น `OWNER`
3. กั้นเส้นทางงานกฎหมาย `@Roles(ADMIN, LAWYER)` ไม่ให้ OFFICE_MANAGER ใช้ได้ (ตอนนี้คนที่ถูกเชิญทุกคนได้ global Role = LAWYER ที่ `invitation.service.ts:148,200`)
4. ให้ `rank` ของ OFFICE_MANAGER อยู่ระดับเดียวกับ SENIOR (2) เพื่อให้มอบงานให้ทนายและผู้ช่วยได้

## 3. หน้าจอทำงานของผู้จัดการสำนักงาน

### เมนูด้านซ้าย (web)

```
🏠 หน้าแรกสำนักงาน         ← ใหม่: /office (แทน /dashboard)
📥 รับเรื่องใหม่            /intake (เห็นทั้งสำนักงาน)
📅 ปฏิทินสำนักงาน           /calendar (ทุกคน + นัดที่ไม่ผูกคดี)
✅ บอร์ดงานประจำวัน          /operations (เต็มรูปแบบ ไม่ใช่แค่ radar)
📁 คดี (สรุป)              /cases
👥 ลูกค้า                  /clients
💰 การเงิน
   ├ ใบแจ้งหนี้ & ลูกหนี้     /invoices
   ├ เบิกค่าใช้จ่าย          /admin/reimbursements
   ├ เงินสดย่อย / เงินทดรอง  /expenses
🗓️ การลา                   /leaves
👤 ทีมงาน                  /team (เชิญคนได้ แต่เปลี่ยน role ไม่ได้)
📚 SOP / แม่แบบ            /sops, /templates
⚙️ ตั้งค่าสำนักงาน          /settings
```

### หน้าแรกสำนักงาน `/office` (ใหม่)

ไม่ต้องสร้างข้อมูลใหม่ ใช้ API เดิมทั้งหมด

| การ์ด | ข้อมูล | API ที่มีอยู่แล้ว |
|---|---|---|
| รอฉันอนุมัติ | ใบเบิก, ใบลา, คำขอเงินทดรอง | claims pending, `leave pending`, cash-advance |
| เรื่องใหม่ยังไม่มีคนรับ | intake/อีเมลที่ยังไม่ได้มอบหมาย | intake list + email-intake |
| นัดศาลวันนี้/พรุ่งนี้ | ใครไป ศาลไหน เตรียมเอกสารครบไหม | calendar + court-day |
| งานเลยกำหนด/ติดขัด | แยกรายคน | operations radar / on-hold |
| ลูกหนี้ครบกำหนด | ใบที่ต้องทวงวันนี้ | `invoices/owner-worklist`, receivables |
| เงินสดย่อยคงเหลือ | ยอด + เตือนเมื่อต่ำ | petty-cash |
| ใครลา/ไม่อยู่วันนี้ | | radar |

บนมือถือใช้การ์ดชุดเดียวกันที่แท็บหน้าแรก และเปิดเมนู `owner-finance` (เฉพาะส่วนลูกหนี้) กับ `team-week` ให้ OFFICE_MANAGER เข้าได้

### ขั้น 3: งานรายสัปดาห์

- ประชุมทีมด้วย `team-week` เพื่อดูภาระงานของแต่ละคน และกระจายงานใหม่ (❌ ตอนนี้เป็นของ OWNER/SENIOR)
- ตรวจเงินสดย่อย → เติมเงิน → กระทบยอด (❌ ยังไม่มี endpoint เติมเงินและไม่มี ledger)
- ตรวจคดีที่นิ่ง/ไม่มีความเคลื่อนไหว (case-health) แล้วแจ้งทนาย (❌ เป็นของ OWNER)

### ขั้น 4: งานรายเดือน

- ปิดรอบออกบิล: ร่างใบแจ้งหนี้จากเวลา/ค่าใช้จ่าย → ส่งให้ทนายตรวจ → ส่งลูกค้า (🟡 ร่างได้ แต่ส่งไม่ได้ และยังไม่มีขั้นอนุมัติบิล)
- รายงานรายเดือนให้เจ้าของ: รายได้, ลูกหนี้, ค่าใช้จ่าย, ภาระงาน (❌)
- จ่ายคืนใบเบิกเป็นรอบ (claim batch) (❌ สิทธิ์ของ OWNER)
- อัปเดต SOP / แม่แบบเอกสาร / วันหยุด (❌ สิทธิ์ของ OWNER หรือ platform admin)

### ขั้น 5: รับพนักงานใหม่ / พนักงานลาออก

| งาน | ตอนนี้ | ต้องทำเพิ่ม |
|---|---|---|
| เชิญทนาย/ผู้ช่วยใหม่ | ❌ OWNER เท่านั้น | ให้ OFFICE_MANAGER เชิญได้ แต่ให้ role ได้ไม่เกิน LAWYER/ASSISTANT |
| คนลาออก: โอนคดี/งาน/นัดให้คนอื่น แล้วปิดบัญชี | 🟡 ลบสมาชิกได้ แต่ไม่มีหน้าโอนงาน | ทำ wizard "โอนงานก่อนปิดบัญชี": แสดงคดี/งาน/นัดค้าง → เลือกผู้รับ → ปิดบัญชี (ให้ OWNER ยืนยัน) |

### ขั้น 6: ตัวผู้จัดการสำนักงานเองลาออก

เจ้าของใช้ wizard เดียวกันโอนงานสำนักงาน (ใบเบิกรออนุมัติ, intake ที่ถืออยู่, ลูกหนี้ที่ตามอยู่ `collectionOwner`) → ปิดบัญชี → audit log บันทึกไว้

## 6. คำถามที่ต้องให้เจ้าของตัดสินใจ

1. ผู้จัดการสำนักงาน **ควรเห็นเอกสารในคดีไหม** (เช่น เพื่อจัดแฟ้ม) หรือเห็นเฉพาะคดีที่ได้รับมอบงาน
