# Customer 360 — ภาพรวมความสัมพันธ์ลูกค้า

สถานะ: พัฒนาหน้าภาพรวมและการบันทึกการติดต่อแล้ว ต้นแบบ HTML ใช้ประกอบการทบทวน UX

[เปิดต้นแบบ HTML Customer 360](customer-360-prototype/index.html)

## งานหลักของหน้า

เมื่อเปิดลูกค้าหนึ่งราย เจ้าหน้าที่ต้องตอบได้ทันทีว่า **ติดต่อใคร เรื่องไหนค้าง ใครรับผิดชอบ และต้องทำอะไรต่อ** ทุกเรื่องเป็น Case ตั้งแต่เริ่มติดต่อ โดยเริ่มขั้นก่อนฟ้องและเดินต่อใน Case เดิม ไม่มีคิว lead หรือขั้นแปลงเรื่องเป็นคดี

หน้า Customer 360 เป็นพื้นที่ทำงานของสำนักงาน Customer Portal เห็นเฉพาะรายงานที่อนุมัติและคดีที่ผู้ติดต่อมีสิทธิ์อยู่แล้ว

## เนื้อหาและการกระทำ

| ส่วน | แสดงอะไร | การกระทำหลัก |
|---|---|---|
| หัวลูกค้า | ชื่อ ประเภท ผู้ติดต่อหลัก ช่องทางติดต่อ บทบาทในคดี | โทร/อีเมลจากข้อมูลที่มี, แก้ผู้ติดต่อ |
| ต้องทำต่อ | Task ที่ผูก Case และยังไม่เสร็จ เรียงเลยกำหนด/วันนี้/ถัดไป พร้อมเจ้าของงาน | เปิดงาน, มอบหมายงานไร้เจ้าของ |
| คดี | Case ที่เป็นลูกความหลัก ลูกความเพิ่มเติม หรือผู้ว่าจ้าง; Case เดียวแสดงหนึ่งแถวพร้อมทุกบทบาท | เปิด Case, กรองตามบทบาท/สถานะ |
| ประวัติ | การติดต่อและเหตุการณ์จาก Case ที่มีสิทธิ์ดู ระบุวัน ผู้ติดต่อ ช่องทาง ผลคุย | บันทึกการติดต่อ, เปิดกิจกรรมต้นทาง |
| รายงาน | ฉบับรายปีที่เผยแพร่แล้ว แยกจากฉบับถอน | เปิดฉบับ, ไปหน้าจัดทำรายงานสำหรับ Owner |

หน้าแรกให้ความสำคัญกับงานติดตามและคนที่ต้องติดต่อ ยอดเรียกร้อง ยอดวางบิล และยอดรับชำระอยู่ในส่วนการเงินที่ Owner เปิดดูได้ โดยแยกฐานของยอด

### บันทึกการติดต่อ

เปิดจากหน้า Client แล้วให้เลือก **Case ก่อนบันทึก** เลือกผู้ติดต่อของลูกค้ารายนั้น ช่องทาง และทนายที่ลูกค้าต้องการติดต่อ จากนั้นระบุว่าได้คุยกันหรือไม่ พร้อมบันทึกผลหรือข้อความที่ฝากไว้ ถ้าไม่ได้คุย เช่น ทนายไปศาล ให้สร้าง Task โทรกลับที่ผูก Case เดิมและมอบหมายให้ทนายคนนั้นทันที โดยมีชื่อผู้โทร เบอร์โทร และข้อความที่ฝากไว้ กำหนดเริ่มต้นเป็นวันนี้ ถ้าได้คุยแล้วจึงแสดงตัวเลือกสร้างงานติดตามอื่นตามความจำเป็น บันทึกแล้วกิจกรรมและ Task ปรากฏทั้งหน้า Client และ Case เดิม ไม่เปิด Case ใหม่เอง และไม่ส่งข้อความออกไปอัตโนมัติ

ข้อมูลติดต่อที่ค้นหาไม่พบให้สร้างผู้ติดต่อใหม่ภายใต้ Client ที่ผู้ใช้เลือก โดยไม่รวมลูกค้าอัตโนมัติเพียงเพราะชื่อคล้ายกัน

## สิทธิ์และข้อมูลที่ต้องรองรับ

จาก source ปัจจุบัน ClientsService.findOne เลือก Case ผ่าน Case.clientId และ CaseAccessService จึงยังไม่รวม CaseClient และ CaseCustomer ในหน้า Client เดิม หน้า Customer 360 ควรมี endpoint สำหรับภาพรวมที่รวมสามความสัมพันธ์นี้แล้วกรอง Case ทุกแถวด้วย CaseAccessService.getCaseFilterForUser ก่อนนับจำนวนหรือดึงกิจกรรมและ Task ห้ามให้จำนวนรวมเผยคดีที่ผู้ใช้ไม่มีสิทธิ์

CaseActivity มีวันที่ ชื่อเรื่อง คำอธิบาย และผู้บันทึก แต่ยังไม่มีช่องผู้ติดต่อ/ช่องทาง/ผลการคุยแบบมีโครงสร้าง งานบันทึกการติดต่อควรเพิ่มช่อง optional เหล่านี้ในกิจกรรมของ Case เพื่อให้ Timeline และการค้นหาเชื่อถือได้ ใช้ Task.caseId, assigneeId, dueDate และ status ที่มีอยู่สำหรับการติดตามครั้งถัดไป ไม่สร้างคิวงาน CRM อีกชุด

ผู้ติดต่อใน Customer Portal ยังใช้สิทธิ์รายผู้ติดต่อและรายคดีของเดิม การเห็น Customer 360 ภายในสำนักงานหรือรายงานประจำปีไม่เพิ่มสิทธิ์พอร์ทัลให้ผู้ติดต่อ

## ลำดับส่งมอบ

1. **ภาพรวมอ่านอย่างเดียว:** รวม Case ทุกบทบาทที่ผู้ใช้มีสิทธิ์ พร้อมงานค้างและกิจกรรมล่าสุด เปิดจากหน้า Client ปัจจุบัน
2. **บันทึกการติดต่อ:** ฟอร์มสั้นที่ผูก Case และผู้ติดต่อ พร้อมสร้าง Task ถ้าต้องติดตาม
3. **ใช้งานรายวัน:** กรองคดีและ Timeline, แสดงงานไร้เจ้าของให้ Owner, เชื่อมรายงานประจำปีที่เผยแพร่แล้ว

## เกณฑ์ตรวจรับ

- ลูกค้ารายเดียวเป็นลูกความใน Case หนึ่งและผู้ว่าจ้างอีก Case หนึ่ง หน้าเดียวเห็นทั้งสองพร้อมป้ายบทบาทที่ถูกต้อง; Case ที่มีสองบทบาทไม่ถูกนับซ้ำ
- ผู้ใช้ที่ไม่มีสิทธิ์ใน Case ไม่เห็นชื่อ จำนวน งาน กิจกรรม หรือยอดของ Case นั้น
- บันทึกผลการโทรและงานติดตามจากหน้า Client แล้วเปิด Case เดิมเห็นกิจกรรมและ Task เดียวกัน
- ลูกค้าโทรหาทนายที่ไปศาลและยังไม่ได้คุย เมื่อบันทึกแล้วต้องมีงานโทรกลับมอบหมายให้ทนายคนนั้นโดยอัตโนมัติ พร้อมชื่อ เบอร์ และ Case; ถ้าได้คุยแล้วต้องไม่สร้างงานโทรกลับ
- งานที่เสร็จแล้วไม่อยู่ใน “ต้องทำต่อ”; งานเลยกำหนดและไร้เจ้าของเห็นชัดตามสิทธิ์ของ Owner
- ถ้าไม่มี Case หรืองานติดตาม หน้าบอกการกระทำถัดไปอย่างตรงไปตรงมา
- ไม่มีการรวมลูกค้า สร้าง Case ซ้ำ ส่งอีเมล หรือส่งข้อความพอร์ทัลโดยอัตโนมัติ
