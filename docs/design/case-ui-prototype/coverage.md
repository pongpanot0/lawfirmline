# ขอบเขตข้อมูลของ mockup — เทียบโค้ดปัจจุบันและ Excel

วันที่ตรวจ: 22 กันยายน 2569

## ข้อกำหนดล่าสุด — เปิดคดีให้เร็ว (ใช้แทนตำแหน่งเดิมในตารางด้านล่าง)

- หน้า Create เป็นหน้าเดียว: ประเภท ชื่อคดี เลขอ้างอิงลูกค้า **Policy ref แยกอีกช่อง** ผู้มอบหมาย/ผู้ติดต่อ ลูกความ และทนายหลัก; ทีม/Playbook เป็นส่วนพับ
- เอาสัดส่วนจ่ายออกตามคำขอ ไม่แสดงในฟอร์มหรือสรุป; ยังเพิ่มผู้มอบหมาย/ลูกความหลายรายได้
- เอาตัวสร้างฟิลด์และเลือกชนิดข้อมูลออกจาก flow ของผู้ใช้งาน ฟิลด์เฉพาะต้องมาจากประเภทคดีที่สำนักงานตั้งไว้
- ย้ายศาล รายละเอียด การเงิน การคำนวณค่าใช้จ่าย นัดหมาย เอกสาร และข้อเสนอ AI ไปทำต่อใน Detail; ไม่มีแนบไฟล์ระหว่างสร้างคดี
- Cargo แสดงใน Detail เฉพาะเมื่อเลือก “ขนส่ง / Cargo claim”; ประเภทคดีอื่นไม่มีแท็บหรือปุ่มเช็กลิสต์ Cargo
- Policy ref เป็นเลขอ้างอิงกรมธรรม์ที่ผู้ใช้ระบุ แยกจาก customerRef และ policyNumber/claimNumber ของรายละเอียดเคลม ไม่คัดลอกหรือถือว่าเป็นค่าเดียวกันอัตโนมัติ
- คำนวณค่าใช้จ่ายต่อแถว = จำนวน × อัตรา พร้อมยอดรวม; ยังไม่กรอกแสดงยังไม่ครบ ไม่เปลี่ยนเป็น 0
- ตรวจจริง: เปิดคดีทั่วไปแล้วไม่มี Cargo และ Policy ref คงอยู่; เลือกขนส่งแล้วมี Cargo; หน้า Create ไม่มี upload/สัดส่วนจ่าย; 2 × 1,500 = 3,000.00 บาท; มือถือ 390px ไม่ล้นแนวนอน

ตารางด้านล่างเป็นรายการฐานสำหรับติดตามข้อมูลจากรุ่นก่อน ตำแหน่งที่ขัดกับรายการล่าสุดนี้ให้ยึดรายการล่าสุด เช่น สัดส่วนจ่ายถูกยกเลิกตามคำสั่งผู้ใช้ มิใช่ฟิลด์ที่ต้องเติมกลับ

## หลักการ

ปรับการจัดวางได้ แต่ไม่ตัดกลุ่มข้อมูลออกเพื่อให้หน้าสั้นลง ข้อมูลที่ใช้เป็นครั้งคราวอยู่ในส่วนพับหรือเมนูส่วนงานอื่น การพับไม่ล้างค่าที่กรอก ค่าใน mockup อยู่ในหน่วยความจำและหายเมื่อรีโหลด ไม่มีการแก้ API ฐานข้อมูล หรือ Excel ต้นฉบับ

นี่เป็น **ตัวอย่างการวางข้อมูลและฟอร์ม** ไม่ใช่ implementation ที่ทำงานเทียบเท่า production ทุกอย่าง ตัวกรองงาน การค้นทะเบียน การสร้างรายงาน AI การส่งเบิก ใบแจ้งหนี้ และการส่งข้อความไม่ได้เชื่อมระบบจริง สถานะตัวอย่างที่กดได้ไม่ใช่สิทธิ์หรือ validation ของระบบจริง

## ข้อมูลใหม่กับสถานะการพัฒนา

จาก CaseItem/CaseDetail/InsuranceClaimItem และหน้า Create ที่ตรวจ ยังไม่พบฟิลด์ Cargo แบบเฉพาะครบทั้งชุด ตัวอย่างนี้จึง **เสนอพื้นที่รองรับ** พร้อมเก็บ labels และที่มาครบ ไม่ได้หมายความว่าข้อมูลเหล่านี้บันทึกผ่าน API ปัจจุบันได้แล้ว `customFields` ที่มีอยู่เป็นช่องทางทั่วไป ยังไม่ใช่หลักฐานว่ามี domain model / validation / schema สำหรับ Cargo พร้อมใช้งาน

ข้อมูลส่วนงานเดิมยังต้องตรวจเทียบทุกฟิลด์ของ nested dialogs, locale, validation และสิทธิ์อีกครั้งในขั้นลง production รายการนี้เป็นฐานตรวจไม่ให้ลดข้อมูลและฟังก์ชัน ไม่ใช่การรับรองว่า mockup มีพฤติกรรมครบเท่าระบบจริง
