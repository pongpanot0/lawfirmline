ปรับพื้นหลักเป็นสีขาว แบ่งหน้าสร้างคดีเป็น 3 ส่วน: ข้อมูลคดี, ผู้มอบหมายและลูกความ, ผู้รับผิดชอบและทีม โดยคงฟิลด์และการเปิดคดีหน้าเดียวไว้ หน้ารายละเอียดใช้พื้นขาวและเส้นคั่น เน้นสีน้ำเงินเฉพาะจุดสำคัญ

# Samnuan — Case UI prototype

**รุ่นล่าสุด:** สร้างคดีหน้าเดียว เพิ่ม Policy ref แยกจากเลขอ้างอิงลูกค้า เอาสัดส่วนจ่าย/ตัวสร้างฟิลด์ออก ย้ายเอกสารและข้อมูลเสริมไป Detail และเปิด Cargo เฉพาะคดีขนส่ง ค่าใช้จ่ายคำนวณจำนวน × อัตราและยอดรวมได้ใน Detail ดูเงื่อนไขล่าสุดที่ต้น [coverage.md](coverage.md) ซึ่งใช้แทนตำแหน่งข้อมูลของรุ่นก่อน

ตัวอย่างแยกสำหรับเปรียบเทียบหน้าสร้างคดีกับรายละเอียดคดี ใช้ข้อมูลสมมติ ไม่เชื่อมต่อ API และไม่บันทึกข้อมูลถาวร

เปิดจากราก repository:

```sh
python3 -m http.server 3017 --bind 127.0.0.1 --directory docs/design/case-ui-prototype
```

เปิด http://127.0.0.1:3017/?variant=A&page=detail

- **A — โต๊ะทำงาน:** ฟอร์มต่อเนื่องกับสรุปด้านข้าง / งานหลักอยู่ซ้ายและข้อมูลแฟ้มอยู่ขวา
- **B — โฟกัส:** ฟอร์มทีละขั้น / เมนูงานแนวตั้งและนัดถัดไปเด่นขึ้น
- **C — แฟ้มคดี:** ฟอร์มมีดัชนีหัวข้อ / ข้อมูลแฟ้มอยู่ซ้ายและงานอยู่ขวา

สลับแบบด้วยลูกศรบนแถบล่างหรือปุ่มลูกศรคีย์บอร์ด สลับหน้าด้วย “สร้างคดี” และ “รายละเอียด” พารามิเตอร์ `variant=A|B|C` และ `page=create|detail` ใช้เปิดแบบที่ต้องการได้โดยตรง

ลองกรอกข้อมูล ตรวจสอบก่อนสร้าง เปิดคดีตัวอย่าง เพิ่มงาน ติ๊กงาน เปิดเอกสารจำลอง และเช็กลิสต์เตรียมขึ้นศาลได้ การรีโหลดล้างข้อมูลที่เปลี่ยนในตัวอย่าง ฟอนต์โหลดจาก Google Fonts และมีฟอนต์สำรอง

ตรวจผ่านเบราว์เซอร์: desktop แบบ A/C, ฟอร์มแบบ B ทีละขั้น, dialog ตรวจสอบ และขนาดมือถือ 390px สำหรับรายละเอียด A และฟอร์ม B/C ไม่พบหน้าล้นแนวนอน ไม่ใช่การทดสอบ production หรือการสร้างคดีจริง

## Revision: ข้อมูลต้องไม่น้อยกว่าเดิม

เพิ่ม `complete-data.js` เพื่อวางกลุ่มฟิลด์จากหน้า Create/Detail และ `source-data.js` สำหรับข้อความและตำแหน่งเซลล์จาก Excel ทั้งสามไฟล์ของผู้ใช้ อ่านรายละเอียดและขอบเขตที่ยังเป็นเพียง UI ได้ที่ [รายการเทียบข้อมูล](coverage.md)

Cargo claim มีข้อมูลจากตาราง 17 หัวข้อ (แยกกรมธรรม์/เคลมเป็น 18 ช่อง), ข้อพิจารณา 12 แถว และเอกสาร 16 รายการ ทุกแถวคงหมายเหตุเดิมและเปิดดูต้นฉบับได้ กฎหมาย อายุความ ผลพิจารณา และสถานะเอกสารที่ว่างไม่ได้ถูกเติมอัตโนมัติ

ตรวจผ่านเบราว์เซอร์เพิ่มเติม: เพิ่มผู้จ่าย/ลูกความรายที่สองและพบในสรุปก่อนสร้าง; ค่า Shipper และ Remark คงอยู่หลังสลับหน้า/แบบ; เช็กลิสต์มี Status 16 ช่อง; ข้อพิจารณามีข้อ 6 สองแถวตามต้นฉบับ; เปิดต้นฉบับและ dialog นัดหมายได้; มือถือ 390px ในหน้า Cargo แบบ B/C และ Create แบบ A/C ไม่ล้นแนวนอน ไม่พบ console error ในจังหวะที่ตรวจ

ตัวกรอง การเชื่อมทะเบียน ไฟล์จริง AI workflow อนุมัติ และ validation ยังไม่เทียบเท่า production จึงยังไม่ควรนำ prototype ไปแทนหน้าจริงโดยตรง

ยังไม่มีแบบที่ได้รับเลือก เก็บไว้เป็นต้นแบบสำหรับวิจารณ์หน้าตา ก่อนนำแนวที่เลือกไปพัฒนาในระบบจริง
