# Mobile: ฟีเจอร์สำนักงาน 5 งาน

ตรวจวันที่ 3 ตุลาคม 2026 ใน worktree `11b5/lawfirm` ด้วยแอป native debug และ API/ฐานข้อมูล local จริง

## สิ่งที่เพิ่มจากหน้าปัจจุบัน

| ฟีเจอร์ | ทางเข้า | ผู้ใช้และพฤติกรรม |
| --- | --- | --- |
| ภาระงานทีมล่วงหน้า 7 วัน | หน้าแรก Owner, แท็บทีม และหน้ามอบหมายงาน | Owner เลือกวันเริ่ม ดูงาน นัดหมาย และวันลารายคน กดขยายรายละเอียด/เปิดงาน/เริ่มมอบหมายได้ เลื่อนแถววันที่เพื่อดูครบ 7 วัน |
| สร้างเอกสารจากแบบสำเร็จ | คดี → เอกสาร → สร้างจากแบบ | เลือกแบบตามประเภทคดี เติมข้อมูลคดี/ลูกความ แก้ข้อความ ตรวจร่าง และยืนยันก่อนสร้าง DOCX; สร้างเป็น DRAFT ไม่ส่งให้ลูกความอัตโนมัติ |
| ตั้งงานทำซ้ำ | สร้าง/แก้ไขงาน → รายละเอียดเพิ่มเติม | Owner หรือผู้รับงานตั้งทุก 1–365 วัน รวมตัวเลือก 1/7/30 วันและกำหนดเอง หรือยกเลิกได้ เมื่องานปิดจึงสร้างรอบถัดไป |
| รอเอกสารจากภายนอก | คดี → เอกสาร และเมนูเพิ่มเติม | ระบุเอกสาร ผู้ที่รอ วันติดตาม และหมายเหตุ แก้ไข/ได้รับแล้ว/กลับไปรอได้ แสดงรายการจาก intake ที่แปลงเป็นคดีด้วย |
| ส่งจุดติดขัดให้คนแก้ | หน้างาน → จุดติดขัดที่บันทึกแล้ว | ผู้รับงานทุก role ส่งให้ Owner หรือผู้รับตามลำดับสิทธิ์เดิมได้ Owner ส่งต่อจากงานที่เข้าถึงได้ มีผู้รับแก้และสถานะ เปิดงานแก้ไขได้ และผู้ทำงานยืนยันเองหลังแก้เสร็จ |

ยังใช้ห้าแท็บ สี และองค์ประกอบเดิม เพิ่มทางเข้าที่สัมพันธ์กับงาน ร่างข้อความของฟอร์มใหม่กู้คืนผ่านระบบร่างเดิมและแยกตามผู้ใช้/สำนักงาน

## กติกาที่ตรวจแล้ว

- ภาระงานใช้จำนวนงาน/คะแนนร่วมกับนัดหมายและลา ไม่คำนวณเป็นชั่วโมงว่างจริง และยังไม่จองกำลังคนสำหรับงานหลายวัน
- เอกสารที่มีช่อง `{{...}}` ยังไม่ครบสร้างไม่ได้ รวมชื่อช่องภาษาไทย การแก้เนื้อหาหลังยืนยันจะต้องตรวจร่างใหม่ ใช้ข้อความที่ตรวจแก้จริงใน DOCX
- งานซ้ำที่ผ่านการส่งตรวจกลับไปยังผู้ทำงานเดิม ไม่ส่งรอบใหม่ให้ผู้ตรวจ การยอมรับพร้อมกันสร้างรอบถัดไปเพียงหนึ่งงานด้วยคีย์เฉพาะของรอบต้นทาง
- รายการรอเอกสารและไฟล์ที่เชื่อมต้องอยู่ในคดีที่ผู้ใช้เข้าถึงได้ การกด “ได้รับแล้ว” เป็นการรับรองโดยผู้ใช้; แนบไฟล์ผ่านหน้าเอกสารคดีได้
- จุดติดขัดต้องตรงกับรายงานล่าสุดที่บันทึกจริง มีการตรวจข้อมูลเปลี่ยนระหว่างเปิดฟอร์ม ไม่ทับ dependency ที่ยังค้าง และกดซ้ำไม่สร้างงานแก้ไขซ้ำ
- งานต้นทางปิด/ส่งตรวจไม่ได้ขณะงานแก้ไขที่เชื่อมยังไม่เสร็จ เมื่อแก้เสร็จไม่ปิดงานต้นทางและไม่ลบข้อความติดขัดอัตโนมัติ ผู้ทำงานตรวจแล้วจึงยืนยันว่าปลดจุดติดขัดได้
- การเข้าถึงข้ามสำนักงานและคดีที่ไม่มีสิทธิ์ถูกปฏิเสธที่ API

## หลักฐานจาก native UI

- iPhone SE 3, 375 × 667, iOS Simulator 26.5: เปิดภาระงาน/รายละเอียดรายคน ส่งจุดติดขัดไป Owner และเห็นงานแก้ไขที่เชื่อม รับเอกสารแล้วเปิดดูสถานะ และเลือกแบบ/แก้ข้อความ/ยืนยัน/สร้างเอกสารสำเร็จ
- ตรวจไฟล์ DOCX ที่สร้างผ่าน native UI โดยเปิด ZIP XML: มีข้อความคดีและลูกความตามฉบับที่ตรวจแก้จริง ไม่มีช่องที่ยังไม่กรอก
- iPad Pro 11 นิ้ว M5, iOS Simulator 26.5: ตรวจภาระงานและรายการรอเอกสารทั้งแนวตั้งและแนวนอน รวมหน้ารายละเอียดงาน/เอกสารคดี
- ตั้งงานซ้ำ 7 วันบน iPad แล้วปิด process แอปก่อนบันทึก เปิดใหม่และยืนยัน biometric ตาม flow เดิม พบรายการร่างบนหน้าแรกและกู้ค่า 7 วันได้ หลังบันทึกตรวจฐานข้อมูลพบค่า 7; ก่อนบันทึกฐานข้อมูลยังเป็น null

## ขอบเขตการส่งมอบ

Migration `20261003080000_case_document_requests` รองรับรายการเอกสารทั้ง intake และ case และใช้เฉพาะฐานข้อมูล local แล้ว ต้องใช้ migration นี้เมื่อปล่อย API จริง ข้อมูล/ไฟล์จำลอง native ถูกล้างหลังเก็บหลักฐาน

ยังไม่ได้ deploy, commit หรือ push หลักฐานนี้เป็น local API และ iOS Simulator; Android ผ่านการ export แต่ยังไม่ได้กด native UI บน Android ไม่มีหลักฐานจากอุปกรณ์จริง กล้อง/เน็ตหลุด/แจ้งเตือน push และการให้พนักงานใหม่ทำ SOP โดยไม่ช่วยยังต้องทดสอบหน้างาน
