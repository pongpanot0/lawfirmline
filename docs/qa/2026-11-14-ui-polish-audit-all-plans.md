## สถานะการแก้ไข (อัปเดต 2026-11-14)

P1 ทั้ง 3 ข้อแก้แล้วใน branch นี้ (ยังไม่ commit) และตรวจด้วย Playwright บนหน้าจริง 8/8 ผ่าน:

## ข้อค้นพบตามความรุนแรง

### P1 — ควรแก้ก่อนปล่อย (gates เริ่มมีผล 2026-11-15)

1. **บันทึกการใช้งาน (Audit Log) แสดงเป็น error แทนการล็อกแพ็กเกจ**
   - ที่: `apps/web/src/app/(dashboard)/admin/audit-log/page.tsx` — API ตอบ 403 `PLAN_FEATURE_LOCKED` สำหรับ FREE/SOLO/TEAM/FIRM
   - ผู้ใช้เห็น: "โหลดบันทึกไม่สำเร็จ ลองโหลดหน้าใหม่" + ปุ่ม "ลองใหม่" ที่กดเท่าไรก็ไม่สำเร็จ
   - แก้: ใช้การ์ดล็อกแบบเดียวกับ /reports ("เฉพาะ Professional · ดูแพ็กเกจ") หรือซ่อนเมนูนี้สำหรับแพ็กเกจที่ไม่มีสิทธิ์
   - คำสั่ง: `/impeccable harden`

2. **Free ชนเพดาน 15 คดี: รู้ตัวหลังกรอกฟอร์มเสร็จ**
   - ที่: `/cases/new`, `/cases`
   - ผู้ใช้เห็นฟอร์มเปิดคดีเต็มรูป กรอกเสร็จกด "เปิดคดี" แล้วจึงได้ toast + แถบแดง "ถึงจำนวนคดีสูงสุดของแพ็กเกจแล้ว (15 คดี…) ติดต่อเจ้าของสำนักงาน" — ข้อความบอกเจ้าของสำนักงานให้ติดต่อตัวเอง และหน้ารายการคดีไม่มีตัวนับ 15/15
   - แก้: แสดงแถบแจ้งเพดานบน /cases/new และปุ่ม "สร้างคดีใหม่" เมื่อเหลือ 0 (มี `caseRoom()` ฝั่ง API อยู่แล้ว), ข้อความแยกตามบทบาท (เจ้าของ → ดูแพ็กเกจ, สมาชิก → ติดต่อเจ้าของ)
   - คำสั่ง: `/impeccable harden`, `/impeccable clarify`

3. **ปุ่มลอย "ผู้ช่วย AI" บังปุ่มและช่องอื่น** (WCAG 2.4.11 Focus Not Obscured)
   - เจอ: ปุ่ม "ทำเลย →" ในรายการคดี, ปุ่มสลับ "รายการ/บอร์ด" ใน /todos /work, แท็บล่างของ /my-day, ปุ่มตอบแบบสอบถาม "หน้านี้ใช้งานเป็นยังไงบ้าง?", ช่องกรอกล่างสุดของ /admin/reimbursements — ทั้ง desktop และ mobile
   - แก้: เผื่อ padding ล่างให้เนื้อหาเท่าความสูงปุ่มลอย หรือย่อเป็นไอคอนเมื่อเลื่อน
   - คำสั่ง: `/impeccable layout`

### P2 — ควรแก้รอบถัดไป

## ปัญหาเชิงระบบ

- **สถานะตามแพ็กเกจยังไม่มี component กลาง**: แต่ละหน้าจัดการ 403/400 เอง → บางหน้าล็อกสวย บางหน้าเป็น error แนะนำให้มี `PlanLock` เดียว ใช้กับ `PLAN_FEATURE_LOCKED`, `PLAN_LIMIT_CASES`, ที่นั่งเต็ม
- **ข้อจำกัดถูกบังคับฝั่ง API ครบ แต่ UI ไม่บอกล่วงหน้า** (เพดานคดี, ที่นั่ง) — ผู้ใช้รู้หลังกรอกเสร็จ
- **สีฝังในโค้ด** 299 hex + 266 palette class ใน 43+ ไฟล์ (มากสุด: `PreLitigationIntake.tsx` 22, `outlook-addin/page.tsx` 16) — dark mode มี token แต่มี `dark:` เพียง 65 จุด
- **ปุ่มลอยกับแถบ sticky** ไม่มีระบบเผื่อพื้นที่ล่างจอ

## สิ่งที่ทำได้ดี

- Login, สมัคร, สร้างลูกความ, สร้างคดี ผ่านทุกแพ็กเกจ; หน้าคดีทั้ง 10 แท็บโหลดได้ทุกแพ็กเกจ
- **0 หน้าล้นจอบนมือถือ 390px** และ **0 JS error** จากการเปิดหน้า 576 ครั้ง
- API บังคับเพดานคดีและที่นั่งถูกต้อง พร้อมข้อความภาษาไทยชัดเจน
- /reports ล็อกตามแพ็กเกจได้ดี (การ์ด "เฉพาะ Firm และ Professional · ดูแพ็กเกจ")
- หน้าแพ็กเกจแสดงข้อมูลถูกต้องทุกแพ็กเกจ (ราคา, ที่นั่ง, เครดิต AI, พื้นที่) และแบนเนอร์ทดลองใช้ชัดเจน
- ปุ่มและช่องกรอกสูงขั้นต่ำ 44px, focus ring ทุกปุ่ม, `lang="th"`, มี skip link, รองรับ `prefers-reduced-motion`

## ข้อจำกัดของการทดสอบ

- ไม่ได้ทดสอบ: พอร์ทัลลูกความหลัง login, dark mode, Stripe checkout จริง (/account/billing/checkout redirect กลับหน้าแพ็กเกจ), เชื่อม Microsoft/Outlook, แอปมือถือ (Expo), screen reader, gesture touch จริง
- ฮิวริสติก "ป้ายขึ้นสองบรรทัด" และ "ปุ่มไม่มีชื่อ" แบบอัตโนมัติให้ผลบวกลวงมาก — ทุกข้อในรายงานนี้ยืนยันจากภาพหน้าจอแล้ว
- ภาพแบบ full page ได้แค่จอแรก เพราะแอปเลื่อนใน container ด้านใน ไม่ใช่ทั้งหน้า
- ข้อมูลทดสอบ (สำนักงาน "Audit … สำนักงาน" 6 แห่ง) อยู่ใน DB local ที่ใช้ร่วมกัน
- ภาพหน้าจอและผลดิบอยู่ใน scratchpad ของ session (อาจถูกล้าง): `results.json`, `gates.json`, `shots/`, `shots-gates/`
