## สิ่งที่ปรับ

| หน้าจอ | วิธีเริ่มใช้งาน | ข้อมูลเพิ่มเติม |
| --- | --- | --- |
| ลูกค้า → เปิดคดี | เติมลูกค้าเดิม ชื่อคดี และทนายผู้รับผิดชอบให้ เมื่อเปิดจากหน้าลูกค้า | ไม่ต้องเลือกลูกค้าซ้ำ; หากโหลดลูกค้าไม่ได้ จะแจ้งให้แก้ก่อนสร้าง |

| เพิ่มงานในภาระงานทีม | เริ่มจากชื่องาน; ผู้รับผิดชอบและวันที่มีค่าเริ่มต้น | กำหนดส่ง ขนาดงาน คิว และผู้ตรวจอยู่ในส่วนรายละเอียด; การยืนยันความเสี่ยงยังแสดงให้เห็น |
| เพิ่มบริษัท | บันทึกจากชื่อบริษัทอย่างเดียวได้ | เพิ่มผู้ติดต่อภายหลังได้; หากใส่เบอร์ อีเมล หรือตำแหน่ง ต้องมีชื่อผู้ติดต่อที่ไม่ใช่ช่องว่าง |
| คู่มือให้อ่าน | ชื่อคู่มือและขั้นตอนการทำงาน | หมวดคู่มือเป็นข้อมูลเสริม; เพิ่ม แก้ และล้างหมวดได้ |
| SOP อัตโนมัติ | ชื่อ SOP แล้วพิมพ์ชื่องาน กด Enter เพื่อเพิ่มแต่ละขั้นตอน | ประเภทคดี เอกสาร วิธีทำ ผู้รับผิดชอบ และกำหนดส่งค่อยตั้งเพิ่มได้ |
| นำ SOP ไปใช้กับคดี | กด “ใช้กับคดี” ในคลัง เลือกคดี แล้วเปิดรายการงานให้ตรวจทันที | ทุกจุดที่เรียกใช้ SOP ผ่านหน้าตรวจรายการก่อนยืนยัน; เปิดคดีใหม่ไม่สร้างงานจาก SOP โดยอัตโนมัติ |
| เพิ่มงานในคดี | เริ่มจากชื่องานได้; ผู้รับผิดชอบเริ่มที่ตัวเอง และกำหนดส่งเว้นได้ | แสดง 3 ช่องหลัก; การตรวจงาน ความสำคัญ และผู้ติดตามกางเมื่อต้องใช้; หากเลือกให้ตรวจ ต้องเลือกผู้ตรวจ |
| เปิดงานเพื่อทำต่อ | เปิดหน้าทำงาน / ส่งตรวจโดยตรง และเห็นสถานะ ผู้รับผิดชอบ กำหนดส่ง | ผู้เกี่ยวข้อง บันทึกเพิ่มเติม และการทำซ้ำพับไว้; รับงาน วางแผน และตรวจงานยังใช้งานได้ |
| ติดตามงานที่ส่งตรวจ | ผู้ส่งยังเห็นงานในรายการของตัวเอง ระหว่างรอตรวจและหลังตรวจผ่าน | ผู้ตรวจรับงานตามสิทธิ์เดิม; ส่งกลับแก้ไขต้องมีเหตุผล และผู้รับงานส่งตรวจใหม่ได้ |
| ภาระงานทีมสำหรับเจ้าของ | เปิดที่ “ต้องจัดการวันนี้” เป็นค่าเริ่มต้น | ยังสลับไปดูภาพรวมภาระงานได้ |

คลัง SOP มีตัวกรองทั้งหมด / คู่มือให้อ่าน / สร้างงานอัตโนมัติ และค้นหาได้จากคำในขั้นตอนด้วย เมื่อบันทึกคู่มือแล้วเปิดให้อ่านทันที หากบันทึกล้มเหลวจะแสดงข้อผิดพลาดและเก็บข้อความที่พิมพ์ไว้

ตัวเลือก SOP แสดงรุ่นล่าสุดของแต่ละชุด และยังเปิดรุ่นเดิมที่เชื่อมไว้ได้ การเผยแพร่ไม่แก้รุ่นเดิมย้อนหลัง และการนำไปใช้พร้อมกันไม่เพิ่มงานซ้ำ หากโหลดรายการงานล้มเหลวจะให้ลองใหม่ก่อนยืนยัน

ปุ่ม “เพิ่มงาน” ขณะอยู่ในคดีสร้างงานผูกคดีนั้น เมื่อบันทึกสำเร็จจะเปิดงานให้ทำต่อ และจำนวนงานบนหัวคดีเปลี่ยนทันที

คำแนะนำการใช้งานเปิดจากปุ่ม `?` ได้ โดยไม่เด้งขวางการกรอกหรือบันทึกเอง ส่วนคำขอ SOP ใช้ตัวส่งคำขอร่วมของระบบเพื่อให้ต่ออายุ session ได้ และการต่ออายุไม่รีโหลดฉบับที่กำลังเขียน

ฟอร์มบริษัทส่งผู้ติดต่อเริ่มต้นตามสัญญา API เดิมเมื่อยังไม่ระบุบุคคล หากกรอกเบอร์ อีเมล หรือตำแหน่ง จะต้องมีชื่อบุคคลเพื่อเก็บข้อมูลครบ การติดตามผู้ส่งตรวจใช้ประวัติส่งงานเดิม โดยยังจำกัดสำนักงาน สิทธิ์เข้าถึง และสิทธิ์ตรวจงาน

## ผลตรวจ

- E2E รวม **7 ชุดผ่าน (30.6 วินาที)**
- เส้นทางใช้งานจริง 2 ชุด: จอ 375 และ 1440 พิกเซล ตรวจลูกค้า → เปิดคดี → ตรวจ SOP → สร้างงาน → มอบหมาย → รับงาน/วางแผน/บันทึกความคืบหน้า → ส่งตรวจ → ส่งกลับแก้ไข → ส่งตรวจใหม่ → ตรวจผ่าน รวมการติดตามของผู้ส่งและการสร้างงานจากชื่ออย่างเดียว
- E2E ฟอร์ม 2 ชุด: จอ 375 และ 1440 พิกเซล ตรวจกรอกครบ เว้นข้อมูลเสริม และกรอกผิด พร้อมตรวจข้อมูลในฐานข้อมูลหลังบันทึก
- E2E SOP 2 ชุด: จอ 375 และ 1440 พิกเซล ตรวจสร้าง/แก้คู่มือ ค้นเนื้อหา แยกประเภท เผยแพร่รุ่นใหม่ ตรวจรายการก่อนเพิ่มงาน และป้องกันใช้ซ้ำ
- API regression 1 ชุด: ตรวจสิทธิ์เจ้าของสำนักงาน การเข้าถึงข้ามสำนักงาน รุ่น SOP ที่แก้ย้อนหลังไม่ได้ และการเพิ่มงานพร้อมกันโดยไม่ซ้ำ
- API unit tests **62 รายการผ่าน** ใน 3 suites ครอบคลุมรายการงาน รายละเอียดงาน และสิทธิ์เข้าถึง รวมงานที่ Senior ส่งตรวจ
- TypeScript ทั้งเว็บและ API และ `git diff --check` ผ่าน

กรณีที่ตรวจเพิ่มเติม: ค่าทุนทรัพย์เกินขอบเขต ข้อหาบังคับตามประเภทคดี เบอร์/อีเมลผิด ชื่อผู้ติดต่อเป็นช่องว่าง ผู้ตรวจที่ยังไม่ได้เลือก ชื่อ SOP/ชื่องานว่าง และชื่อคู่มือยาวบนจอแคบ ช่องผิดในส่วนพับจะกางให้แก้ และข้อมูลที่กรอกก่อนพับยังบันทึกครบ

การทดสอบความล้มเหลวจำลอง HTTP 503 ตอนบันทึกคู่มือ โหลดรายการ SOP และสร้างงาน รวม HTTP 401 ตอนเผยแพร่ SOP; ตรวจว่าข้อมูลยังอยู่และลองใหม่ได้ การบันทึกสำเร็จ การ refresh session การมอบหมาย และวงจรตรวจงานใช้ API/ฐานข้อมูล local จริง

คำสั่งรันทดสอบซ้ำ:

```sh
pnpm exec playwright test --project=workflow-usability --project=simple-forms --project=sop-ui --project=practice-setup -g 'client → case|short forms|SOP library|immutable playbook versions'
pnpm --filter api exec jest --runInBand --watchman=false src/tasks/tasks.service.spec.ts src/tasks/tasks.service.detail.spec.ts src/common/services/case-access.service.spec.ts
pnpm --filter web exec tsc --noEmit --incremental false
pnpm --filter api exec tsc --project tsconfig.build.json --noEmit
git diff --check
```

ต้องมี API ที่พอร์ต 3001 เว็บที่พอร์ต 3005 และฐานข้อมูล local; fixture จะสร้างสำนักงานทดสอบแล้วลบข้อมูลของสำนักงานนั้นเมื่อจบ ใช้ helper เดิมที่ป้องกันการรันกับฐานข้อมูลนอก local

ผลนี้ยืนยันเส้นทางหลักข้างต้นบนเว็บ local และความกว้างจอมือถือ ยังไม่ได้ deploy หรือทดสอบแอปมือถือจริง และไม่ใช่ผลตรวจครบทุกเมนู เช่น การเงิน การอัปโหลดเอกสาร และบริการภายนอก
