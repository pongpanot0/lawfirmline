# การตรวจต้นแบบ

วันที่ 8 กันยายน 2026 — ตรวจผ่านเบราว์เซอร์จริง ข้อมูลและการเปลี่ยนสถานะจำลองในหน้าเท่านั้น

## ลองครบแล้ว

- เปิดอีเมล → อ่านสรุป → ยืนยันเหตุผล → เตรียมเอกสาร
- ส่งตรวจโดยยังไม่เลือกคน: แสดง validation ให้เลือกผู้ตรวจ ผู้แก้ และกำหนดตรวจ
- เลือก Senior Lawyer และ Lawyer เป็นผู้ตรวจสองคน และ Owner เป็นผู้แก้ร่วมกับ Lawyer ได้
- ส่งตรวจแล้วทั้งสองชื่อปรากฏในหน้ารอบตรวจและคิว
- ผู้ตรวจส่งกลับพร้อมเหตุผล แล้วผู้แก้เห็นข้อแก้ไขในเรื่องเดิม
- บันทึก v2 → ส่งตรวจใหม่ → คนแรกยืนยันแล้วยังคงรออีกหนึ่งคน → คนที่สองยืนยันแล้วผ่านตรวจ
- ยืนยันตรวจผู้รับ/เหตุผล → แสดงผลจำลองเตรียมร่าง Outlook และระบุว่ายังไม่ส่งจริง
- แก้หลังผ่านตรวจเป็น v3 → กลับสถานะร่าง และปุ่มเตรียมร่าง Outlook ถูกปิดจนตรวจใหม่
- ตรวจ JavaScript syntax ผ่าน

## Responsive

- ตรวจภาพหน้าเอกสารที่ desktop และหน้าเรื่องบนมือถือ
- วัด DOM หน้าเรื่อง/flow ที่ความกว้าง 320, 375, 414, 768 และ desktop 1440: ไม่พบ root horizontal overflow ในหน้าที่ตรวจ
- ตรวจคิวผู้ตรวจที่ 414: ไม่พบองค์ประกอบเนื้อหาล้นด้านข้าง
- คืน viewport ปกติและเริ่มข้อมูลตัวอย่างใหม่ก่อนส่งมอบ
- ไม่ได้ตรวจทุกชุดสถานะ × ทุกขนาดหน้าจอ และยังไม่ทดสอบ English

## ปรับหลังตรวจ

- ข้อความผลสรุปด้านข้างเปลี่ยนตามสถานะที่ทนายยืนยันแล้ว
- เปลี่ยนแหล่งต้นแบบแล้วล้างสถานะพร้อมใช้/การอนุมัติเดิม และเพิ่มรุ่นเอกสาร

## ยังไม่ใช่ผลทดสอบ integration

ไม่มีการเชื่อม Outlook, OneDrive, Word, AI, OCR หรือระบบสิทธิ์จริง ไม่สร้างหรือส่งอีเมล ไม่อัปโหลดไฟล์ และไม่แตะข้อมูลแอป production

## ตรวจหลังเพิ่มปุ่มในหน้าเปิดตรวจ

- เลือกผู้ตรวจคนที่สอง (Lawyer) ที่คิว → เปิดตรวจ → ชื่อผู้ตรวจคงเดิม
- กดผ่านการตรวจในหน้าเอกสาร → ขึ้นคุณตรวจผ่านแล้วและยังรอผู้ตรวจอีกคน
- กลับคิว เลือกผู้ตรวจอีกคน → เปิดตรวจและกดผ่าน → ผ่านครบทุกคน
