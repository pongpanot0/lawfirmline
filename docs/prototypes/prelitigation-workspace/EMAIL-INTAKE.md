# UI รับงานจากอีเมลและ Reply

ต้นแบบเพิ่มเติมวันที่ 8 กันยายน 2026 เปิด `intake.html` จากเซิร์ฟเวอร์ต้นแบบเดิม

## หน้ารับงาน

เมลและไฟล์แนบอยู่ซ้าย ข้อมูลที่เสนอกรอกอยู่ขวา แยกเป็น “พบจากต้นทาง / ระบบเสนอ / ต้องยืนยัน” ทุกช่องแก้ได้ ชื่อเรื่อง ลูกค้า ผู้ติดต่อ ยอด วันที่ขอคำตอบ สรุปคำขอ และผู้รับผิดชอบ

ยืนยัน 2 จุดในตัวอย่าง: ยอดที่ลูกค้าแจ้งและวันที่ลูกค้าขอคำตอบ วันที่ขอไม่ใช่กำหนดทางกฎหมายหรือวันตกลงส่งงาน การรับผิดชอบเรื่องไม่ใช่การตกลงรับฟ้อง

## เมื่อรับแล้ว

สรุปข้อมูลที่ใช้และเอกสารในเรื่องเดิม พร้อมเริ่มพิจารณา จุดประสงค์คือไม่คัดลอกข้อมูลและสร้างงานซ้ำ การเลือกผู้ตรวจและผู้แก้เกิดภายหลังตามเอกสาร

## Reply

- แสดงบทสนทนาเดิมและข้อความใหม่
- เทียบค่าเดิมกับข้อเสนอใหม่ก่อนเขียนทับ
- ตัวอย่างยอด 450,000 → 400,000 บาท มีไฟล์ใหม่หนึ่งไฟล์และไฟล์ซ้ำหนึ่งไฟล์
- เลือกใช้ข้อมูลยอดและเพิ่มไฟล์แยกกัน เก็บค่าเดิมในหน้าตรวจ
- ชี้ว่าร่างเก่าอาจต้องทบทวน ไม่แก้ Word เองและไม่ถือว่าผ่านตรวจต่ออัตโนมัติ

## ขอบเขต

ข้อมูลสมมติและสถานะในหน่วยความจำ ไม่มีการเชื่อมเมล สร้างเรื่องหรือไฟล์จริง การเก็บไว้ตรวจภายหลังอยู่ได้เฉพาะรอบตัวอย่างนี้ รีโหลดจะล้าง ลิงก์ไปต้นแบบก่อนหน้าเปิดข้อมูลตัวอย่างอีกชุด ยังไม่เชื่อมสถานะกัน

ระบบจริงต้องเพิ่มการจับคู่ thread ที่กำกวม ข้อมูลที่ขัดแย้งกัน การไม่พบวันที่/ยอด (ไม่บังคับเดาข้อมูล) และหลักฐานการเปลี่ยนแปลงรายช่อง รวมถึงตรวจสิทธิ์ Microsoft 365 ก่อนเลือกวิธีเชื่อม
